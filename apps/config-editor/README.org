#+TITLE: Loki Assistant 配置编辑器

* 作用

配置编辑器是独立的 macOS App。启动后先请求 services 的 ~GET /meta~ 获取配置元数据，再并行读取各可编辑模块的 ~GET /data/{module_id}~ 实例数据；两者全部读取成功后，左侧显示配置模块，右侧按元数据中的名称和类型生成编辑控件，并填入服务器返回的生效值。配置项不在客户端写死。

切换模块和前后导航使用对应模块已加载的实例数据；工具栏“刷新”可重新读取服务器的元数据和实例。读取失败时显示实际原因并提供“重试”，不会把配置接口错误一律显示为服务没有运行。保存时通过 ~PUT /data/{module_id}/{key}~ 提交原始 JSON 值，并使用服务器响应更新该模块的值和来源。

当前支持字符串、文件路径、可执行文件 (~Executable~)、整数、数字、布尔值以及 JSON 字典/列表的通用编辑。每项在同一行显示名称、当前值和选择按钮。默认来源的文本值使用浅色斜体，默认布尔值使用较淡的开关样式；配置项描述、底层字段名和独立默认值文字不显示。配置模型为空时显示明确提示。

~Executable~ 类型提供同行的“选择…”按钮，通过系统文件面板选择程序；可进入 ~.app~ 包内部选择 ~emacsclient~ 。也可在文本框中手动输入路径或程序名，按回车保存。默认程序名和建议搜索目录由 services 元数据声明；文件面板可使用建议目录定位，程序查找与校验由服务器完成。

字段输入后调用 ~POST /config/validate~ 预检，错误值显示红色文字和边框，悬停可查看原因。提交时服务器再次校验；无效值不替换原有配置，界面保留输入并标红错误。预检不会保存配置。

“登录时自动启动”控制托盘的用户级 LaunchAgent。重复开启会启动已注册任务，尚未注册时再加载 plist；重复关闭也可正常完成。托盘日志写入 ~~/Library/Logs/LokiAssistant/center.log~ 和 ~~/Library/Logs/LokiAssistant/center.error.log~。

用户设置保存于 ~~/.assistant/config.yml~，重启 services 后仍然有效。元数据默认值与自动发现的程序路径不写入该文件。配置读取的 ~value~ 和 ~source~ 协议见 [[file:../../docs/control-center-services.org::*配置中心][配置中心协议]]。

* 构建与运行

在仓库根目录执行：

#+begin_src sh
make build-config-editor
make run-config-editor
#+end_src

应用启动后读取 ~~/.assistant/service~ 获取 services 端口，再请求配置接口。需要先启动 services：

#+begin_src sh
make start-service
#+end_src

* 测试

#+begin_src sh
make test-config-editor
#+end_src

测试覆盖元数据与实例解码、启动时完整加载、模块切换、服务端预检、保存错误及重试和自动启动状态处理；网络与 launchctl 测试使用注入替身，不修改用户配置或真实 LaunchAgent。
