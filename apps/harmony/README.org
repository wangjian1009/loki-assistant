#+TITLE: Loki Assistant HarmonyOS 手机应用

* 项目说明

这是 Loki Assistant 的 HarmonyOS 手机执行中心工程，使用 Stage 模式和 ArkTS，Rust/NAPI 提供 iroh 设备通信。首页提供设备管理：没有电脑时提示增加设备，点击后扫描电脑二维码绑定；绑定后展示电脑状态、设备标识、绑定时间与最近检查时间。手机辅助能力、跨设备同步与后台常驻仍在规划中。

应用、Ability 和启动窗口使用项目统一的“对话中的 L”图标，与 macOS 应用共用仓库根目录 ~resources/icons/~ 的 SVG 母版。根目录 ~make export-icons~ 将图标导出为 ~AppScope/resources/base/media/app_icon.png~ 的 1024 × 1024 PNG；构建直接使用仓库中的导出资源。设计与导出说明见 [[file:../../docs/icon-design.org][图标设计]]。

* 设备管理

先在电脑的 Emacs 设备管理界面点击“新增设备”，再在手机首页点击“增加设备 · 扫码绑定”；已有电脑时可用右上角“增加”继续扫码。系统扫码支持相机和相册，取消后返回首页；无效、过期或已取消的邀请会提示重新生成二维码。

手机保存随机身份和绑定记录，重新启动后恢复电脑列表；每次连接一台电脑，其他记录可点击“使用此电脑”切换。切换会停止旧电脑请求，之后的通用请求只发给选中的电脑。电脑状态由实际认证请求确定，显示“在线”“暂时无法连接”“已解除绑定”或“绑定待确认”；应用前台每轮检查结束后间隔 20 秒刷新，也可点击“刷新”。后台停止安排轮询，重新进入页面重新检查，不把历史绑定记录当作当前在线。电脑需要运行支持设备状态协议的 services；中继配置变化后可重新扫码更新手机凭据。

绑定请求发送前先保存待确认记录，避免电脑已绑定但手机丢失响应时丢失关系；刷新会查询电脑并在邀请有效时重试。手机私钥、电脑中继信息与待确认邀请保存在应用私有目录的 ~devices.json~ ，使用 ~0600~ 权限和原子替换，不进入 UI 或日志；成功确认后删除一次性邀请凭据。协议见 [[file:../../docs/control-center-services.org::*扫码绑定][扫码绑定]]。

Rust Workspace 统一构造 Network 与设备模块，手机业务通过注入的 ~network.request()~ 使用 HTTP 方法、路径、query 和 JSON body，不传目标 service。电脑 network 模块将 iroh 请求转到现有 HTTP handler，状态查询已经使用 ~GET /network/session~ 。Network 未设置 service 时返回错误回调；Workspace 提供 stop 优雅停止：主动通知未完成请求取消，等待业务收尾并关闭网络，已保存的绑定不删除。接口、分发和生命周期见 [[file:../../docs/service-client.org][Workspace 与 Network 接口]]。

* 构建与运行

工程依赖 DevEco Studio 提供的 Node.js、OHPM、Hvigor 和 HarmonyOS SDK，以及 Rust 工具链和 ~aarch64-unknown-linux-ohos~ target。原生库当前构建 ARM64 版本。默认工具路径为：

- ~/Applications/DevEco-Studio.app/Contents/tools/hvigor/bin/hvigorw~
- ~/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc~

在本目录执行：

#+begin_src sh
make check-sdk   # 检查 SDK 安装
make deps        # 检查 SDK 并安装工程依赖
make build       # 构建 Debug HAP，使用 OrgTasksDebug 调试签名
make test        # 检查并测试设备管理 Rust 模块
make devices     # 查看 hdc 设备
make install     # 安装到已连接设备
make run         # 启动手机应用
make deploy      # 检查真机，构建、安装并启动
#+end_src

~make build~ 自动检查 SDK 目录及 ~sdk-pkg.json~ ，执行工程和 entry 模块的 OHPM 依赖安装，使用 Rust 和 DevEco NDK 编译设备通信库，再通过 Hvigor 的 ~default@PackingCheck~ 和 ~default@CollectDebugSymbol~ 打包。构建显式指定 ~module=entry@default~ 、 ~product=default~ 、 ~buildMode=debug~ 和 ~debuggable=true~ ，随后由 ~scripts/sign-hap.cjs~ 使用 ~signing/config.json~ 指定的材料独立签名，生成 ~entry/build/default/outputs/default/entry-default-signed.hap~ 。安装入口只使用已签名产物，真机还需已授权的 ~hdc~ 连接。根目录 ~make harmony-test~ 执行手机 Rust 检查；~make services-test~ 同时验证手机入口与 services 的真实 relay 握手。

~make install~ 和 ~make run~ 同样通过设备选择脚本自动选择唯一真机；也可用 ~HDC_TARGET=<设备 ID>~ 显式选择已连接的模拟器。根目录提供 ~make harmony-deps~ 和 ~make harmony-check-sdk~ 对应依赖安装与 SDK 检查。

~make deploy~ 在构建前检查真机，自动选中唯一已连接的真机；多台真机时通过 ~HDC_TARGET=<设备 ID>~ 指定。模拟器、离线或未授权设备不能作为部署目标。确认设备后依次完成构建签名、安装和启动，任一步失败即停止；并行执行 make 时也保持此顺序。根目录的 ~make deploy~ 和 ~make harmony-deploy~ 均调用此入口。

* 调试签名

项目复用 ~OrgTasksDebug~ 调试证书，配套的 ~LokiAssistantDebug~ Profile 绑定包名 ~cc.loki.assistant.mobile~ 和后台登记的手机，有效期至 2027-10-11。此配置用于调试构建。

- ~signing/OrgTasksDebug.cer~ ：公共证书链，纳入版本管理。
- ~signing/LokiAssistantDebug.p7b~ ：Loki 专用调试 Profile，纳入版本管理；增加调试设备时需在华为后台更新并重新下载。
- ~signing/config.json~ ：证书、Profile、私钥路径、keyAlias 和 Keychain 条目名称，纳入版本管理。
- ~.signing/org-tasks.p12~ ：与证书配套的本地私钥库，由 Git 忽略；新开发环境需要恢复此文件。

签名脚本从 macOS Keychain 的 ~org-tasks-signing~ / ~development~ 条目读取密码，通过 stdin 交给 JVM 内的签名工具；密码不写入工程配置或命令行。签名前校验签名材料的有效期、Profile 包名以及证书与私钥是否配套。
