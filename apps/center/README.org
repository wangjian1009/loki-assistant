#+TITLE: Loki Assistant 菜单栏入口

* 当前状态

当前 Mac 应用是最小的菜单栏入口。点击菜单栏图标后，菜单显示控制中心 services 的连接状态、版本和运行时间，并可手动刷新；services 不可达时显示失败原因。

应用通过系统的 ~launchctl~ 查询 LaunchAgent 是否运行；随后读取 ~~/.assistant/service~ 获取服务端口，再通过 loopback HTTP 请求 ~GET /healthz~ 获取版本。应用后台每 5 秒轮询一次，菜单再次打开时立即查询；服务未运行时显示灰色启动按钮。不包含 Emacs 会话、语音输入或其他旧版功能。

在配置编辑器的“控制中心”模块开启“登录时自动启动”后，使用 ~cc.loki-assistant.center~ 用户级 LaunchAgent 在 GUI 登录时启动托盘。重复开启会检查现有注册并启动任务；未注册时重新加载。重启 services 仅重启 Rust 服务，托盘由自己的 LaunchAgent 管理。

应用承接 services 的通用系统通知，通过 ~UNUserNotificationCenter~ 展示 macOS 系统通知。首次接收时会请求通知权限；点击后按通用导航 URL 回调 services，由所属业务模块执行跳转。Emacs 通知未指定 buffer 时显示 Emacs，指定时定位存活 buffer；未指定图标时使用 Emacs 原生图标附件。文本 ~icon~ 放在标题前，本地图片和应用图标作为 PNG 附件展示。完整协议见 [[file:../../docs/control-center-services.org::*系统通知模块][系统通知模块协议]]。

通过 ~loki-assistant~ URL scheme 后台接收通知；运行新版应用后由 LaunchServices 注册该 scheme。macOS 禁止通知或启用勿扰模式时可能不显示横幅，权限与处理错误记录在系统日志中。

收到带 ~notification_id~ 的通知时，应用将提交成功或明确失败的结果回报 services；提交成功不保证系统已经展示横幅。回执通过文件锁、服务发现文件和健康检查获取当前本机 HTTP 地址，网络错误时最多尝试 3 次；只重试回执，不重复发送通知。未知或已过期的通知停止回报。旧版不含 ID 的 URL 仍可展示通知，但没有回执。状态通过 ~/notification/{id}~ 查询，回执发往 ~/notification/{id}/receipt~ ，保留期限见系统通知模块协议。点击跳转每次重新发现服务，调用一次业务回调；成功或失败写入系统日志，不覆盖提交回执。失败时弹窗显示 services 返回的具体原因，例如目标 buffer 已关闭、无法连接目标 Emacs 或调用超时；services 不可用时也会提示。旧通知沿用相同流程，不在 App 中启动 Emacs。

* 构建与运行

在仓库根目录执行：

#+begin_src sh
make build
make run
make restart-center
#+end_src

修改菜单栏 App 后使用 ~make restart-center~ ，确保旧实例退出并加载新的 binary。

需要 macOS、CMake 3.30 及以上和支持 Swift 6 的 Xcode。构建配置及源文件列表以 [[file:mac/CMakeLists.txt][CMakeLists.txt]] 为准。

* 测试

#+begin_src sh
make test-mac
#+end_src

测试覆盖 services 健康响应、状态模型、通知 URL 解码和展示内容、回执分类、服务发现及回执重试，不要求 services 正在运行，也不发送真实系统通知。
