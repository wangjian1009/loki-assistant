#+TITLE: Loki的助理 菜单栏入口

* 当前状态

当前 Mac 应用是最小的菜单栏入口。点击菜单栏图标后，菜单显示控制中心 services 的连接状态、版本、网络连接状态和启动时间；启动时间与网络连接状态来自每次打开菜单时读取的完整 ~GET /status~ 快照，其中启动时间读取 ~service~ 数据中的 ~start_at~ ，不逐秒更新运行时长。services 不可达时显示不可用状态。

每次打开菜单时，应用先检查 ~~/.assistant/service.lock~ 是否由服务持有，再读取 ~~/.assistant/service~ 获取服务端口，只请求一次 ~GET /status~ 。同一快照用于刷新启动时间、网络连接状态和 Slack 新消息会话。顶部图标保持单色，只有菜单第一项圆点着色：服务未运行或不可达为红色，注册失败、断开或连接中为黄色，注册成功和未配置的 ~offline~ 为绿色。services 的启动和停止由 ~brew services~ 或根目录 Makefile 管理。

「Slack 新消息」显示符合通知规则且仍未读的会话，按最新匹配消息从新到旧排列。每行显示会话名和工作区，点击后在 Emacs 定位消息或线程。 [[file:../../docs/slack-services.org::*托盘新消息会话][Slack 状态和跳转协议]]

菜单中的“阻止空闲休眠”开关使用 macOS 的 ~PreventUserIdleSystemSleep~ activity。开启后阻止系统因空闲自动休眠，关闭后立即释放 activity；开关状态保存到用户默认设置并在应用下次启动时恢复。该开关不阻止用户主动睡眠、合盖或锁屏。

在 Emacs 配置界面的“控制中心”模块开启“登录时自动启动”时，由 services 的控制中心模块先同步系统设置，成功后才保存配置；失败会显示具体错误并保留输入。使用 ~cc.loki-assistant.center~ 用户级 LaunchAgent 在 GUI 登录时启动托盘。重复开启会检查现有注册并启动任务；未注册时重新加载。重启 services 仅重启 Rust 服务，托盘由自己的 LaunchAgent 管理。

应用承接 services 的通用系统通知，通过 ~UNUserNotificationCenter~ 展示 macOS 系统通知。首次接收时会请求通知权限；点击后按通用导航 URL 回调 services，由所属业务模块执行跳转。Emacs 通知未指定 buffer 时显示 Emacs，指定时定位存活 buffer；services 的 Emacs 模块在未收到 ~app~ 时补为 ~emacs~ 。center 根据 ~app~ 从内置资源读取 PNG 图标附件，不读取调用方指定的图标、路径或应用 Bundle ID。完整协议见 [[file:../../docs/control-center-services.org::*系统通知模块][系统通知模块协议]]。

通过 ~loki-assistant~ URL scheme 后台接收通知；运行新版应用后由 LaunchServices 注册该 scheme。macOS 禁止通知或启用勿扰模式时可能不显示横幅，权限与处理错误记录在系统日志中。

收到带 ~notification_id~ 的通知时，应用将提交成功或明确失败的结果回报 services；提交成功不保证系统已经展示横幅。回执通过文件锁、服务发现文件和健康检查获取当前本机 HTTP 地址，网络错误时最多尝试 3 次；只重试回执，不重复发送通知。未知或已过期的通知停止回报。旧版不含 ID 的 URL 仍可展示通知，但没有回执。状态通过 ~/notification/{id}~ 查询，回执发往 ~/notification/{id}/receipt~ ，保留期限见系统通知模块协议。点击跳转每次重新发现服务，调用一次业务回调；成功或失败写入系统日志，不覆盖提交回执。失败时弹窗显示 services 返回的具体原因，例如目标 buffer 已关闭、无法连接目标 Emacs 或调用超时；services 不可用时也会提示。旧通知沿用相同流程，不在 App 中启动 Emacs。

“设置”请求 services 的 ~POST /emacs/apps/open?app=config~ ；“日志”请求 ~POST /emacs/apps/open?app=logs~ ，打开 ~~/.assistant/loki-assistant.log.org~ 。托盘菜单打开、设置和日志均写入 Org 日志；一级标题是用户操作，二级标题是本次操作的 services 调用，文件最多保留 500 条一级操作。应用不存在、服务不可用或 Emacs 出错时，弹窗显示服务返回的具体原因。界面用法见 [[file:../../docs/emacs.org::*服务配置管理][服务配置管理]]。

* 应用图标

应用显示名称为“Loki的助理”，采用已确认的“对话中的 L”图标：深绿底板、薄荷色字母 L 与回应气泡。SVG 母版与设计预览统一放在仓库根目录 ~resources/icons/~ ，由根目录 ~scripts/export-icons.py~ 同时生成 macOS 与 HarmonyOS 图标。Mac 应用的完整 PNG iconset、ICNS、1024 像素 PNG 及菜单栏 20/40 像素透明图标位于 ~mac/Resources/AppIcon/~ 。顶部菜单栏保持单色 template 渲染并保留休眠月牙标记；红、黄、绿仅用于展开菜单后的第一项状态圆点；设计说明与导出文件见 [[file:../../docs/icon-design.org][图标设计]]。

修改 SVG 母版后，在仓库根目录执行：

#+begin_src sh
make export-icons
make restart-center
#+end_src

导出需要 Python 3、~rsvg-convert~ 和 macOS 自带的 ~iconutil~ 。构建使用已导出的资源；标准 ~AppIcon.appiconset~ 由 Xcode 编译成 ~Assets.car~ 和 ~AppIcon.icns~ 随应用打包，菜单栏图标也由 CMake 打包。单独导出的 ICNS 保留为交付资产。

** 通知中的应用标识图标

通知图标按 ~mac/Resources/NotificationAppIcons/<app>.png~ 命名并由 CMake 打包到应用内的 ~Contents/Resources/NotificationAppIcons/~ 。~app~ 是仅含小写字母、数字、~-~ 或 ~_~ 的非空标识；已内置 ~emacs.png~ ，对应 ~app: "emacs"~ 。该资源取自 GNU Emacs 随附的 ~share/icons/hicolor/128x128/apps/emacs.png~ 。新增应用时按同一规则加入 PNG 资源并重新构建，无需维护代码映射表。

Slack 通知使用 ~app: "slack"~ 和内置的 ~slack.png~ 。使用 ~make export-icons~ 从公共 SVG 母版生成 Slack 通知图标。 [[https://commons.wikimedia.org/wiki/File:Slack_icon_2019.svg][Slack 图标来源]]

未提供 ~app~ 或找不到对应资源时继续展示文字通知；图标附件不改变系统通知来源名称及来源应用图标。

* 构建与运行

在仓库根目录执行：

#+begin_src sh
make build
make run
make restart-center
#+end_src

修改菜单栏 App 后使用 ~make restart-center~ ，确保旧实例退出并加载新的 binary。

~make test-mac~ 使用独立构建目录、测试宿主 Bundle ID 和 URL scheme，避免与正在使用的托盘实例争用 LaunchServices 注册；测试只验证协议与状态逻辑，不操作真实服务。

需要 macOS、CMake 3.30 及以上和支持 Swift 6 的 Xcode。构建配置及源文件列表以 [[file:mac/CMakeLists.txt][CMakeLists.txt]] 为准。

#+begin_src sh
