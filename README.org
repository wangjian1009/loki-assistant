#+TITLE: Loki Assistant

* 项目简介

Loki Assistant 是个人使用的助理程序，应用中文名称为“Loki的助理”。当前重新设计由 Rust services、macOS 菜单栏入口、Chrome 全文捕获插件和 HarmonyOS 手机执行中心初始化工程组成。

* 当前阶段

services 提供本机 loopback HTTP 服务、服务发现、配置数据、系统通知、Emacs gateway 和 macOS LaunchAgent 管理。Mac 菜单栏应用展示 services 状态并承接系统通知，点击后回调 services 执行对应业务跳转。

services 的网络模块自动生成并保存本地身份，按 ~network.relay_url~ 和 ~network.relay_token~ 注册中转，并通过通知模块报告结果。Emacs 提供设备管理和新增绑定入口，services 已实现二维码 PNG 生成、单次邀请、iroh 绑定握手和设备关系持久化，协议见 [[file:docs/control-center-services.org::*扫码绑定][扫码绑定]]。状态中心统一提供各模块的 Rust 发布接口与 HTTP 只读查询。~apps/harmony/~ 使用 HarmonyOS Stage 模式与 ArkTS，目前提供执行中心入口；手机扫码客户端、辅助能力与后台常驻尚未实现。

~emacs/~ 中的 ~loki-assistant~ Emacs Lisp 包提供服务配置管理、异步 services HTTP 请求、通知发送和浏览器全文捕获，支持目标 buffer、标题、正文、应用标识和处理器选择；失败时返回明确错误。Chrome 插件通过 services 的固定 loopback 接口提交页面内容，Emacs 不启动独立 HTTP 服务。

* 快速开始

构建并运行 services：

#+begin_src sh
make services-test
make services-run
#+end_src

构建并运行 Mac 菜单栏入口：

#+begin_src sh
make build
make run
make restart-center
#+end_src

构建并运行 HarmonyOS 手机应用（需要 DevEco Studio 的 SDK，以及已授权的 ~hdc~ 设备）：

#+begin_src sh
make harmony-build
make deploy
#+end_src

~make deploy~ 先检查真机，再构建、签名、安装并启动应用；多台真机时使用 ~HDC_TARGET=<设备 ID>~ 指定目标。模拟器、离线或未授权设备会被排除。

HarmonyOS 构建会自动检查 SDK 并安装 OHPM 依赖，显式使用可调试的 Debug 模式打包后独立签名。~make harmony-install~ 和 ~make harmony-run~ 默认选择唯一真机，也可通过 ~HDC_TARGET=<设备 ID>~ 显式选择模拟器。

构建 Chrome 插件：

#+begin_src sh
make chrome-build
#+end_src

然后在 =chrome://extensions/= 开启开发者模式，加载
=dist/chrome-plugin= 。插件使用固定的
=http://127.0.0.1:47321/emacs/capture/full=，需要先启动 services。

修改菜单栏 App 代码后使用 ~make restart-center~，该命令会退出旧进程并强制启动新构建的 App；只执行 ~make run~ 可能会复用旧实例。

在已启动 server 的 Emacs 中打开服务配置或设备管理界面：

#+begin_src sh
make emacs-config
make emacs-devices
#+end_src

也可在加载包后执行 ~M-x loki-assistant-config~ ，或通过菜单栏“设置”打开。界面按模块显示配置，提供校验、保存、撤销编辑和文件选择；详见 [[file:docs/emacs.org::*服务配置管理][服务配置管理]]。

通过 Homebrew 注册、启动和停止 services（安装后立即启动）：

#+begin_src sh
make install-service
make start-service
make service-status
make stop-service
#+end_src

安装后可直接用 ~brew services list~ 或 ~brew services info loki-assistant-services~ 查看状态。services 自身由 Homebrew 管理，托盘只显示状态；托盘的登录启动继续在 services 的“控制中心”配置中管理。具体安装和环境配置见 [[file:services/README.org::*macOS 服务管理][macOS 服务管理]]。

* 开发操作

跨应用图标的 SVG 母版与设计预览集中在 ~resources/icons/~ ，通过根目录 ~make export-icons~ 同步生成 macOS 的 iconset、ICNS、asset catalog、菜单栏图标、Chrome 插件图标，以及 HarmonyOS 的应用 PNG。各应用构建直接使用已导出的资源，详见 [[file:docs/icon-design.org][图标设计]]。

加载 Emacs 包前，需有正在运行且已启动 ~server-start~ 的 Emacs。从仓库根目录执行：

#+begin_src sh
make emacs-load
make emacs-test
#+end_src

该命令通过 ~emacsclient --eval~ 将 ~emacs/~ 加入 ~load-path~，卸载已加载的包后执行 ~(require 'loki-assistant)~ 和 ~(require 'loki-assistant-config)~ ，用于首次加载和修改后的重新加载。

~make emacs-test~ 重新加载包并运行 ERT，使用临时 HTTP listener 验证请求、通知与配置界面，不改动用户配置或发送系统通知。测试失败时命令返回非零退出码；不会退出 Emacs。~make test~ 执行 Mac、services 和 Chrome 插件检查，Emacs 测试通过独立入口运行。
