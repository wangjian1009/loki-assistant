#+TITLE: Chrome 插件、密码查询与全文捕获设计
#+LANGUAGE: zh-CN

本文记录 Chrome 插件、services 和 Emacs capture 模块的已确认设计与实现边界。
第一版实现已落在对应目录；本文仍作为跨模块协议和行为基准。

* 目标与范围

Chrome Manifest V3 插件的功能菜单包含全文保存和只读密码查询：

| 显示名称 | 功能标识 | 行为 |
|----------+----------+------|
| 全文保存 | =org-capture= | 读取当前完整网页，转换为 Org 文本并提交到 Loki Assistant |
| 密码 | =password-query= | 查询 pass 条目，复制字段并填充当前网页 |

功能菜单保留按功能扩展的边界，每个能力使用独立功能目录；后续能力不得把协议和实现堆回
=popup=，也不改变已有的 =org-capture= 请求协议。

本次功能明确分为三层：

- 浏览器解释当前页面并转换为 Org 文档。
- services 提供唯一的对外 HTTP 接入点，并通过现有 Emacs gateway 调用 Emacs。
- =loki-assistant-capture-full= 实现 Org 捕获、去重、窗口激活和保存后的索引处理。

Emacs 不启动或依赖独立 HTTP 服务；插件不连接 Emacs 的 HTTP server、simple-httpd、
=org-protocol= 或剪贴板。

* 数据流程

#+begin_example
Chrome 当前标签页
  -> activeTab + scripting 读取 DOM
  -> 浏览器内 HTML 转 Org
  -> POST /emacs/capture/full 到本机 services
  -> services 校验请求并调用 emacsclient gateway
  -> loki-assistant-capture-full 使用 org-roam capture API 建立捕获缓冲区
  -> 用户在 Emacs 中 C-c C-c 保存或 C-c C-k 取消
#+end_example

浏览器只提交页面已经加载的内容，不在 services 或 Emacs 中重新下载网页，也不下载图片。
请求超时后插件提示请求结果未知，不能自动重复提交；服务端仍按来源 URL 去重。

* 插件结构

插件放在 =chrome-plugin/= ，目录按通用界面、共享客户端和功能划分：

构建产物统一输出到仓库根目录的 =dist/chrome-plugin/= ，Chrome 加载该目录。

│   ├── manifest.json                 Manifest V3 和权限

│   │   ├── popup.html

│   │   └── popup.js

│   ├── features/

│   │   │   └── html2org/              转换器及其许可证
│   │   ├── password-query/           services 查询和 pass 原文解析

popup 只负责显示功能菜单、启动功能和显示结果。密码列表及详情请求在 popup 中按需发起，
密码填充和全文保存通过 service worker 调度。每个功能由自己的目录导出入口，目录之间不共享
隐式全局状态。

插件使用 =activeTab=、=scripting= 权限，以及访问
=http://127.0.0.1/*= 的 =host_permissions= 。不申请 cookies、下载、剪贴板或全部网页
访问权限；复制使用扩展页面的 Clipboard API，不声明 =clipboardRead= 或 =clipboardWrite= 。
Chrome 内部页面、Web Store、PDF 查看器和没有 HTML body 的页面直接显示不支持提示。

页面转换沿用参考项目的边界：复制可见的主文档 body，忽略脚本、样式、iframe、隐藏元素、
Shadow DOM 和 canvas；链接转为绝对 HTTP(S) 地址；图片只保留远程地址，不转 Base64；
正文为空时拒绝提交。转换器的第三方代码、许可证和修改记录随插件维护。

* services 地址

Chrome 扩展不读取 =~~/.assistant/service= pfile，直接在代码中固定 services 地址：

#+begin_example
http://127.0.0.1:47321/emacs/capture/full
#+end_example

这是本功能的本机约定，不增加设置页、端口配置或 token。若 services 使用
=LOKI_ASSISTANT_HTTP_ADDR= 改到其他端口，需要同步修改插件源码并重新加载扩展；本版不
自动发现或读取 pfile。

* services HTTP 接口

在现有 =modules/emacs= 中增加业务接口，不新建独立的 HTTP 服务：

#+begin_example
POST /emacs/capture/full
Content-Type: application/json
#+end_example

协议版本沿用 Emacs 模块的 =api_version: "1"= ，字段使用本项目已有的 snake_case 命名。

** 请求

#+begin_src json
{
  "title": "网页标题",
  "url": "https://example.com/article/123",
  "captured_at": "2026-11-18T12:30:00.000Z",
  "body": "* 页面正文\n\n浏览器转换后的 Org 内容。\n"
}
#+end_src

| 字段 | 类型 | 约束 |
|------+------+------|
| =title= | string | 必填、非空、不得含换行；由页面标题清理得到 |
| =url= | string | 必填；绝对 HTTP 或 HTTPS URL，不含空白 |
| =captured_at= | string | 必填；UTC RFC 3339，使用 =Z= 后缀 |
| =body= | string | 必填、非空；浏览器生成的 Org 文本，保留换行 |

未知字段、非法 JSON、字段类型错误和不符合格式的值返回 =400 invalid-request= ，服务不
调用 Emacs。单次请求体上限建议为 16 MiB，按 UTF-8 字节计算；正文不进入 services
日志。服务只负责校验和转发，不解释 Org 语法。

** 成功响应

新来源创建捕获缓冲区后返回 HTTP 202：

#+begin_src json
{
  "api_version": "1",
  "status": "pending",
  "url": "https://example.com/article/123"
}
#+end_src

202 只表示 Emacs 已建立捕获缓冲区，不表示文件已经保存。用户仍需在 Emacs 中确认或
取消。

已保存的来源 URL 返回 HTTP 200，并激活原文档：

#+begin_src json
{
  "api_version": "1",
  "status": "existing",
  "url": "https://example.com/article/123",
  "document": {
    "id": "bf25ec0b-e09a-4994-8059-fefb78d18fa2",
    "title": "已保存的网页标题",
    "relative_path": "article/2026/20261118123000-网页标题.org"
  }
}
#+end_src

=relative_path= 只用于提示和日志，不作为浏览器后续查询地址；本版不增加捕获状态查询
接口。

** 错误

错误响应沿用现有 Emacs 模块的 JSON 错误包装：

#+begin_src json
{
  "api_version": "1",
  "code": "capture-busy",
  "message": "Emacs 中已有其他来源的未完成捕获，请先保存或取消。"
}
#+end_src

| HTTP | code | 含义 |
|------+------+------|
| 400 | =invalid-request= | 请求 JSON、字段类型或字段值无效 |
| 404 | =capture-not-installed= | Emacs 未加载 capture 模块或依赖不可用 |
| 409 | =capture-busy= | 存在其他来源的未完成捕获 |
| 422 | =capture-invalid= | capture 模块配置或模板无法使用 |
| 502 | =emacsclient-failed= | emacsclient 调用失败 |
| 503 | =emacs-unavailable= | 目标 Emacs server 不可连接 |
| 503 | =emacs-ui-unavailable= | 没有可用图形 frame |
| 504 | =emacs-timeout= | gateway 超时，结果可能已在 Emacs 中产生 |

同一来源的重复请求应返回同一个 pending 结果，不创建第二个缓冲区；不同来源在存在
未完成捕获时返回 =capture-busy= ，第一版不排队。

接口用 =#[loki_api]= 注册到服务发现，使用现有的 =EmacsService= 、配置的
=emacsclient_path=、=socket_name= 和串行 gateway。services 不把请求内容拼接进 shell，
而是用 JSON 字符串参数传给固定的 Emacs Lisp 入口。

* browserpass 查询行为兼容

本插件参考 browserpass-extension 3.13.0 和 browserpass-native 3.x 的查询行为。原版
native host 的 =configure=、=list=、=fetch= 分别对应本插件的配置中心、
=GET /password/entries= 和 =GET /password/entries/{*file}= ；原版 =tree= 、=save=、
=delete= 不对应当前 services 的只读接口，因此界面不提供新增、编辑、删除或生成密码。
原版的四字节 Native Messaging framing、=status/version/data= 响应和多 password store
设置由项目现有的 loopback HTTP、=api_version/status/error= 错误模型和单一配置目录替代。
源码入口包括 [[https://github.com/browserpass/browserpass-extension/blob/dcdd297b4bd4a2df53c59185d8a7888e2332113b/src/background.js][extension/src/background.js]] 的 =hostAction= 、=parseFields=、填充和复制分发，
以及 [[https://github.com/browserpass/browserpass-native/blob/7c62896ca318cf44fcab5d041a93525119e69a5d/request/process.go][native/request/process.go]]、
[[https://github.com/browserpass/browserpass-native/blob/7c62896ca318cf44fcab5d041a93525119e69a5d/request/list.go][request/list.go]] 和
[[https://github.com/browserpass/browserpass-native/blob/7c62896ca318cf44fcab5d041a93525119e69a5d/request/fetch.go][request/fetch.go]]；字段和 OTP 规则来自
[[https://github.com/browserpass/browserpass-extension/blob/dcdd297b4bd4a2df53c59185d8a7888e2332113b/src/helpers/base.js][extension/src/helpers/base.js]] 与 =background.js= 。

插件保留以下可见行为：

- 条目列表默认按当前标签页 hostname 过滤，输入搜索词时按第一词模糊匹配、其余词做字面子串过滤；“全部条目”按钮取消域名过滤，Backspace 在搜索框为空时也会取消过滤。
- 条目卡片支持填充用户名/密码、复制用户名、复制密码和打开详情；详情按需读取完整原文，显示标准字段和额外的 key/value 字段，并支持复制、填充及打开 URL。
- 字段别名沿用 browserpass：=secret/password/pass=、=login/username/user=、=url/uri/website/site/link/launch=、=otp/totp= 和 =openid= 。没有显式密码时使用第一行，没有用户名时使用条目文件名。
- OTP 支持 =otpauth://= URI 的 type、secret、algorithm、digits、period 和 Base32 secret-only 形式；使用 Web Crypto HMAC 计算当前 token。填充带 OTP 的条目后复制 token，和 browserpass 的自动复制行为一致。
- =Enter= 填充第一项，=Ctrl+C= 复制密码，=Ctrl+Shift+C= 复制用户名，=Ctrl+O= 打开详情；扩展命令 =Ctrl+Shift+F= 填充当前网站最匹配的条目。
- 表单填充在当前标签页的可访问 frame 中查找可见用户名和 password input，派发 =input/change= 事件；条目中设置 =autosubmit: true= 时提交所在 form。跨域受限 frame 或浏览器内部页面失败时显示明确说明。

原版 browserpass 的最近使用统计、浏览器历史日志、Basic Auth 监听、跨 store 颜色设置、
Native Messaging options 页和写入操作不在当前版本，因为当前扩展未申请相应权限且 services
只提供查询。它们不能由前端假装实现；未来后端增加写入和配置协议后再逐项开放。

密码原文只在详情、复制或填充操作时读取，不写入 Chrome storage、页面属性或 services
日志。查询响应不缓存；services 的密码接口统一返回 =Cache-Control: no-store= 。

Chrome 扩展请求需要本机 loopback host permission。若 Chrome 对 JSON POST 触发预检，
services 只对 =chrome-extension://= Origin 提供必要的 =OPTIONS= 和 CORS 响应，不向普通
网页开放跨域写入；其他本机 API 的行为保持不变。

* Emacs capture 模块

新增 =emacs/loki-assistant-capture.el= ，feature 名为
=loki-assistant-capture=，由 =loki-assistant.el= 提供加载入口。它不启动 HTTP listener，
不注册 simple-httpd 路由，也不修改用户的 =org-roam-capture-templates= 。

对 services 暴露一个固定入口：

#+begin_src emacs-lisp
(loki-assistant-capture-full REQUEST-JSON)
#+end_src

入口解析并再次校验服务传入的字段，将结果编码成 services 可解析的 JSON。页面正文按
字面插入捕获缓冲区，不执行其中的 =%=、=${}= 或 Lisp 表达式；标题也通过安全的模板
占位替换传入，避免标题被当作模板代码求值。

** 内置模板

捕获模块调用 =org-roam-capture= 的参数 =:templates= 传入
=loki-assistant-capture-templates= ，不要求用户预先配置
=org-roam-capture-templates= 中的键，也不把该模板加入全局变量。这样手动执行
=org-roam-capture= 时仍只看到用户自己的配置。

=loki-assistant-capture-templates= 使用与 =org-roam-capture-templates= 相同的模板结构，
由 Emacs 配置文件提供 key 为 =f= 的模板。=loki-assistant-capture-full= 固定选择 =f= ，
不需要额外配置 =full= 或选择 key；模板的目录、文件名、头部和正文位置都可以在该变量中
调整。浏览器请求协议不携带模板、路径或 Lisp 表达式。

第一版内置模板的语义为：

- 以 =org-roam-directory= 为根目录；目录不存在或不可写时返回配置错误。
- 配置模板默认使用时间戳和安全 slug 生成新文件名；具体文件头和文件名格式集中在
  =loki-assistant-capture-templates= 的 =f= 项，不由浏览器提交。
- 文件标题来自请求的 =title= ，正文只插入浏览器转换后的 =body= 。
- 将来源 =url= 写入 =ROAM_REFS=，将 =captured_at= 作为捕获元数据保留在请求状态，
  不强制写进正文。
- 保存完成后显式更新该文件的 org-roam 索引；取消只释放处理中来源，不创建第二份文档。

模板变量只影响 Loki Assistant 发起的全文捕获，不改变服务请求协议，也不污染 org-roam
的全局模板。

** 去重和生命周期

来源 URL 是唯一去重依据。模块在调用 capture 前：

1. 规范化 URL 的 Unicode 和百分号编码，用 org-roam refs 查询已保存文档。
2. 若找到文档，激活 Emacs 并打开原节点，不覆盖或追加正文，返回 =existing= 。
3. 若同一 URL 正在捕获，激活已有捕获缓冲区，返回 =pending= 。
4. 若其他 URL 正在捕获，返回 =capture-busy= ，不排队。
5. 新来源占用 URL 后激活 Emacs 图形 frame，建立捕获缓冲区并返回 =pending= 。

保存或取消由 =org-capture-after-finalize-hook= 清理处理中状态。保存成功后更新索引；
索引失败时保留错误状态并在 Emacs 中提示，后续请求不能静默创建第二份文档。

窗口激活沿用 services 现有 gateway 约定：优先选择显示目标的图形 frame，没有可用图形
frame 时返回 =emacs-ui-unavailable= ；不因为捕获请求自动创建第二个 Emacs daemon。

* 已确认的决定

当前已确认的实现决定如下：

1. Chrome 使用代码中固定的 =http://127.0.0.1:47321= services 地址，不读取 pfile，不提供
   设置页。
2. services 通过 gateway 调用 =loki-assistant-capture-full= ；Emacs 不启动独立 HTTP 服务。
3. =loki-assistant-capture-templates= 使用兼容 =org-roam-capture-templates= 的结构，由
   Emacs 配置文件提供 key 为 =f= 的模板；Loki Assistant 固定使用 =f= ，不写入 org-roam
   全局模板。
4. 第一版继续使用 org-roam 的索引和文档模型，202 仅表示捕获缓冲区已经打开，最终保存
   结果只在 Emacs 内反馈；本版不增加浏览器查询保存状态的接口。

实施时同步修改 services API 文档、实现代码、测试、插件 README 和根目录 Makefile 入口。
