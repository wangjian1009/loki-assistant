#+TITLE: 控制中心 services 模块规划

* 范围

本文规划电脑端控制中心服务层及其最小 macOS 菜单栏入口。当前交付由 Rust services、macOS LaunchAgent 管理和只读状态菜单组成。

旧版 Mac 会话界面、Emacs 插件和 agent-shell 控制协议已经清理。后续重新设计相关能力时，再建立新的模块和协议。

* 当前模块

| 模块 | 职责 | 状态 |
|------+------|------|
| ~runtime~ | 服务进程启动配置、运行状态和 Services 持有 | 已实现 |
| ~services~ | 业务模块组合和路由组合 | 已实现 |
| ~http~ | loopback HTTP server | 已实现 |
| ~modules/discover~ | 编译期模块/API 描述和发现接口 | 已实现 |
| ~modules/config~ | 配置模型、数据读写和变化订阅 | 已实现基础能力 |
| ~modules/health~ | 服务健康检查 | 已实现 |
| ~platform/macos~ | LaunchAgent plist 和 launchctl 服务管理 | 已实现基础能力 |
| ~apps/center~ | 菜单栏显示 services 状态 | 已实现最小入口 |
| ~apps/config-editor~ | 通用配置模型和数据编辑 | 已实现基础能力 |

services 启动后写入 ~~/.assistant/service~ JSON pfile，客户端通过该文件获取服务地址和端口，再请求 HTTP 接口；不应在客户端写死服务端口。

业务模块在自己的目录中维护 ~model.rs~、~protocol.rs~、~routes.rs~ 和业务逻辑。HTTP API 使用 ~#[loki_api]~ 声明，模块描述通过 ~linkme~ 在编译/链接阶段收集；~Services::build~ 只负责路由组合。

* HTTP 接口

| 方法 | 路径 | 返回内容 |
|------+------|----------|
| GET | ~/healthz~ | services 健康状态 |
| GET | ~/discover~ | 全部模块和 API 描述 |
| GET | ~/discover/modules~ | 模块摘要列表 |
| GET | ~/discover/modules/{module_id}~ | 单个模块描述 |
| GET | ~/meta~ | 配置模型 |
| GET | ~/meta/{module_id}~ | 单个配置模块模型 |
| GET | ~/data/{module_id}~ | 已设置配置数据 |
| GET | ~/data/{module_id}/{key}~ | 单个配置值 |
| PUT | ~/data/{module_id}/{key}~ | 替换完整配置值 |
| POST | ~/data/{module_id}/{key}~ | 合并字典或追加列表 |

未设置的配置不会自动返回默认值，调用方从配置模型获取默认值。

* macOS 服务管理

#+begin_src sh
make install-service
make start-service
make service-status
make restart-service
make stop-service
make uninstall-service
#+end_src

~make restart-service~ 会重新编译 services 并重启同一路径的 Debug binary。LaunchAgent 管理器使用用户级 domain，不在服务启动时自动修改用户配置。
