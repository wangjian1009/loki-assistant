#+TITLE: 控制中心 services 模块规划

* 范围

本文规划电脑端控制中心服务层及其最小 macOS 菜单栏入口。当前交付由 Rust services、macOS LaunchAgent 管理和只读状态菜单组成。

旧版 Mac 会话界面、Emacs 插件和 agent-shell 控制协议已经清理。后续重新设计相关能力时，再建立新的模块和协议。

* 当前模块

| 模块 | 职责 | 状态 |
|------+------|------|
| ~runtime~ | 服务进程启动配置、运行状态和 Services 持有 | 已实现 |
| ~services~ | 业务模块组合和路由组合 | 已实现 |
| ~http~ | loopback HTTP server | 已实现 |
| ~modules/discover~ | 编译期模块/API 描述和发现接口 | 已实现 |
| ~modules/config~ | 配置模型、数据读写和变化订阅 | 已实现基础能力 |
| ~modules/emacs~ | emacsclient gateway、buffer 列表和通知分发 | 已实现 |
| ~modules/health~ | 服务健康检查 | 已实现 |
| ~platform/macos~ | LaunchAgent plist 和 launchctl 服务管理 | 已实现基础能力 |
| ~apps/center~ | 菜单栏显示 services 状态 | 已实现最小入口 |
| ~apps/config-editor~ | 通用配置模型和数据编辑 | 已实现基础能力 |

services 启动后写入 ~~/.assistant/service~ JSON pfile，客户端通过该文件获取服务地址和端口，再请求 HTTP 接口；不应在客户端写死服务端口。

业务模块在自己的目录中维护 ~model.rs~、~protocol.rs~、~routes.rs~ 和业务逻辑。HTTP API 使用 ~#[loki_api]~ 声明，模块描述通过 ~linkme~ 在编译/链接阶段收集；~Services::build~ 只负责路由组合。

* HTTP 接口

| 方法 | 路径 | 返回内容 |
|------+------|----------|
| GET | ~/healthz~ | services 健康状态 |
| GET | ~/discover~ | 全部模块和 API 描述 |
| GET | ~/discover/modules~ | 模块摘要列表 |
| GET | ~/discover/modules/{module_id}~ | 单个模块描述 |
| GET | ~/meta~ | 配置模型 |
| GET | ~/meta/{module_id}~ | 单个配置模块模型 |
| GET | ~/data/{module_id}~ | 已设置配置数据 |
| GET | ~/data/{module_id}/{key}~ | 单个配置值 |
| PUT | ~/data/{module_id}/{key}~ | 替换完整配置值 |
| POST | ~/data/{module_id}/{key}~ | 合并字典或追加列表 |
| POST | ~/emacs/eval~ | 执行 Lisp 并返回打印表示 |
| POST | ~/emacs/receiver/notification~ | 接收 Emacs 通知上报，默认展示 macOS 系统通知 |
| GET | ~/emacs/buffers~ | 查询当前 Emacs buffer 列表 |

未设置的配置不会自动返回默认值，调用方从配置模型获取默认值。

* Emacs 模块

Emacs 模块的协议版本为 ~1~，成功和错误响应均包含 ~api_version: "1"~。HTTP handler 只依赖 ~EmacsService~；外部进程通过可注入的 ~CommandRunner~ 调用，不经过 shell。只连接默认 Emacs server，不为每个请求另建会话。

** 配置和连接

配置元数据通过 ~GET /meta/emacs~ 获取，~emacsclient_path~ 使用配置中心的通用读写接口。默认值为 ~emacsclient~，按服务进程的 ~PATH~ 查找；也可指定包含空格的完整可执行文件路径。不展开 ~ 和环境变量，也不接受附加命令行参数。

每次求值读取最新配置，不需要重启服务或启动配置订阅任务。配置中心当前只有内存存储，重启后回到默认值。

调用固定传入 ~--alternate-editor=~ 和 ~--eval~ 。server 不可用时，由 emacsclient 启动 Emacs daemon 并连接；不会因为普通 Lisp 错误重复求值。已打开但未运行 server 的 Emacs 与新 daemon 可能是两个进程。Emacs daemon 的启动依赖服务运行环境中的 Emacs 可执行程序和用户配置。

同一 gateway 内的求值串行执行。每次外部进程调用和自定义通知处理器执行最多等待 30 秒，排队时间不计入此限制。超时或请求取消会终止 emacsclient 子进程，但不会保证中止已经在 Emacs 中开始的 Lisp，也不会终止自动启动的 daemon。

** Lisp 求值

~POST /emacs/eval~ 接受非空 ~script~，可以包含多条 Lisp 表达式；返回最后一条的 Lisp 打印表示，不将符号、列表或 ~nil~ 强制转换成 JSON 类型。所有表达式在执行前一起读取，语法错误不会导致只执行前面一部分；运行期间的错误不会回滚先前副作用。

#+begin_src json
{"script":"(+ 1 2)\n(list :done t)"}
#+end_src

#+begin_src json
{"api_version":"1","result":"(:done t)"}
#+end_src

脚本在 lexical binding 下求值；Lisp 错误和 ~quit~ 转为 ~lisp-error~ ，错误说明保留 Emacs 返回内容。

** Buffer 查询

~GET /emacs/buffers~ 返回所有存活 buffer，包括内部 buffer。~file~ 在非文件 buffer 上为 ~null~，~modified~ 是 JSON boolean。

#+begin_src json
{"api_version":"1","buffers":[{"name":"*scratch*","file":null,"modified":false,"major_mode":"lisp-interaction-mode"}]}
#+end_src

该接口复用求值连接，因此 server 不可用时也会尝试自动启动。

** 通知和处理器

~POST /emacs/receiver/notification~ 是 Emacs 向 services 上报通知的入口。~title~ 和 ~buffer~ 为必填非空字符串；~icon~ 为可选字符串，~module_id~ 默认为 ~emacs~，~payload~ 为可选的任意 JSON 值，默认为 ~null~ 。

#+begin_src json
{"module_id":"emacs","title":"任务完成","icon":"✓","buffer":"*scratch*","payload":{"task_id":"task-1"}}
#+end_src

默认处理器通过 ~NotificationLauncher~ 将上报转交给 Loki Assistant 菜单栏应用，由 ~UNUserNotificationCenter~ 展示 macOS 系统通知。点击通知只激活 Emacs 应用；如果 Emacs 没有运行，尝试通过其 Bundle ID ~org.gnu.Emacs~ 打开。~buffer~ 当前仅保留为通知元数据，不检查是否存在，也不执行 buffer 切换或 Lisp 求值。

~icon~ 支持文本或本地图片的绝对路径 / ~file:~ URL：文本置于标题前，图片作为通知附件展示，系统应用图标仍由 macOS 决定。图片读取失败时省略附件并记录日志。图片先复制到临时目录，避免系统附件处理影响原文件。

#+begin_src json
{"api_version":"1","module_id":"emacs","result":{"display":"macos","status":"forwarded","activation":"emacs"}}
#+end_src

使用前需启动新版菜单栏应用以注册 ~loki-assistant~ URL scheme；可执行 ~make restart-center~ 加载当前构建。首次上报由菜单栏应用请求系统通知权限，拒绝后需要在系统设置中开启。~forwarded~ 仅表示 LaunchServices 已接受转交，不保证系统已展示；通知权限、勿扰模式或客户端处理失败可能影响展示，客户端错误写入系统日志。

services 使用独立参数调用 ~/usr/bin/open -g~ ，将百分号编码的 JSON 放入 ~loki-assistant://emacs/notification?payload=...~ URL，后台唤起菜单栏应用。菜单栏应用通过 AppKit delegate 接收 URL，并持有系统通知 delegate 处理点击；不直接调用 emacsclient。找不到菜单栏应用或转交进程失败返回 ~notification-failed~ 。指定 Emacs buffer 的定位留待后续实现。

其他业务模块通过 ~EmacsService::register_notification_handler~ 注册异步处理器，按 ~module_id~ 精确分发，返回值作为响应的 ~result~。注册表不会在处理器执行期间持锁。重复注册返回错误，可先使用 ~unregister_notification_handler~ 取消；注册 ~emacs~ 可覆盖默认处理器，取消后恢复默认行为。未知模块返回 404，不静默丢弃通知。处理器须使用异步操作，避免阻塞运行时。

以下为在组合根中接入处理器的示意；~tasks~ 处理器不是内置模块：

#+begin_src rust
use std::sync::Arc;
use loki_services::modules::emacs::protocol::Notification;
use serde_json::json;

services.emacs.service().register_notification_handler(
    "tasks",
    Arc::new(|notification: Notification| async move {
        // 此处接入所属模块的业务逻辑。
        Ok(json!({"accepted": true, "title": notification.title}))
    }),
).await?;
#+end_src

Emacs 代码可读取 services pfile，再异步发送通知；将 ~module_id~ 改为已注册模块即可定向投递：

#+begin_src emacs-lisp
(require 'json)
(require 'url)
(let* ((target (buffer-name))
       (service (with-temp-buffer
                  (insert-file-contents (expand-file-name "~/.assistant/service"))
                  (json-parse-buffer :object-type 'alist)))
       (host (alist-get 'host service))
       (url-request-method "POST")
       (url-request-extra-headers '(("Content-Type" . "application/json")))
       (url-request-data
        (encode-coding-string
         (json-encode `((module_id . "emacs")
                        (title . "任务完成")
                        (icon . "✓")
                        (buffer . ,target)))
         'utf-8)))
  (url-retrieve
   (format "http://%s:%s/emacs/receiver/notification"
           (if (string-match-p ":" host) (concat "[" host "]") host)
           (alist-get 'port service))
   (lambda (_status)
     (unwind-protect
         (message "通知 HTTP 状态：%s" url-http-response-status)
       (kill-buffer (current-buffer))))))
#+end_src

** 错误

#+begin_src json
{"api_version":"1","code":"lisp-error","message":"Emacs Lisp 执行失败：示例错误"}
#+end_src

| HTTP 状态 | code | 含义 |
|-----------+------+------|
| 400 | ~invalid-request~ | JSON 结构、字段类型或必填内容无效 |
| 404 | ~notification-handler-not-found~ | 目标模块没有处理器 |
| 409 | ~notification-handler-exists~ | Rust 接口重复注册处理器 |
| 422 | ~lisp-error~ | Lisp 读取或求值失败 |
| 500 | ~invalid-config~ | 无法读取有效的 Emacs 配置 |
| 502 | ~emacsclient-failed~ | 子进程失败，说明包含退出码与 stderr 或 stdout |
| 502 | ~invalid-emacs-response~ | 子进程成功退出但响应无法解析 |
| 502 | ~notification-failed~ | 自定义处理器报告通知失败 |
| 503 | ~emacs-unavailable~ | 无法执行 emacsclient |
| 504 | ~emacs-timeout~ | 外部进程或通知处理器等待超时 |

* macOS 服务管理

#+begin_src sh
make install-service
make start-service
make service-status
make restart-service
make stop-service
make uninstall-service
#+end_src

~make restart-service~ 会重新编译 services 并重启同一路径的 Debug binary。LaunchAgent 管理器使用用户级 domain，不在服务启动时自动修改用户配置。
