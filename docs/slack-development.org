** 接入步骤

1. 登录 Slack 网页，从目标工作区取得 Team ID。
2. 通过配置模块仅提交 Team ID。配置模块保存待确认记录，以 ~team_id~ 为 ~Key~ ，向 ~POST /slack/config/teams/{key}~ 发送创建通知。Slack 返回 ~202~ 。
3. Slack 模块发现凭据不全时会打开本机工作区配置页。也可在配置界面点击「重试」再次打开该页面。
4. 在提示页或配置界面填写同一网页会话的 ~xoxc-~ 令牌和 ~d~ Cookie，点击保存。两项齐全后，Slack 核对用户和 Team ID。配置确认后，services 管理 WebSocket 连接。校验失败后，配置模块清除本次填写的两项凭据并保留错误提示，用户可重新填写。
5. 会话失效时，重新登录 Slack 网页，通过配置模块更新凭据。

配置模块向同一接入点发送 ~DELETE~ 并等待结果，确认后移除记录。Slack 随后停止该 Team 的后台任务并清理连接状态。 [[file:config-module.org::*配置项通知接入点][通知与确认协议]]

* 验证与实现进度

- 目标流程完成保存后，通过 ~GET /status/slack/connections~ 核对 ~authorization_state~ 为 ~authorized~ ，再用 ~GET /slack/conversations?team_id={team_id}~ 验证会话读取。
- 已用 Emacs ~slack.el~ 配置的 X-Tech 网页会话凭据调用 Slack ~auth.test~ ，确认身份有效且 Team ID 匹配。
- 新增 Team 由配置模块的通知接入点处理，真实 Team 由用户在配置界面手动添加。

* 当前工作区配置

配置界面按 ~SlackTeam~ 元数据生成表单，新增时只显示 Team ID。待确认记录可继续编辑凭据。 [[file:slack-services.org::*Team 配置][SlackTeam 字段与配置接口]]

后台通过 Slack RTM WebSocket 接收实时消息，按「提及和私信」规则提交桌面通知。连接使用与 HTTP API 相同的工作区凭据，状态通过 ~socket_state~ 查询。模拟集成测试覆盖 WebSocket 握手、重复消息去重、提及和私信通知及网页会话发送。

现有 API 契约见 [[file:slack-services.org][Slack services 接口]]。
