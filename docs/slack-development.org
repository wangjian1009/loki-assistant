** 接入步骤

1. 登录 Slack 网页，从目标工作区取得 Team ID。
2. 通过配置模块仅提交 Team ID。配置模块保存待确认记录，以 ~team_id~ 为 ~Key~ ，向 ~POST /slack/config/teams/{key}~ 发送创建通知。Slack 返回 ~202~ 。
3. 编辑待确认记录，补充同一网页会话的 ~xoxc-~ 令牌和 ~d~ Cookie，配置值为包含 ~token~ 和 ~d_cookie~ 的 JSON 对象。保存使用 ~PATCH~ 。Slack 通过 ~auth.test~ 校验凭据和 Team ID，配置模块根据结果确认或回退。仍待确认时，可在配置界面手动「重试」。
4. 会话失效时，重新登录 Slack 网页，通过配置模块更新凭据。

配置模块向同一接入点发送 ~DELETE~ 并等待结果，确认后移除记录。Slack 随后停止该 Team 的后台任务并清理连接状态。 [[file:config-module.org::*配置项通知接入点][通知与确认协议]]

* 验证与实现进度

- 目标流程完成保存后，通过 ~GET /status/slack/connections~ 核对 ~authorization_state~ 为 ~authorized~ ，再用 ~GET /slack/conversations?team_id={team_id}~ 验证会话读取。
- 已用 Emacs ~slack.el~ 配置的 X-Tech 网页会话凭据调用 Slack ~auth.test~ ，确认身份有效且 Team ID 匹配。
- 已通过 services 设置 API 发起 X-Tech 工作区新增，确认本机导入页可访问，且请求等待导入结果。
- 新增 Team 由配置模块的通知接入点处理，真实 Team 由用户在配置界面手动添加。

* 当前工作区配置

配置界面按 ~SlackTeam~ 元数据生成表单，新增时只显示 Team ID。待确认记录可继续编辑凭据。 [[file:slack.org::*Team 配置][SlackTeam 字段与配置接口]]

后台 Socket Mode 通知使用独立的应用令牌和事件订阅配置。需要启用时，可在工作区记录中选择已存入 pass 的应用令牌条目。

现有 API 契约见 [[file:slack.org::*services RESTful 接口][services RESTful 接口]]。
