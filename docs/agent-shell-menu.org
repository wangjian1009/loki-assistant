#+TITLE: 托盘 agent-shell 会话菜单方案

* 状态与目标

本文为会话菜单的后续方案。Emacs 主动状态上报、`emacs/buffer` 关注数据和 services 状态缓存已经实现；现有托盘已提供 services 状态、“设置”和“退出”。以下 agent-shell 会话菜单本身尚未实现。

目标是在托盘中列出当前 Emacs 实例中仍连接的 agent-shell 会话，点击后显示对应会话并聚焦 Emacs。控制中心只访问 services HTTP API，Emacs 操作与 agent-shell 适配由服务和 Emacs 包完成。

第一期沿用配置中的单个 ~emacs.socket_name~ ，列表和点击均连接这个实例。查询、点击都不得启动新的 Emacs daemon、Agent 进程或会话；已有 Emacs 没有图形 frame 时，点击可以创建图形 frame。

* 会话范围与菜单

“运行中”按会话连接仍存活定义，包含正在处理、等待用户回应及空闲状态。仅保留 buffer 但 ACP 进程已退出的历史会话不展示；初始化中的存活进程展示为“连接中”。

#+begin_example
0.1.0 · 已运行 02:13:08
─────────────────────────────
agent-shell 会话（3）
  ◉ Codex · loki-assistant · 正在处理
  ◇ Claude · notes · 等待回应
  ○ Codex · demo · 空闲
刷新会话
─────────────────────────────
设置
退出
#+end_example

会话使用单行菜单按钮，显示 Agent 名称、项目或工作目录短名和中文状态。同一 Agent、同一目录存在多个会话时追加会话标题；标题仍相同时追加短 ID 以区分。悬停提示完整标题、工作目录和 buffer 名称，长标签截断后仍能辨认目标。图标形状与状态文字共同表达状态，保留现有 ~.labelStyle(.titleAndIcon)~ 。

正常返回空列表时显示“没有运行中的 agent-shell 会话”。读取失败显示“无法读取会话”和具体原因，不能将错误伪装为空列表。首次加载显示“正在读取会话…”。“设置”和“退出”不受会话读取错误影响。

* 分层与挂接位置

| 层 | 挂接位置 | 职责 |
|----+----------+------|
| 托盘 UI | ~DashboardView~ | 在服务状态与“设置”之间插入会话区块；按钮只携带会话 ID |
| Mac 请求与状态 | 新增 ~AgentShellSessionsClient~ 和 ~AgentShellSessionsModel~ | 服务发现、读取快照、刷新状态与错误反馈，不维护 Lisp 或 Agent 业务规则 |
| HTTP 服务 | 现有 ~services/src/modules/emacs/~ | 声明接口元数据、选择固定应用入口、调用 Emacs gateway、转换错误 |
| Emacs 适配 | ~emacs/loki-assistant-agent-shell.el~ | 枚举、筛选、生成快照和解析会话 ID，处理 viewport 偏好 |
| 图形窗口激活 | 复用现有激活实现的窗口选择与聚焦部分 | 优先复用已有窗口，恢复隐藏或最小化的 frame |

服务只返回当前 Emacs 快照，不新增会话数据库或后台监听服务。状态快照由 Emacs 主动上报到 `/emacs/status`，托盘打开菜单时读取 `/emacs/status/emacs/buffer`；详见 [[file:control-center-services.org::*Emacs 主动状态上报][Emacs 主动状态上报]]。列表不通过 Swift 解析 ~/emacs/buffers~ 的 buffer 名称，也不依赖通知是否开启来决定会话状态。

* HTTP 接口建议

沿用已有 ~/emacs/apps/open~ 的应用入口约定，增加会话列表接口：

| 方法 | 路径与参数 | 行为 |
|------+------------+------|
| GET | ~/emacs/apps/sessions?app=agent-shell~ | 读取 agent-shell 存活会话快照 |
| POST | ~/emacs/apps/open?app=agent-shell&session_id=<id>~ | 激活指定存活会话 |
| POST | ~/emacs/apps/open?app=config~ | 保持现有配置界面入口 |

列表建议响应：

#+begin_src json
{
  "api_version": "1",
  "app": "agent-shell",
  "sessions": [
    {
      "id": "opaque-session-token",
      "agent": "Codex",
      "title": "整理托盘菜单",
      "buffer": "Codex Agent @ loki-assistant",
      "directory": "/Users/example/workspace/loki-assistant/",
      "state": "busy",
      "last_active_at": 1794870000
    }
  ]
}
#+end_src

~id~ 是 Emacs 适配层维护的不可解释标识，绑定真实 buffer 和其当前 ACP 会话。buffer 重命名时保持不变；buffer 被关闭、会话被替换或 Emacs 重启后失效。相同名称的后来 buffer 不能复用旧 ID。~buffer~ 仅用于展示与诊断，客户端不能拿名称作为点击定位依据。~last_active_at~ 使用 Unix 秒，无记录时为 ~null~ ，不根据 buffer 修改时间推断活动。

点击成功沿用已有 ~OpenAppResponse~ ，返回 ~{"api_version":"1","app":"agent-shell","opened":true}~ 。只在窗口显示和聚焦完成后报告成功。

| HTTP | code | 处理 |
|------+------|------|
| 400 | ~invalid-request~ | 缺少或为空的 ~app~ 、 ~session_id~ 等参数 |
| 404 | ~app-not-found~ | 目标 Emacs 未加载 agent-shell，或应用标识不支持 |
| 404 | ~session-not-found~ | ID 失效、目标 buffer 关闭或 ACP 进程已退出；托盘移除失效快照并刷新 |
| 503 | ~emacs-unavailable~ | 配置的 Emacs server 不可连接；明确提示，不自动启动 daemon |
| 503 | ~agent-shell-unavailable~ | agent-shell 关键接口不兼容，提示检查版本 |
| 422 / 502 / 504 | 现有 Emacs 错误码 | 保留 Lisp 执行、响应格式和超时原因 |

“agent-shell 已加载且无存活会话”才返回 HTTP 200 空数组。读取先根据已加载的 agent-shell feature 和函数能力判断可用性，不为探测功能主动加载 agent-shell 或启动会话。确认 agent-shell 已加载后，可以加载 Loki 自己的会话适配函数；这不安装通知 hook，也不修改通知开关。查询与会话激活使用 gateway 的禁止启动策略；既有配置界面入口的启动行为保持原约定。

* Emacs 适配与状态

已核对本机 agent-shell 0.96.1 的源码，具备以下可复用接口：

| 数据 | 来源 | 使用方式 |
|------+------|----------|
| 会话 buffer | ~agent-shell-buffers~ | 已处理 shell 与 viewport 去重 |
| 初始化状态 | ~agent-shell-initialized-p~ | 区分“连接中”和可交互状态 |
| 会话状态 | ~agent-shell-status~ | ~busy~ → 正在处理； ~blocked~ → 等待回应； ~ready~ → 空闲 |
| ACP 会话 ID | ~agent-shell-session-id~ | 作为绑定会话实例的一部分，不直接充当跨 buffer 唯一 ID |
| 活动时间 | ~agent-shell-last-activity-time~ | 转换为 Unix 秒，缺失时返回 ~null~ |
| Agent 名称 | ~agent-shell-get-config~ | 读取配置的可读名称，不解析 buffer 名称 |
| 工作目录 | ~agent-shell-cwd~ | 在目标 shell buffer 上下文中读取 |

~blocked~ 同时覆盖授权请求与其他用户输入请求，因此第一期统一显示“等待回应”，不误标为全部“等待授权”。

进程存活检测需要读取 ACP client 的 process；会话标题和 viewport 查找也可能涉及上游内部字段或函数。将这些访问集中在 Loki 的少量适配函数中，校验类型与函数能力，不散落到 Rust 或 Swift。可选标题缺失时回退到 buffer 名称；关键存活状态无法可靠读取时返回兼容性错误，不把历史 buffer 当作运行会话。

列表基于查询时的真实状态生成，既有会话也可立即发现，不要求在会话创建前先安装新的 hook。暂不建立一套依赖事件推送才能准确工作的状态机，也不修改现有通知开关。

* 刷新与一致性

第一期复用托盘现有约 5 秒一次的状态刷新节奏：services 健康时更新会话快照；首次进入菜单内容及手动“刷新会话”时也可触发刷新。每次重新发现服务地址，复用文件锁检查和 loopback 校验。

同一时刻最多一个列表请求；重复刷新合并，不排队累积。客户端将请求绑定到本次发现的服务地址和本次刷新代号；过期响应不能覆盖更新后的列表。socket 配置始终由服务读取，Swift 不复制 Emacs 连接配置；服务切换到另一实例后，旧 ID 在目标 Emacs 中失效。显示最近一次成功快照时标记更新时间，刷新失败后保留可见信息但停用旧会话按钮，并提供重试。

菜单展开期间保持当前条目的顺序，状态变化不使条目跳到鼠标下；新增、移除与重新排序在下一次展开时统一应用。列表按最近访问顺序建立，点击始终捕获不可解释的会话 ID，不依赖数组下标。实现时需验证 ~MenuBarExtra~ 的原生菜单生命周期；只有不能满足上述行为时，才补最小 AppKit 适配。

列表请求预算建议 2 秒，包含 gateway 排队时间。现有 gateway 的超时不包含等待串行锁的时间，因此需为这些交互新增包含排队的预算，而不是直接复用现有 30 秒等待。客户端对应预算可设为 3 秒。激活建议使用 5 秒服务预算、6 秒客户端预算；不重试点击，以免重复创建窗口或覆盖用户随后切换的焦点。

* 点击激活流程

1. 用户点击条目，托盘提交 ~app=agent-shell~ 与该行 ID，并避免重复提交。
2. services 连接配置的现有 Emacs server；不回退其他 socket，不启动新 daemon。
3. Emacs 在同一次求值内重新解析 ID，确认 buffer 与当前 ACP 会话匹配且进程存活；无效时返回 ~session-not-found~ 。
4. 若用户偏好 viewport 且已有对应 viewport，则选择它；否则显示原 shell buffer。优先复用已经显示目标的图形 window，再选择已有图形 frame，必要时创建图形 frame。
5. 恢复并聚焦 frame 后返回成功；失败时托盘展示服务端中文说明。

激活不发送输入，不恢复已关闭会话，不创建同名 buffer。会话在列表返回后结束、buffer 改名、Emacs 重启等情况由点击时的重新校验处理；可激活目标的校验与窗口操作在一次 Emacs 调用内完成，避免两次 HTTP 请求之间的名称复用问题。

* 实施顺序与验收

1. 增加 Emacs 快照、存活检查和 ID 解析适配，覆盖启动、忙碌、等待回应、空闲及已退出会话。
2. 在现有 Emacs 模块增加列表路由并扩展应用打开入口，声明发现元数据，补齐结构与错误码测试。
3. 提取可复用的图形窗口激活部分，接入会话目标与 viewport 选择；保留原通知跳转行为。
4. 托盘加入客户端、快照模型和菜单区块，验证异步加载、菜单顺序、过期响应、空态、错误与重试。
5. 手工验收多个会话、同项目重名会话、等待授权与其他输入、空闲会话、进程退出但 buffer 保留、菜单打开后会话结束，以及 Emacs 隐藏、最小化或无图形 frame 的情况。

ERT 使用临时 buffer 和进程替身，不启动真实 Agent；Rust 测试注入 gateway runner；Swift 测试注入服务发现和 HTTP transport。跨模块验收须确认查询不会启动 daemon，点击失效 ID 不会激活后来同名的会话。
