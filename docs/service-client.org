#+TITLE: Workspace 与 Network 统一访问接口

* 实现与职责

手机应用通过 ~Workspace~ 持有唯一 ~Network~ 。Rust 不再提供 DeviceManager 或多设备集合；ArkTS ~Application~ 管理电脑列表、手机名称、目标选择和持久化，业务请求始终发给 Network 当前唯一的 Service。

| 对象 | 职责 |
|------+------|
| Rust ~Workspace~ | 创建 Tokio runtime 和一个 Network，持有本机随机身份及通用私有存储适配，不选择电脑 |
| ~Network~ | 设置唯一 Service，查询当前绑定数据和错误，自动绑定、认证请求、连接复用、超时和取消 |
| ~Service~ | 当前电脑 Endpoint ID、中继配置以及携带协议凭据的绑定状态 |
| ArkTS ~Application~ | 管理多台电脑、选择、名称、状态展示与完整配置持久化 |
| ~HttpDispatcher~ | 电脑端将认证后的通用请求转为进程内 HTTP 调用 |
| NAPI | 复用原生 Workspace；异步执行请求，直接转交结果与 ResponsError Union |

手机业务 → Network.request → iroh → 电脑 Network 身份和凭据校验 → 进程内 HTTP request → 现有 Axum handler → 响应回调。

* 创建、绑定与恢复

~Workspace::open~ 只加载本机身份并创建执行环境，不自动从应用数据中恢复目标或建立连接。多次调用 ~workspace.network()~ 得到同一个 ~Arc<Network>~ 。

#+begin_src rust
let workspace = Workspace::open(WorkspaceOptions::new(private_directory))?;
let network = workspace.network();
let service = Service::new(identity, endpoint_id, relay_url, relay_token)?
    .with_auto_binding(AutoBinding { invitation, device_name: "我的手机".into() });
network.set_service(service)?;
// set_service 返回后，自动绑定由 Network 调度；读取 service() 获取状态和错误。
#+end_src

Network 不提供公开的 ~bind~ 或确认接口；应用只添加 Service 配置。未绑定目标设置到 Network 时立即进入 ~binding~ 并异步执行内部握手，校验一次性邀请、当前目标与手机名称，上报固定 ~device_type: mobile~ 。同一目标的相同配置不会重复启动绑定；切换或关闭取消旧任务，旧结果不得覆盖新目标。

电脑生成二维码后将邀请加入有效队列，默认有效期 300 秒。超时主动丢弃队列数据；成功绑定并持久化授权后立即移出队列，队列中不存在的邀请（含已消费、过期和取消）返回 410 ~pairing-expired~ ，不重新发放 token。供本机 Emacs 查询的最近 128 条结果仅保留完成、过期、取消等元数据，不保留邀请摘要或绑定 token。

自动绑定成功后，电脑签发随机 ~binding_token~ ，Network 将 Service 更新为携带 ~credential~ 的 ~bound~ 。失败保存在该 Service 的 ~binding.error~ 中，直接使用 ~ResponsError~ Union，供应用查询、保存和展示。

#+begin_src typescript
interface BindingCredential { token: string; bound_at: number }
interface Unbound { status: 'unbound' }
interface BindingInProgress { status: 'binding' }
interface BindingFailed { status: 'failed'; error: ResponsError }
interface Bound { status: 'bound'; credential: BindingCredential }
type BindingState = Unbound | BindingInProgress | BindingFailed | Bound
interface AutoBinding { invitation: Invitation; device_name: string }
interface Service {
  endpoint_id: string
  relay_url: string
  relay_token: string
  binding: BindingState
  auto_binding?: AutoBinding
}
#+end_src

只有内部绑定握手允许无绑定凭据；QUIC 身份和一次性邀请仍需验证。没有 token 时，所有业务请求都在本机拒绝，返回 ~not_bound/binding_required~ ；电脑对所有非绑定远程请求同时校验 Endpoint ID、当前授权和 token，包括状态查询。凭据无效或绑定被撤销后，Service 记录 ~failed~ 和对应错误。

~network.service()~ 是本地查询，返回完整配置、绑定状态、绑定错误与运行时代次，未设置时返回 None / null。业务获取并持久化成功配置，下次重新设置：

#+begin_src typescript
await workspace.network.setService(savedService)
const current = await workspace.network.service()
// 保存 endpoint_id、relay_url、relay_token、binding，以及仍在绑定时的 auto_binding。
// generation 仅用于当前进程关联，不作为授权依据。
#+end_src

设置带有效凭据的目标不会重新扫码或绑定，首次业务请求时建立连接。设置未绑定目标自动绑定；绑定成功或失败后均清除一次性 ~auto_binding~ 数据。保存的失败状态恢复后继续展示错误，不自动重试；失败只能删除记录后扫描新二维码。不存在“绑定待确认”业务状态，也不在响应丢失时重试取得旧 token；邀请已消费时再次确认提示过期。

Network 不读写多设备列表；应用保留完整配置和随机手机身份。相同配置复用连接；替换、清除或关闭取消旧任务，业务请求不向新电脑自动重发。~clear_service~ 仅清除当前运行时目标，不撤销电脑端授权。

* 界面状态

设备页面仅展示四种状态：离线、绑定中、绑定失败、在线。~binding~ 对应绑定中，~failed~ 显示 Service 保存的具体错误，并提示“请删除此设备后重新扫码绑定”。~bound~ 仅表示持有绑定票据，在线必须由实际认证请求确定；网络失败显示离线，不删除有效票据。绑定中每轮结束后间隔 1 秒查询本地 Service，其他状态每轮结束后间隔 20 秒刷新，后台停止轮询。

* 异步请求与取消

Rust ~network.request<T>(request, options, on_success, on_error)~ 立即返回 ~RequestHandle~ ，异步触发一个成功或错误回调。请求填写 method、path、query 和 JSON body，不传目标、ALPN 或 token。

#+begin_src typescript
const handle = workspace.network.request({
  method: 'GET', path: '/status'
}, (response) => {
  // status、request_id、body 和 generation 保留；状态中包含电脑 name / device_type。
}, (error: ResponsError) => {
  // 直接按 kind 和该分支自己的 reason 分流，不包装成 Error 类。
})
handle.cancel()
#+end_src

~path~ 为以单个 ~/~ 开头的资源路径，不含 scheme、host、query、fragment 或反斜杠。动态路径段由调用方编码；query 的值由网络适配器编码并允许重复键。~body: None~ 表示无请求体，~Some(Value::Null)~ 表示显式 JSON null。

2xx 触发成功回调，保留 201、202 等状态；204 对应 JSON null。非 2xx 返回 Services 错误及 HTTP status/source/code/message；403 ~peer-not-bound~ 和 ~invalid-binding-token~ 映射为未绑定分支。Rust 通过 Serde 解码业务 DTO；响应结构错误归入网络错误原因 ~invalid_response~ 。

默认超时 10 秒，可设置 1 至 30 秒，覆盖连接、发送和读取。~RequestHandle.cancel()~ 显式取消，丢弃句柄不取消。NAPI 取消只投递信号，不等待异步线程空闲；停止时同样先发出关闭信号，再等待回调完成并释放 runtime。停止幂等，之后的新请求收到 ~cancelled/network_closed~ 。绑定和业务请求共用此生命周期。

取消、超时不保证已发出的写操作回滚。网络层不自动重试；~generation~ 随配置切换变化，旧响应不得更新当前目标。

* ResponsError Union

Rust 采用对应的 enum，ArkTS 直接使用带 ~kind~ 标签的 Union 数据；不维护一个包含所有原因的共同枚举，也不继承 Error 类。

#+begin_src typescript
type ResponsError = NotConfiguredError | NotBoundError | NetworkFailure |
  CancelledError | ServicesError | InvalidRequestError
#+end_src

| kind | 该分支独立的 reason | 附加数据 |
|------+--------------------+----------|
| ~not_configured~ | ~service_not_set~ | 尚未设置任何 Service |
| ~not_bound~ | ~binding_required~ 、~binding_revoked~ 、~invalid_credential~ | 缺少凭据、授权已撤销或凭据被拒绝 |
| ~network~ | ~connect_failed~ 、~connect_timeout~ 、~send_failed~ 、~receive_failed~ 、~request_timeout~ 、~invalid_response~ 、~response_too_large~ | 连接、传输、超时与协议失败 |
| ~cancelled~ | ~user_requested~ 、~service_changed~ 、~network_closed~ | 调用者取消、目标替换、模块关闭 |
| ~services~ | ~rejected~ | 电脑返回的 ~status/source/code/message~ |
| ~invalid_request~ | ~invalid_method~ 、~invalid_body~ 、~invalid_query~ 、~invalid_path~ 、~invalid_timeout~ 、~request_too_large~ 、~invalid_service~ 、~invalid_device_name~ 、~invalid_invitation~ 、~expired_invitation~ 、~invitation_target_mismatch~ | 本机参数校验失败 |

各分支还包含面向用户的 ~message~ 、可选 ~request_id~ 和 ~outcome~ 。~outcome~ 为 ~not_sent~ 、~rejected~ 或 ~unknown~ ，分别表示尚未发送、收到有效拒绝、已发送但结果未知。收到拒绝不自动保证无副作用，重试由业务决定。

凭据仅通过显式完整配置获取接口交给应用私有存储；不进入错误、设备展示 DTO、监控、通知或日志。Rust Debug 对绑定凭据隐藏内容。

* 电脑端分发接口

~RequestDispatcher~ 与发起请求的 Network.request 属于收发两侧接口。电脑网络模块接收请求，验证认证身份、绑定与接口访问范围，再调用内置 HttpDispatcher：

#+begin_src rust
pub struct RequestContext {
    pub request_id: Uuid,
    pub peer_id: EndpointId,
}

pub struct DispatchRequest {
    pub method: http::Method,
    pub path: String,
    pub query: Vec<QueryParameter>,
    pub body: Option<serde_json::Value>,
}

pub struct DispatchResponse {
    pub status: http::StatusCode,
    pub body: serde_json::Value,
}

pub type DispatchFuture = Pin<Box<dyn Future<Output = DispatchResponse> + Send>>;
pub trait RequestDispatcher: Send + Sync {
    fn dispatch(&self, context: RequestContext, request: DispatchRequest) -> DispatchFuture;
}
#+end_src

HttpDispatcher 构造 HTTP request，编码 query 和 body，将认证后的设备 Endpoint ID 注入 Axum 请求扩展以及 ~x-loki-device~ 和 ~x-loki-remote-devices~ 请求头，然后调用 Router 并读取 HTTP 状态与 JSON body。

Services 组合根通过 ~attach_remote~ 注入基于 Weak 引用的 Router 工厂。请求使用现有业务实例，不形成 Network → Router → Services 的永久循环持有，也不复制 handler。~peer_id~ 只来自 iroh 已认证连接，不能从请求 JSON 或 HTTP header 伪造。

API 使用 ~#[loki_api(access = "paired")]~ 显式开放给绑定设备，默认 ~local~ 。未开放的接口返回 ~remote-api-forbidden~ 。配置项和状态项各自声明远端访问范围。[[file:control-center-services.org::*通用 services 请求通道][通用 services 请求通道]]

* 设备名称与类型

手机应用持有本机显示名称，可在设置页修改并保存，后续绑定时上报；此操作不修改电脑已有授权记录，也不调用 services 的名称修改 API。services 不提供名称修改接口。

电脑 services 启动时发布 ~service/name~ 和 ~service/device_type: computer~ 。Mac 优先使用系统设置中的电脑名称，其他平台使用 hostname。手机绑定成功后从 ~GET /status~ 读取名称和类型并缓存展示，移动端在绑定时上报 ~device_type: mobile~ 。名称和类型仅用于展示。

* 存储与验证

ArkTS Application 管理最多 64 台电脑和 ~selected_endpoint_id~ ，只选择一台设置到 Network；未选中的不轮询。Workspace 的通用私有存储适配原样保存应用 JSON，不解释电脑列表。沿用 ~devices.json~ 、版本 1、随机身份和原子替换；私钥不向 ArkTS 导出，身份损坏禁止自动重置。旧数据缺少通信凭据时保持未绑定并重新扫码。

绑定失败或授权失效时，应用提示删除后重新扫码绑定，删除本地记录后可再次扫码。删除当前目标时清除 Network，删除其他记录不影响当前目标；磁盘提交失败保留原数据。

~make harmony-test~ 验证应用层恢复、自动绑定与失败展示、名称、单目标选择与 Union 回调，并测试 Rust 身份存储、状态数据和取消。~make services-test~ 使用临时身份与真实本机 relay 验证凭据签发、重启恢复、一次性邀请消费与超时清理、逐请求认证、解绑、HTTP 参数与错误保真。
