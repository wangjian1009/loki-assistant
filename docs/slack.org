#+TITLE: Slack 模块
#+SETUPFILE: .setup.org

* 技术选型
工作区接入沿用 Emacs ~slack.el~ 的做法，使用同一网页会话的 ~xoxc-~ 用户令牌和 ~d~ Cookie。services 用 ~auth.test~ 核对用户和 Team ID，通过 ~rtm.connect~ 获取并管理 WebSocket 连接地址。

* 核心设计

- services 将用户资料、会话、消息和按需下载的文件保存到本地缓存。发送请求和通知去重状态保存在内存中。
- 会话选择数据由 services 在工作区预热时准备，并随会话、用户和消息状态变化更新。查询直接读取当前内存快照，不等待预热或向 Slack 补查。Emacs 每次打开选择器重新获取一次，响应仅在本次选择期间使用。
- 他人发来的未读私信（含群组私信）、直接 ~@~ 当前用户的未读频道消息和已关注主题的普通未读消息会触发桌面通知。线程回复沿用所属会话的规则。 [[file:slack-services.org::#conversation-watches][主题聊天关注队列]]
- 已读位置由客户端显式提交 ~through_ts~ 推进。顶层消息和各线程的游标只向前移动，连同初始未读基准写入会话的 ~info.txt~ ，重启后恢复。

* 缓存设计

#+BEGIN_EXAMPLE
~/.cache/slack/{team_id}/
├── users/
│   ├── {user_id}.txt
│   └── {user_id}.png
├── icons/
│   └── {sha256}.png
├── conversations/{conversation_id}/
│   ├── info.txt
│   ├── messages/
│   │   └── {ts}.txt
│   └── threads/
│       └── {thread_ts}/
│           └── {ts}.txt
└── attachments/
    ├── {key}.original.{ext}
    └── {key}.preview.{ext}
#+END_EXAMPLE

- 每个 ~.txt~ 文件保存一条 UTF-8 S 表达式。顶层消息平铺在 ~messages/~ 下，线程回复按根消息的 ~thread_ts~ 分目录，文件名保留 Slack 返回的原始 ~ts~ 。
- services 启动时读取已授权工作区的缓存，收到 Slack 更新后更新对应文件。写入时先写同目录的临时文件，再原子替换。资料或消息缓存缺失或损坏时按需从 Slack 补取。
- 附件跟随所属消息记录，记录原始文件名、MIME 类型和缓存引用。文件按需下载到工作区的 ~attachments/~ ，同一 Slack 文件可由多条消息共用。 ~{key}~ 优先取 Slack ~file_id~ 。缺少 ID 时使用 ~url-~ 加实际下载 URL 的 SHA-256 小写十六进制值，原件和预览各用自己的 URL 计算。
- 消息自带的图片图标以 URL 的 SHA-256 散列为文件名保存在 ~icons/~ ，沿用附件的缓存保留时间。同一 URL 由多条消息共用。
- 原件优先沿用原始文件名的扩展名，缺失时按下载响应的 MIME 类型推断，仍无法识别时用 ~bin~ 。预览按下载响应的图片类型取扩展名。例如同一附件可保存为 ~F123ABC.original.png~ 和 ~F123ABC.preview.webp~ 。
- 在 Slack 配置中通过 ~cache_retention_days~ 设置消息和附件的缓存保留天数，默认 30 天。services 启动时、配置变更后和之后每天清理一次。普通消息和附件按各自的文件修改时间计算，线程按根消息及所有回复中最近一次写入的时间计算，到期时一起清理。过期数据在查询或打开时按需从 Slack 补取。
- 本机查询接口可返回用户资料、头像、会话、消息和附件的缓存绝对路径。Emacs 直接读取文件，用 ~read~ 解析 ~.txt~ 。文件缺失时，Emacs 重新请求 services 补取。
