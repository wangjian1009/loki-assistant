* 模块边界

- Mac 应用：界面、配置、异步进程调用、返回值解码、错误提示与 Emacs 应用激活。
- Emacs 插件：会话识别、会话标识、显示 buffer、调用 agent-shell、请求校验与响应编码。
- ~emacsclient~ ：连接 Emacs server，执行统一入口并返回函数结果。

第一阶段不包含新建或终止会话、完整对话流展示、手机端、跨设备通信及独立后台服务。

* 调用与编码

Mac 应用以独立子进程执行 ~emacsclient --eval~ ，从标准输出获取返回值。通过独立参数传递配置与表达式，不经过 shell。

统一入口为 ~loki-assistant-request~ ，接收一个 Base64 字符串参数，返回一个 Base64 字符串。

1. 请求对象序列化为 UTF-8 JSON，再编码为单行、标准 Base64。
2. 将编码结果作为唯一字符串参数，调用统一入口。
3. 插件解码、校验并执行约定操作，将响应按同样方式编码后返回。
4. ~emacsclient~ 将返回值打印为带外层双引号的 Elisp 字符串。
5. Mac 端校验输出仅包含一个带引号的标准 Base64 字符串，去除外层引号及末尾输出换行，再进行 Base64 和 UTF-8 JSON 解码。

标准 Base64 不含双引号、反斜线或换行，因此无需实现通用 Elisp 字符串解析器。编码时禁止插入换行。插件限制编码后请求最多 1 MiB，Mac 端限制标准输出最多 1 MiB；协议字段及操作类型由插件校验。

调用结构如下，占位内容需替换为真实请求的编码：

#+begin_src emacs-lisp
(loki-assistant-request "<请求 JSON 的 Base64 编码>")
#+end_src

调用需要等待返回值，不能使用 ~--no-wait~ 或 ~--suppress-output~ 。调用方设置超时，并禁用 Emacs 不可达时的替代编辑器启动行为。

此通道是单次请求与响应，不提供持续事件推送。仪表盘和会话窗口展示时自动刷新，会话窗口也支持手动刷新。

* 请求与响应

以下示例展示编码前的 JSON。协议版本从 ~1~ 开始，请求标识由调用方生成并在响应中回传；无法解码或读取请求标识时响应标识为 ~null~ 。

#+begin_src json
{
  "version": 1,
  "id": "request-1",
  "operation": "list-sessions",
  "params": {}
}
#+end_src

成功响应：

#+begin_src json
{
  "version": 1,
  "id": "request-1",
  "ok": true,
  "result": {"sessions": []}
}
#+end_src

失败响应：

#+begin_src json
{
  "version": 1,
  "id": "request-2",
  "ok": false,
  "error": {"code": "session-not-found", "message": "目标会话已失效"}
}
#+end_src

* 操作语义

| 操作             | 参数                     | 成功结果               | 行为                         |
|------------------+--------------------------+------------------------+------------------------------|
| ping             | 空对象                   | emacs_version, plugin_version | 检查插件连接与版本      |
| list-sessions    | 空对象                   | sessions 数组          | 返回当前 agent-shell 会话    |
| select-session   | session_id               | session_id, emacs_pid  | 在 Emacs 中显示目标 buffer   |
| send-prompt      | session_id, prompt       | session_id, accepted   | 向目标会话提交需求           |

当前已实现 ~ping~、~list-sessions~、~select-session~ 和 ~send-prompt~ 。请求标识必须为 1 至 128 个字符的字符串，参数必须为 JSON 对象。

~select-session~ 成功结果的 ~emacs_pid~ 为正整数，由插件返回 ~emacs-pid~ 的实际值。Mac 必须按此 PID 激活所属 Emacs，不按应用名选择其他实例。进程不存在或无法激活时，保留已选会话并明确提示激活失败。

协议版本保持 ~1~；~emacs_pid~ 从插件 ~0.2.0~ 起提供。当前 Mac 应用需要同步加载该版本插件，缺失或无效的 PID 按无效响应处理，不能回退到按名称激活。

会话包含 ~id~ 、 ~buffer_name~ 、 ~project_path~ 和 ~status~ 。项目路径无法获取时为 ~null~ ；状态为 ~ready~ 、 ~busy~ 或 ~unknown~ ，适配时须依据真实 API 判断。

会话标识是插件分配的非展示字段，在会话存活期间稳定，不使用可能重名或改变的 buffer 名称作为身份。Emacs 重启后须重新获取列表。

~send-prompt~ 的 ~prompt~ 必须为非空字符串。只有确认当前会话允许提交时才发送，否则返回可解释的错误；第一阶段不自行排队或中断正在执行的任务。

~accepted: true~ 仅表示需求已成功提交给 agent-shell，不代表 agent 已完成任务。具体调用和发送条件须在实现前核实 agent-shell 当前版本的接口。

* 失败处理

- 连接或进程失败：Mac 端处理进程退出码、标准错误、超时和不可解析的输出。
- 协议失败：使用 ~invalid-request~ 、 ~unsupported-version~ 、 ~unknown-operation~ 。
- 业务失败：使用 ~agent-shell-unavailable~ 、 ~session-not-found~ 、 ~session-not-ready~ 、 ~send-failed~ 。
- 未预期的插件失败：使用 ~internal-error~ ，详细诊断保留在 Emacs 中。

进程正常退出不等于操作成功，仍须读取响应中的 ~ok~ 。进程超时也不保证 Emacs 内操作已取消；发送结果不确定时不得自动重试，避免重复提交。
