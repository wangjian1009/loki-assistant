#+TITLE: Slack 本机 HTTP API v1

* 范围与约定

本协议供 Emacs 通过现有异步 HTTP 客户端调用，适用于多个 Slack 项目及各项目的已有私信会话。services 负责 Slack OAuth、Socket Mode、消息缓存与发送。后台连接和配置说明见 [[file:slack-integration.org][Slack 后台接入与 Emacs 使用]]。

- RESTful 接口以会话、消息、已读位置、授权记录和发送记录为资源。~GET~ 读取资源，~POST~ 在集合中提交新资源，~PUT~ 幂等更新已知资源，~DELETE~ 结束当前本机授权会话。客户端通过 ~Location~ 找到新建的授权记录或异步发送记录。
- Emacs 每次请求从 =~/.assistant/service= 查找 loopback 地址，使用 ~loki-assistant-request~ 的 ~:headers~、~:params~ 和 ~:body~ 传递参数。JSON 响应包含字符串 ~api_version: "1"~ ，HTTP 状态码及错误结构沿用 services 约定。带 JSON 请求体的调用使用 ~Content-Type: application/json~ 。 [[file:emacs.org::*通用 HTTP 请求][Emacs HTTP 客户端]]、[[file:control-center-services.org::*错误响应原则][services 协议约定]]
- 所有 ~/slack/~ 路由使用 ~local~ 访问范围，响应带 ~Cache-Control: no-store~ ，使用无 CORS 的 loopback listener。除 OAuth 浏览器回调、结果页和通知点击入口外，调用均需 ~Authorization: Bearer <token>~ 。Emacs 通过仅当前用户可读的 =~/.assistant/slack-api-token= 读取本机凭据。services 首次随机生成凭据，按文件权限 ~0600~ 原子保存。登录 Keychain 保存 OAuth access token 和 refresh token。app-level token 按项目的 ~password_id~ 保存在 pass。
- 读写会话、消息、已读和发送记录的请求还需带 ~X-Loki-Slack-Session~ ，值取自状态接口的 ~session_id~ 。同一会话的服务重启、token 刷新和同账户重新授权沿用此 ID。切换账户或断开后重新授权会分配新 ID，旧请求返回 ~409 slack-session-changed~ 。Emacs 将草稿与原 ~session_id~ 关联。

- 使用 ~X-Loki-Slack-Project~ 选择本机项目。已有 ~default~ 项目或仅配置一个项目时，省略请求头可选择该项目。OAuth 回调通过一次性 ~state~ 中的项目标识路由，并验证实际 Slack Team。共享 ~/status/slack/projects~ 按项目发布授权与连接状态。受保护的 ~/slack/status~ 还提供当前会话的私有标识。

* 凭据与连接状态

** 查询状态

~GET /slack/status~ 始终可供具备本机 Bearer 凭据的客户端查询。~authorization_state~ 取 ~unconfigured~、~authorization_required~、~authorized~、~reauthorization_required~ 或 ~credentials_unavailable~ 。~socket_state~ 取 ~stopped~、~connecting~、~connected~ 或 ~reconnecting~ 。~session~ 在没有有效会话时为 ~null~ 。~issue~ 为 ~null~ 或经过脱敏的 ~{code, message}~ 。

#+begin_src json
{
  "api_version": "1",
  "authorization_state": "authorized",
  "socket_state": "connected",
  "session": {
    "session_id": "c0faa5da-0a58-47e9-83db-15aef1780202",
    "team_id": "T024EXAMPLE",
    "user_id": "U010EXAMPLE",
    "team_name": "项目协作"
  },
  "issue": null
}
#+end_src

** 配置、授权与断开

- 新增工作区调用通用配置保存接口，Slack 在 services 内完成授权并返回保存结果。重新授权使用 ~POST /config/actions/slack/authorize/{project}~ ，完成后返回操作结果。应用令牌通过 ~PUT /data/slack/app_token~ 写入 pass。 [[file:control-center-services.org::*结构化配置][结构化配置]]
- ~POST /slack/oauth/authorizations~ 使用空请求体，创建一条有效期为 600 秒的 PKCE 授权记录，返回 ~201 Created~ 。~Location~ 指向 ~/slack/oauth/authorizations/{id}~ ，JSON 包含 ~id~、~state~、~authorization_url~ 和 ~expires_at~ 。新的记录会将上一次仍待完成的记录置为 ~superseded~ 。若已有授权，当前会话继续可用，直到新授权成功并完成切换。
- ~GET /slack/oauth/authorizations/{id}~ 返回 ~id~、~state~、~expires_at~ 和 ~error~ 。~state~ 取 ~pending~、~succeeded~、~failed~、~expired~ 或 ~superseded~ 。~error~ 为 ~null~ 或已脱敏的项目错误对象。此 Slack 接口可查询已创建的授权记录。授权记录保存在内存，进程重启或记录清理后查询返回 ~404 slack-authorization-not-found~ 。
- ~GET /slack/oauth/callback~ 接受 Slack 提供的 ~state~ 与 ~code~ 或 ~error~ 。核对注册回调地址和未消费的 ~state~ ，在换取凭据前消费该授权记录的一次性 ~state~ 。仅当前有效记录可提交凭据并切换会话。用户拒绝或兑换失败时将记录置为 ~failed~ 。通过校验的回调返回 ~303 See Other~ ，~Location~ 指向固定路径 ~/slack/oauth/result~ 。结果页提示返回 Emacs 查看授权结果。
- ~DELETE /slack/session~ 使用空请求体，校验请求头中的 ~session_id~ 。持久化断开并取消该会话后台任务，移除本机用户凭据及会话数据，保留 app-level token 供重新授权。成功断开或已无会话时返回 ~204 No Content~ 。如当前已切换到另一个会话，返回 ~409 slack-session-changed~ 。已经发往 Slack 的发送请求可能已经送达。Slack 工作区中的应用授权由 Slack 管理。

创建授权记录后，响应体给出浏览器授权地址及其到期时间。

#+begin_src json
{
  "api_version": "1",
  "id": "7ef7b916-0c7c-4fa7-826a-0dddead5c88a",
  "state": "pending",
  "authorization_url": "https://slack.com/oauth/v2/authorize?state=example",
  "expires_at": "2026-11-20T09:10:00Z"
}
#+end_src

* 查询收件箱、会话和消息

** 共同分页规则

- 分页请求接受可选的 ~limit~ 和 ~cursor~ 。默认 ~limit~ 为 50，可取 1 到 100。~cursor~ 是 services 生成的不透明字符串，仅用于同一会话、端点、目标和筛选条件。过期、格式错误或与目标不匹配时返回 ~400 slack-invalid-cursor~ ，客户端从第一页重新查。
- 分页响应包含 ~items~、~next_cursor~ 和 ~sync_state~ 。~next_cursor: null~ 表示到达当前查询可提供的末页。~sync_state~ 为 ~live~ 或 ~cached~ 。后者表示连接中断、后台同步未完成或本次查询回退到缓存。服务可按需向 Slack 取历史。暂无可用缓存且无法取回指定数据时返回 ~503 slack-data-unavailable~ 。如果本地还有已知历史缺口，保留可继续查询的游标，待 Slack 恢复后补齐。
- 会话列表使用排序键分页，期间有新活动的会话可能移到第一页。Emacs 按会话 ~id~ 合并并定期刷新第一页。时间线和线程以 ~ts~ 为分页边界。第一页返回最近一页，每页内部按时间从早到晚，下一页由 ~next_cursor~ 指向更早消息。Emacs 每次刷新按 ~ts~ 合并。新一页与已显示消息没有重叠时可继续向前取页以接上。

** 会话列表与收件箱

~GET /slack/conversations~ 按 ~last_activity_ts~ 递减排序，空值排在末尾，同一时间按 ~id~ 升序，支持 ~kind=im~ 或 ~kind=mpim~ 。Emacs 收件箱使用 ~GET /slack/conversations?unread=true~ ，仅返回有未读的会话，按最近一次未读活动递减排序，同一时间按 ~id~ 升序。省略 ~unread~ 或传 ~false~ 时返回全部会话，可与 ~kind~ 筛选组合使用。

#+begin_src json
{
  "api_version": "1",
  "sync_state": "live",
  "items": [
    {
      "id": "D024EXAMPLE",
      "kind": "im",
      "title": "林舟",
      "last_activity_ts": "1795142160.000100",
      "preview": "好，我把会议链接也放进邀请。",
      "unread_count": 2,
      "first_unread": {"ts": "1795141860.000100", "thread_ts": null}
    }
  ],
  "next_cursor": null
}
#+end_src

~first_unread~ 是首条未读的位置，值为 ~null~ 时表示已读完。若它的 ~thread_ts~ 有值，Emacs 可直接打开根消息对应的线程。~last_activity_ts~ 与 ~preview~ 分别是最新消息的时间戳与纯文本摘要。没有消息时两字段均为 ~null~ 。

** 时间线与线程

~GET /slack/conversations/{id}/messages~ 的 ~items~ 只含顶层消息。~GET /slack/conversations/{id}/threads/{thread_ts}/messages~ 中的 ~thread_ts~ 使用根消息的 Slack 时间戳。线程页每次返回 ~root~ ，~items~ 只含回复。两种响应均含 ~conversation_id~ 和该视图的 ~read_through_ts~ 。未设置已读位置时该值为 ~null~ 。会话 ID 与 ~ts~ 共同标识消息。~ts~ 和 ~thread_ts~ 保留 Slack 的十进制字符串，服务端按精确时间比较。文本为给 Emacs 展示的纯文本，显示名无法取得时使用发件人 ID，系统消息没有对应作者时 ~author~ 为 ~null~ 。

~first_unread_ts~ 给出当前视图中最早的本机未读消息，已读完时为 ~null~ 。~covered_range~ 给出 services 已完整核对的时间区间，端点 ~from_ts~、~through_ts~ 均包含在内。已知覆盖的时间区间中缺失的旧条目可从 Emacs 视图移除。直接用缓存返回，或该页无法确认完整时，整个 ~covered_range~ 为 ~null~ ，Emacs 只合并返回的消息。

#+begin_src json
{
  "api_version": "1",
  "conversation_id": "D024EXAMPLE",
  "sync_state": "live",
  "read_through_ts": null,
  "first_unread_ts": "1795141860.000100",
  "covered_range": {"from_ts": "1795141860.000100", "through_ts": "1795141860.000100"},
  "items": [
    {
      "ts": "1795141860.000100",
      "thread_ts": null,
      "author": {"id": "U024EXAMPLE", "name": "林舟"},
      "text": "明天可以，我来发邀请。",
      "reply_count": 2,
      "edited": false
    }
  ],
  "next_cursor": "opaque-cursor"
}
#+end_src

* 已读位置

客户端通过 ~PUT~ 更新目标时间线或线程的 ~/read-position~ 资源。JSON 请求体只含必填的 ~through_ts~ ，该消息必须属于路径指定的视图。services 对同一视图只推进位置，重复或乱序提交返回当前有效值。顶层时间线与各线程的更新各自独立。

首次授权时从当前时刻开始累计未读。早于该时刻的历史供浏览，断线期间新消息补拉后按已读位置计算未读。未读计数排除当前用户自己发的消息。普通 GET 保持已读位置，客户端在用户实际阅读或明确操作时调用写入接口。

#+begin_src http
PUT /slack/conversations/D024EXAMPLE/threads/1795141860.000100/read-position HTTP/1.1
Host: 127.0.0.1:47321
Authorization: Bearer <token>
X-Loki-Slack-Session: c0faa5da-0a58-47e9-83db-15aef1780202
Content-Type: application/json

{"through_ts":"1795142160.000100"}
#+end_src

#+begin_src json
{
  "api_version": "1",
  "conversation_id": "D024EXAMPLE",
  "thread_ts": "1795141860.000100",
  "read_through_ts": "1795142160.000100",
  "unread_count": 1
}
#+end_src

响应中的 ~unread_count~ 是更新后整个会话的未读条数，客户端可直接刷新会话行。

* 发送与结果查询

客户端向对应的消息集合发起 ~POST~ 。会话路径发送顶层消息，线程路径向指定根消息添加回复。JSON 请求体只含 ~text~ ，通过 ~Idempotency-Key~ 请求头传递客户端生成的 UUID。~text~ 需包含非空白内容，长度至多 4,000 个 Unicode 码点，保留原内容和换行，以纯文本消息发送。发件人取自当前授权用户。

#+begin_src http
POST /slack/conversations/D024EXAMPLE/threads/1795141860.000100/messages HTTP/1.1
Host: 127.0.0.1:47321
Authorization: Bearer <token>
X-Loki-Slack-Session: c0faa5da-0a58-47e9-83db-15aef1780202
Content-Type: application/json
Idempotency-Key: 6756181d-af8c-4406-943f-ecae48301786

{"text":"好，收到。"}
#+end_src

services 先持久登记，再由后台任务投递。提交仍在处理时返回 ~202 Accepted~ ，已完成的重复提交返回 ~200 OK~ 及已有结果。两者均通过 ~Location~ 给出 ~/slack/send-requests/{request_id}~ 。读取该记录返回 ~200 OK~ 及当前状态。

~request_id~ 使用 ~Idempotency-Key~ 的 UUID，因此客户端能在尚未收到 ~Location~ 时拼出发送记录的路径。同一 ~session_id~ 下，该 ID 与消息集合路径对应的会话、线程及正文绑定，直到本机授权会话结束。对相同内容并发或重试提交只登记一次。用该 ID 提交不同内容或目标时返回 ~409 slack-request-id-conflict~ 。终态记录保留提交摘要、目标与结果，正文由待发任务暂存，成功发送的消息进入正常消息缓存。

| ~state~ | ~result~ / ~error~ | 客户端行为 |
|---------+---------------------+------------|
| ~pending~ | 两者均为 ~null~ | 保留草稿并查询结果 |
| ~sent~ | ~result~ 为 ~{ts}~ ，~error~ 为 ~null~ | 清空草稿，按 ~ts~ 刷新并定位已发送的消息 |
| ~failed~ | ~result~ 为 ~null~ ，~error~ 为项目错误对象 | 保留草稿，显示明确失败原因。若 Slack 限流，参考 ~retry_after_seconds~ |
| ~unknown~ | ~result~ 为 ~null~ ，~error~ 含 ~slack-delivery-unknown~ | 保留草稿，刷新会话核对。再次发送由用户主动操作 |

#+begin_src json
{
  "api_version": "1",
  "request_id": "6756181d-af8c-4406-943f-ecae48301786",
  "conversation_id": "D024EXAMPLE",
  "thread_ts": "1795141860.000100",
  "state": "pending",
  "result": null,
  "error": null,
  "retry_after_seconds": null
}
#+end_src

Emacs 请求超时后用同一个 ID 查发送记录。查到 ~404 slack-send-request-not-found~ 时可用相同的路径、~Idempotency-Key~ 和请求体重试。services 在向 Slack 发请求前持久化已开始投递的状态。进程重启时可继续处理还未开始的登记，已经开始且缺少 Slack 明确结果的记录转为 ~unknown~ 。Slack 返回成功后以会话 ID 和消息 ~ts~ 合并 Web API 响应与 Socket Mode 消息。

* 错误

JSON 错误使用 ~{"api_version":"1","status":409,"error":{"source":"business","code":"slack-session-changed","message":"Slack 会话已变更，请刷新状态。"}}~ 。参数与调用方身份错误归属 ~services~ ，Slack 业务与上游错误归属 ~business~ 。发送记录中的 ~error~ 复用同一错误对象。

| HTTP | ~error.code~ | 条件 |
|------+--------------+------|
| 400 | ~invalid-request~ | 请求体、路径或查询字段无效 |
| 400 | ~slack-invalid-cursor~ | 页游标无法用于当前查询 |
| 400 | ~slack-oauth-invalid-state~ | OAuth 回调状态缺失、过期或已消费 |
| 401 | ~slack-local-auth-required~ | 本机 Bearer 凭据缺失或不匹配 |
| 403 | ~slack-permission-denied~ | 当前 Slack 用户缺少所需权限 |
| 404 | ~slack-authorization-not-found~ | 找不到指定的 OAuth 授权记录 |
| 404 | ~slack-conversation-not-found~ | 当前会话目录中找不到目标 |
| 404 | ~slack-thread-not-found~ | 找不到指定根消息 |
| 404 | ~slack-send-request-not-found~ | 当前授权会话中找不到发送记录 |
| 409 | ~slack-authorization-required~ | 需要首次授权或重新授权 |
| 409 | ~slack-not-configured~ | OAuth 所需的应用配置尚未提供 |
| 409 | ~slack-session-changed~ | 客户端的会话 ID 已失效 |
| 409 | ~slack-request-id-conflict~ | 已有发送记录的目标或正文与提交不符 |
| 422 | ~slack-invalid-read-position~ | 消息时间戳不属于指定视图 |
| 422 | ~slack-app-token-rejected~ | Slack 拒绝候选 app-level token |
| 429 | ~slack-rate-limited~ | 上游暂时限流且当前读取无法用缓存完成，附 ~Retry-After~ 秒数 |
| 502 | ~slack-upstream-error~ | Slack 无法完成请求，且当前读取无法用缓存完成 |
| 503 | ~slack-data-unavailable~ | 当前请求缺少所需的缓存和 Slack 数据 |
| 503 | ~slack-credentials-unavailable~ | Keychain 暂时不可访问 |
| 503 | ~slack-storage-unavailable~ | 本机 Slack 存储暂时无法读写 |
