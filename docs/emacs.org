#+TITLE: Emacs 包使用说明

* 已实现能力

~loki-assistant~ 提供 Customize 风格的服务配置管理界面，支持异步访问 services HTTP API，并向指定通知处理器发送目标 buffer、标题、可选正文和应用标识。~Package-Requires~ 声明最低版本为 Emacs 29.1、Logview 0.19.3 和 AgentShell 0.94.1。~make emacs-load~ 会通过 ~package.el~ 安装缺失依赖，安装 AgentShell 时可从 MELPA 获取。

先按 [[file:../README.org::*快速开始][快速开始]] 启动 services；默认处理器的系统通知还需要菜单栏应用。加载与测试入口见 [[file:../README.org::*开发操作][开发操作]]。持久配置可将仓库的 ~emacs/~ 绝对路径加入 ~load-path~ ，再加载包：

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/loki-assistant/emacs")
(require 'loki-assistant)
#+end_src

* 界面快捷键

Loki Assistant 的界面在状态栏显示操作快捷键。按 ~C-c C-q~ 退出当前界面，按 ~?~ 查看模式帮助。编辑配置字段或 Slack 草稿时，按 ~C-c ?~ 查看帮助。 [[file:emacs-ui-design.org][Emacs 界面设计规范]]

* 命令菜单

安装 Hydra 后，执行 ~M-x loki-assistant-command-map~ 可以打开命令菜单。也可以绑定快捷键。

#+begin_src emacs-lisp
(global-set-key (kbd "C-x a") #'loki-assistant-command-map)
#+end_src

使用 ~use-package~ 时通过 ~:bind~ 绑定。按下菜单中的快捷键后即退出菜单。

| 快捷键 | 命令     |
|--------+----------|
| c      | 服务配置 |
| d      | 设备管理 |
| r      | 稍后阅读 |
| ~C-c C-q~ | 退出 |

* 本机服务发现

每次请求重新读取 ~loki-assistant-service-file~ ，默认为 ~~/.assistant/service~ 。仅接受 IPv4/IPv6 loopback 地址和有效端口，不缓存端口；文件缺失、格式错误和连接失败均通过回调反馈。 ~loki-assistant-request-timeout~ 默认为 10 秒，可在单次调用中用 ~:timeout~ 覆盖。

* Slack 工作区配置

执行 ~M-x loki-assistant-config~ 并选择 Slack 模块，再点「新增工作区」，填写 Team ID 并保存。每个 Team 节点会列出全部字段，未填写或尚未取得的值显示「未设置」。凭据不全时会打开本机配置页，也可点击「重试」再次打开。可以在网页或通过该行的「编辑」填写同一会话的 ~xoxc-~ 令牌和 ~d~ Cookie。两个密码输入框在点击保存时提交。选择节点旁的「删除」并确认，即可删除该工作区及其配置凭据。 [[file:slack-development.org::*接入步骤][Slack 工作区配置]]

* Slack 聊天

~M-x loki-assistant-slack-select-chat~ 使用 Consult 选择会话。每个会话使用独立的 Emacs 窗口和 shell-maker 输入区。再次选择同一会话时会切回它的窗口。

候选显示「Team 名 · 聊天名」、私聊头像和未读状态。最后一条消息的发送者、时间和预览分列对齐。列表按「已打开」「未读」「其他」分组。输入 Team 名、聊天名称或用户名可模糊筛选，中文用户名支持全拼、拼音片段和首字母。 [[file:slack-emacs.org][Emacs 中的 Slack 操作界面]]

在聊天选择器里先输入 ~@~ 可切换到 Slack 用户目录。继续输入姓名、用户名、Team 名或拼音筛选，按 ~RET~ 打开所选用户的私聊。删掉开头的 ~@~ 可回到会话候选。 [[file:slack-emacs.org::*按用户打开私聊][按用户打开私聊]]

在 Slack 聊天里按 ~C-c n~ 设置昵称。光标在提及上时编辑被提及的人，在消息其他位置时编辑发送者。光标在输入区时，单人私聊默认选择对方，频道和群聊会打开用户选择器。 ~RET~ 保存，留空提交可清除昵称， ~C-g~ 取消。 [[file:slack-emacs.org::*在聊天中设置昵称][聊天中的昵称操作]]

带线程的消息左侧显示折叠箭头，默认展开回复。点击消息正文或箭头，也可以将光标移到消息上按 ~RET~ ，即可折叠或重新展开。连续来自同一发送者的消息共用一个独占一行的身份色块。消息末尾的灰底色块显示发送时间。在「我」色块下方的 ~❯~ 后输入消息，按 ~RET~ 激活按钮或发送草稿，按 ~S-RET~ 插入换行。消息随 buffer 自动更新，按 ~C-c C-r~ 可刷新最近一页和已展开的线程，并恢复订阅。

在根消息或回复上按 ~S-Enter~ 打开独立线程。线程中发送的回复会自动显示在主聊天里。在线程中按 ~C-c C-q~ 返回主聊天并保留草稿。

在主题聊天主窗口按 ~C-c C-w~ 增加或取消关注，标题会显示当前状态。关注主题中的普通未读消息和线程回复均可触发系统通知。 [[file:slack-emacs.org::#conversation-watches][主题聊天关注操作]]

* 设备管理

~M-x loki-assistant-devices~ 打开 ~*Loki Assistant Devices*~ buffer；默认只显示当前绑定设备的名称、身份与绑定时间，以及“新增设备”入口。不在托盘中提供设备绑定功能，托盘的其他功能保留。

点击“新增设备”或按 ~a~ 后，在当前 buffer 中展开二维码、目标电脑身份、到期时间和绑定状态。services 创建五分钟有效的单次邀请并生成 PNG，Emacs 直接展示返回的 ~qr_code_png_base64~ ，不自行编码二维码，不显示或保存原始令牌。显示图片需要支持 PNG 的 Emacs 图形界面；中继未连接时显示服务端原因。

只有展开的邀请处于等待状态且 buffer 可见时，每两秒查询一次进度。完成后自动更新设备列表并移除二维码，显示绑定结果；过期或失败后可“重新生成”。“收起”停止查询并取消未完成邀请；关闭 buffer 也会清理邀请与计时器，迟到响应不会恢复旧界面。短暂切换到其他 buffer 不发送后台进度请求，服务端有效期仍继续计算。

按 ~g~ 刷新已绑定设备列表并保留当前邀请。按 ~C-c C-q~ 关闭界面并取消未完成的邀请。设备旁的“解除绑定”在确认后调用 services，失败时保留原设备并展示原因。列表表示绑定关系，不代表设备在线。可以在 Hydra 命令菜单中按 ~d~ 打开设备管理，开发操作使用根目录 ~make emacs-devices~ 。HTTP 字段与传输协议见 [[file:control-center-services.org::*扫码绑定][扫码绑定协议]]。HarmonyOS 扫码客户端尚未接入。

* LLM 用量查询

执行 ~M-x loki-assistant-llm-usage~ ，也可在 Hydra 菜单按 ~u~ 。用 ~1~ 至 ~5~ 切换概览、请求历史、会话、累计用量和实时请求，窗口标题随视图更新。按 ~C-c C-q~ 关闭用量或请求详情窗口。按 ~f~ 设置筛选，~F~ 清除，~g~ 刷新，~l~ 加载下一页。概览或会话选中一行后按 ~RET~ 查看对应的请求，按 ~b~ 返回。请求历史按 ~RET~ 打开详情，可查看和复制上游原始 ~usage~ 。实时请求页面按 ~g~ 读取最新快照，按 ~RET~ 查看选中请求。 [[file:llm-usage-storage.org::*用量查询界面][数据口径与查询接口]]

* Emacs 状态主动上报

加载 ~loki-assistant~ 时默认开启 ~loki-assistant-monitor-mode~ 。Emacs 每 5 秒向 services 的 ~POST /emacs/receiver/status~ 上报一次 ~emacs/runtime~ ，包含进程 ID、版本、启动时间和最近上报时间。自定义状态变更会合并触发同步，请求失败后在下一周期重试。

可以主动触发一次同步：

#+begin_src emacs-lisp
(loki-assistant-status-sync)
#+end_src

外部上报必须符合 ~GET /stats/meta~ 的状态声明，失败时显示具体字段错误，服务端整批保留原值。自定义状态需先在 services 中通过 ~#[loki_status]~ 声明；以下 ~key1~ 、 ~items~ 示例演示本地仓库操作，这些键具备服务端声明后才能用于 HTTP 上报。

状态数据统一由结构化状态仓库维护。使用 ~loki-assistant-status-set-value~ 写入 app/数据项，并由 ~loki-assistant-status-trigger-sync~ 延迟 1 秒合并触发同步：

#+begin_src emacs-lisp
;; symbol 名称和值会按 JSON 规则编码；value1 发送为字符串。
(loki-assistant-status-set-value 'emacs 'key1 'value1)

;; list 和 vector 都作为 JSON array 发送；nil 删除数据项。
(loki-assistant-status-set-value 'emacs 'items '(one two))
(loki-assistant-status-set-value 'emacs 'items [one two])
(loki-assistant-status-set-value 'emacs 'items nil)

;; 用更新函数追加或修改 list/vector；返回 nil 时删除数据项。
(loki-assistant-status-update-value
 'emacs 'items (lambda (items) (vconcat (or items []) [next])))

;; 多次调用在短延迟内合并为一次最终同步。
(loki-assistant-status-trigger-sync)
#+end_src

~loki-assistant-status-sync~ 仍可用于立即发起一次异步同步；普通数据变更应使用 ~loki-assistant-status-set-value~，不要直接修改内部 hash table。~loki-assistant-status-trigger-sync~ 会重新计时，网络请求在途时把变化合并到请求完成后的下一次同步。

关闭 ~loki-assistant-monitor-mode~ 会移除 hooks 和定时器；services 保留最后一次成功数据直到重启。状态接口的完整响应和托盘读取约定见 [[file:control-center-services.org::*Emacs 主动状态上报][Emacs 主动状态上报]]。

* 文档查询与全文捕获

~loki-assistant-doc~ 通过 org-roam 提供 ~loki-assistant-doc-get~ 和 ~loki-assistant-doc-capture-full~ 。services 通过配置的 Emacs server 读取已保存的文档，或把全文和目标名交给文档模块保存。Chrome 使用固定的 loopback HTTP 接口 ~POST /doc/article~ 。

模块的 ~loki-assistant-doc-capture-templates~ 使用 org-roam 模板结构。目标 ~article~ 对应模板 ~p~ ，默认保存到 ~org-roam-directory~ 下的 ~article/YYYY/~ 。Emacs 按 ~ROAM_REFS~ 去重，并在同一次调用中完成保存和索引。Chrome 根据原请求的结果显示成功提示或错误说明。 [[file:control-center-services.org::*文档模块][文档接口与分类]]

** 稍后阅读

执行 ~M-x loki-assistant-read-later~ ，或在命令菜单按 ~r~ ，打开稍后阅读模式。列表从本地 org-roam 索引查询未读日记条目，默认按加入时间倒序显示。

| 快捷键 | 操作 |
|--------+------|
| ~g~ | 刷新未读列表 |
| ~RET~ | 打开当前条目的 Org 日记标题 |
| ~b~ | 打开当前条目的网页链接 |
| ~r~ | 保存已读时间并从未读列表移除当前条目 |
| ~?~ | 查看模式帮助 |
| ~C-c C-q~ | 退出列表 |

要更换用于定位日记文件的模板，可在 Customize 中设置 ~loki-assistant-read-later-daily-template-key~ ，默认使用 ~org-roam-dailies-capture-templates~ 中的 ~d~ 模板。捕获通过 ~org-roam-dailies-capture-today~ 写入带 ID、 ~稍后阅读~ 标签和 ~CREATED~ 属性的链接标题。删除移除标题的 ~ID~ 并更新 org-roam 索引。 [[file:control-center-services.org::*稍后阅读][稍后阅读 HTTP 协议]]

* 服务配置管理

加载包后执行 ~M-x loki-assistant-config~ ，或从仓库根目录执行 ~make emacs-config~ 。菜单栏“设置”调用 services 的 ~POST /emacs/apps/open?app=config~ ，由服务打开该界面并聚焦图形 frame；目标 Emacs 需要已将本包加入 ~load-path~ 。首次连接尚未运行的 server 时，启动行为沿用 [[file:control-center-services.org::*配置和连接][Emacs gateway 的连接约定]]。

打开配置入口后，先从 minibuffer 选择一个模块。选择器从 ~GET /meta~ 读取模块元数据，选中后通过 ~GET /data/{module_id}~ 只读取该模块的配置。每个模块有独立的 buffer。重新选择已打开的模块会回到原 buffer 并刷新配置，正在编辑或有请求执行中的页面会保留当前内容。字段、复选框和按钮沿用 Customize 的 widget。加载失败时，可以在该模块中使用「刷新 / 重试」。

字符串、文件路径、可执行文件使用文本字段；布尔值使用复选框；整数、数字、字典和列表以 JSON 文本编辑。字典和列表分别输入 JSON object 和 array；空对象、空数组、false 和 null 保留原始 JSON 语义。文件和可执行文件提供“选择文件…”按钮，可通过 minibuffer 补全进入 ~.app~ 包，也可直接输入程序名；初始目录参考当前路径或服务元数据的建议搜索目录。

| 操作 | 行为 |
|------+------|
| TAB / S-TAB | 在字段与按钮之间移动 |
| RET | 激活按钮 |
| 保存 | 直接提交该项，显示保存状态和等待时长 |
| 撤销编辑 | 回到该项最近读取或保存成功的值 |
| C-c C-c / 保存本模块修改 | 显示当前项与完成数量，逐项保存。失败时停止并展示原因，此前成功的项目已保存。 |
| g / 刷新 | 在文本字段外按键，重新读取当前模块的元数据和值。有未保存的普通字段编辑时先确认丢弃。 |
| C-c C-q | 退出当前配置窗口，保留 buffer 中的输入 |

配置由 services 保存到 ~~/.assistant/config.yml~ 。输入与元数据中的 Emacs 格式规则不符，或 JSON 文本无法解析时，输入框显示红底，仍可点击保存。services 执行实际的类型、路径和业务校验。保存成功后更新值和来源，失败时保留输入并显示原因。 [[file:config-module.org][配置中心]]

执行期间，配置项显示「正在执行并保存，请稍候…」及已等待秒数，每秒更新。操作、刷新和批量保存按钮暂时禁用，输入框仍可编辑。完成后恢复按钮，失败时在配置项和顶部标红显示服务端原因。保存期间产生的新输入保留为未保存编辑。批量保存显示当前项与进度，失败时停止，并保留此前成功保存的值。

保存请求使用独立的 ~loki-assistant-config-save-timeout~ ，默认等待 120 秒，以覆盖中转注册等配置处理器的执行时间；普通读取和预检仍使用 ~loki-assistant-request-timeout~ 。超时、连接中断或成功响应格式无效时，标记“保存结果未知”，保留输入并暂停再次提交；请等待服务端处理完成后使用“刷新 / 重试”核对实际值，再决定是否修改。不会自动重复保存。关闭配置 buffer 时停止等待计时器，已过期或已关闭界面的回调不更新控件。

“控制中心”的“登录时自动启动”由 services 控制中心模块在配置提交前同步 ~cc.loki-assistant.center~ 用户级 LaunchAgent，系统操作成功后才保存配置。失败时保留原值和当前输入，并在该项显示服务端错误，修复后可再次保存。自定义托盘构建路径通过 services 启动环境中的 ~LOKI_ASSISTANT_CENTER_EXECUTABLE~ 设置；Emacs 不再直接调用 launchctl，也不再提供本地托盘路径变量。具体行为见 [[file:control-center-services.org::*控制中心模块][控制中心模块]]。

配置界面的 ERT 测试包含在 ~make emacs-test~ 中，覆盖真实 loopback HTTP 加载和保存、输入红底提示、失败保留输入、完整快照、过期回调、保存期间继续编辑、等待状态、批量进度和结果未知后的刷新核对。登录启动的系统操作由 services 使用临时目录和 launchctl 替身测试。

* 通用 HTTP 请求

#+begin_src emacs-lisp
(loki-assistant-request
 'get "/emacs/buffers"
 :callback
 (lambda (response)
   (if (plist-get response :ok)
       (message "buffer 列表：%S" (plist-get response :data))
     (message "请求失败：HTTP %S [%s] %s"
              (plist-get response :status)
              (plist-get response :error-code)
              (plist-get response :error-message)))))

;; 查询参数按数据编码，允许中文、空格、引号等字符。
(loki-assistant-request
 'post "/emacs/activate"
 :params `((buffer . ,(buffer-name))))

;; BODY 接受原始 JSON 字符串或可编码为 JSON 的 Lisp 值。
(loki-assistant-request
 'post "/config/validate"
 :body '((module_id . "emacs")
         (key . "socket_name")
         (value . "server"))
 :timeout 5)
#+end_src

签名为 ~(loki-assistant-request method path &key params body headers callback timeout)~ ：

| 参数 | 约定 |
|------+------|
| ~method~ | 字符串或符号，例如 ~"GET"~ 、 ~'post~ ，自动转为大写 |
| ~path~ | 以 ~/~ 开头的本机路径，可带已编码的查询串；不接受主机 URL、fragment 或空白 |
| ~params~ | 查询参数 alist，键值分别 URL 编码；支持重复键；nil 值编码为空字符串 |
| ~body~ | nil 表示无正文；字符串原样发送；其他 Lisp 值编码为 UTF-8 JSON |
| ~headers~ | 额外请求头 alist；默认 ~Content-Type~ 为 ~application/json; charset=utf-8~ |
| ~callback~ | 接收单个响应 plist；省略时在 echo area 和 ~*Messages*~ 显示结果 |
| ~timeout~ | 等待回调的最长秒数，必须是正数 |

JSON 对象使用 alist 或 hash table，数组可用 vector， ~:null~ 和 ~:false~ 分别表示 JSON null 和 false， ~t~ 表示 true。传入 JSON string 标量时应自行提供带双引号的 JSON 字符串。

接口立即返回请求 buffer；无法开始请求时返回 nil。结果通过回调交付，每个请求至多回调一次，响应 buffer 和计时器自动清理。发现失败时回调可能在函数返回前执行。不要依赖回调执行时的当前 buffer；需要修改目标时，应自行捕获并检查目标 buffer。

| 响应字段 | 含义 |
|----------+------|
| ~:ok~ | HTTP 2xx 且正文为空或可解析为 JSON 时为 t |
| ~:status~ | HTTP 状态码；未收到 HTTP 响应时为 nil |
| ~:headers~ | URL 库处理后的响应头字符串，含 HTTP 状态行 |
| ~:body~ | UTF-8 解码后的正文字符串；无响应时为 nil |
| ~:data~ | 解析后的 JSON；对象为 symbol 键 alist，数组为 vector，null/false 为 ~:null~/~:false~ |
| ~:error-code~ | services 错误码或本地错误码；成功时为 nil |
| ~:error-message~ | services 中文错误说明或本地失败原因；成功时为 nil |

HTTP 失败保留状态、原始正文和可解析的 JSON，优先使用 services 返回的 ~code~ 、 ~message~ ；非 JSON 错误页使用 ~http-error~ 。HTTP 2xx 的非空正文不能解析为 JSON 时使用 ~invalid-response~ 。本地错误还有 ~service-discovery-failed~ 、 ~transport-error~ 和 ~timeout~ 。非法调用参数直接报错。

请求异步执行，不阻塞 services 回调 Emacs；不使用代理、Cookie、自动缓存或重定向，不自动重试。超时或连接中断不保证服务端操作已取消，尤其不要直接重发有副作用的请求。 ~:ok~ 表示 HTTP 层成功，业务校验结果如 ~valid~ 仍需从 ~:data~ 判断。

* 通知发送

#+begin_src emacs-lisp
(loki-assistant-notify (current-buffer) "任务完成"
                       :body "处理结果已就绪" :app "emacs")

;; 不指定 buffer 时，默认通知点击后仅显示 Emacs。
(loki-assistant-notify nil "提醒")

;; tasks 仅为示例，必须先在 services 注册对应处理器。
(loki-assistant-notify "*scratch*" "任务完成"
                       :module-id "tasks"
                       :payload '((task_id . "task-1"))
                       :callback
                       (lambda (response)
                         (message "处理器响应：%S" response)))
#+end_src

签名为 ~(loki-assistant-notify buffer title &key body app module-id payload callback timeout)~ 。 ~buffer~ 接受存活 buffer 对象、非空 buffer 名称或 nil；对象会在发送时转换为名称，不切换当前 buffer。名称按数据传递，函数不创建目标 buffer，也不保证其在通知点击时仍然存活。

~title~ 必须非空； ~body~ 接受字符串或 nil；~app~ 接受应用标识或 nil，仅含小写字母、数字、~-~ 或 ~_~ 。省略 ~app~ 时，services 的 Emacs 默认处理器补为 ~emacs~ ，center 使用随程序打包的 Emacs 图标。接口不提供自定义图标参数。 ~module-id~ 默认 ~"emacs"~ ，通过 ~POST /emacs/receiver/notification~ 中的 ~module_id~ 精确分发；未知处理器返回 HTTP 404 ~notification-handler-not-found~ 。 ~payload~ 为附加 JSON 数据。 ~callback~ 和 ~timeout~ 与通用请求接口相同。

没有 ~callback~ 时显示处理器响应状态或明确错误；有回调时调用者自行处理反馈。默认处理器返回 ~unconfirmed~ 表示已登记待确认，返回 ~confirmed~ 表示托盘已成功提交给 macOS。若响应已经包含 ~failed~ 回执，通知函数会将 ~:ok~ 设为 nil 并提取其错误码与说明，同时保留 HTTP 状态和响应内容。

成功响应中的 ~notification_id~ 位于 ~:data~ 的 ~result~ 内，可以查询最终提交状态：

#+begin_src emacs-lisp
(loki-assistant-notify
 (current-buffer) "任务完成"
 :callback
 (lambda (response)
   (if (plist-get response :ok)
       (let* ((result (alist-get 'result (plist-get response :data)))
              (id (alist-get 'notification_id result)))
         (when id
           (loki-assistant-request 'get (concat "/notification/" id))))
     (message "通知失败 [%s]：%s"
              (plist-get response :error-code)
              (plist-get response :error-message)))))
#+end_src

~submitted~ 表示已提交系统通知中心； ~failed~ 包含明确原因； ~unconfirmed~ 表示尚未确认。查询只返回当时状态，需要后续结果时由调用者择时再查询。应用图标命名规则、点击跳转、回执保留期限等服务端约定见 [[file:control-center-services.org::*系统通知模块][系统通知模块]]。

* agent-shell 集成

在 macOS 上，~loki-assistant~ 会等待 ~agent-shell~ 加载完成，再自动加载
~loki-assistant-agent-shell~ 并加入 ~agent-shell-mode-hook~ ；不需要在用户配置中单独
加载扩展。~loki-assistant-agent-shell-enabled~ 默认为 ~t~，设置为 ~nil~ 可关闭自动加载。

扩展提供 Finder 文件复制后的 ~C-y~ 文件上下文、文件拖放和项目外文件复制策略；图片显示
预览，其他文件显示为可点击链接。文件复制策略由
~loki-assistant-agent-shell-file-copy-policy~ 控制，可选 ~auto~、~always-copy~ 和
~always-original~ 。系统临时目录中的文件始终复制到当前项目的
~.agent-shell/.loki-assistant/~ 数据目录。

截图后可直接将 macOS 浮动缩略图拖入 agent-shell 会话或 viewport，显示图片预览。
截图会先复制到会话所属项目的数据目录，使用 ~截图 - YYYY-MM-DD HH-MM-SS.png~
形式命名并保留原扩展名；同一秒内重名时依次追加 ~-1~、~-2~ 等序号，不覆盖已有文件。
截图识别依据 macOS 截图临时目录或常见中英文截图文件名，始终缓存，不受
~always-original~ 策略影响。

~loki-assistant-agent-shell-yank-image~ 将剪贴板中的图片保存到当前会话缓存并插入预览，
沿用截图时间戳命名和重名避让规则，不自动发送给 Agent。该命令直接读取 Emacs 的图片
剪贴板数据，无需 ~pngpaste~ ；没有图片时提示错误。建议在会话及 viewport 中绑定 ~C-c y~ ：

#+begin_src emacs-lisp
(with-eval-after-load 'loki-assistant-agent-shell
  (dolist (map (list agent-shell-mode-map
                     agent-shell-viewport-edit-mode-map
                     agent-shell-viewport-view-mode-map))
    (keymap-set map "C-c y" #'loki-assistant-agent-shell-yank-image)))
#+end_src

Agent 的 ~permission-request~ 和 ~turn-complete~ 事件通过
~loki-assistant-notify~ 发送，因此统一使用 services 和菜单栏应用的通知链路。通知由
~loki-assistant-agent-shell-notifications~ 控制；默认在 Emacs 未聚焦或当前显示其他缓冲区时
发送，~loki-assistant-agent-shell-notify-current-buffer~ 可设为 ~t~ 以便当前会话也发送。

远程输入接收尚未实现；后续交互命令暂定命名为
~loki-assistant-agent-shell-receive-input~ ，以便与通知和文件输入能力保持同一命名空间。

* Org Edna 排程扩展

加载 ~loki-assistant~ 后，包会在 Org Edna 加载时自动接入 ~loki-assistant-edna~ ，无需将函数写入个人配置。扩展提供 ~loki-scheduled-next!~ 、 ~loki-deadline-next!~ 与 ~loki-spawn-next!~ ，支持按星期集合安排计划、截止与后继任务。

动作参数为 ~BASE DAY...~ ，基准支持 ~source~ 、 ~target~ 和 ~today~ ；星期为 ~mon~ 至 ~sun~ 的非空集合。~source~ 使用来源任务的对应规划日期与时刻，~target~ 使用目标任务已有的对应规划日期与时刻，~today~ 使用当前自然日及目标原有时刻。结果严格晚于基准日期；夏令时切换时仍保留原时刻，不跳过或重复日期。

** 已有任务依次排程

适用于已经列出的有限次数任务。把同组条目放在独立父标题下，只在第一项设置规则：

#+begin_src org
** 乐刻健身
*** TODO 乐刻健身 - 1
SCHEDULED: <2026-07-09 Thu 11:30-13:00>
:PROPERTIES:
:TRIGGER: next-sibling loki-scheduled-next!(source tue thu) chain!("TRIGGER")
:END:
*** TODO 乐刻健身 - 2
*** TODO 乐刻健身 - 3
#+end_src

完成第一项时，~next-sibling~ 选择同一父标题下的下一个已有条目；~loki-scheduled-next!~ 安排到下一个周二或周四，并保留 ~11:30-13:00~ 。~chain!("TRIGGER")~ 将本条触发规则整项复制给目标，后续完成时依次传递。上例第二项得到 ~<2026-07-14 Tue 11:30-13:00>~ ，第三项得到 ~<2026-07-16 Thu 11:30-13:00>~ 。

后续项不必提前填写触发器；此方式不新增任务。最后一项找不到下一个同级条目时自动结束，也不会越过父标题影响其他任务组。若链中后续动作失败，本次完成状态、日期修改和触发器复制一同回滚。

** 自动创建后继

每次完成后需要创建新任务时，使用：

#+begin_src org
:TRIGGER: self loki-spawn-next!(source tue thu)
#+end_src

新后继位于目标整个子树之后，标题末尾的连续阿拉伯数字自动加一，前缀和补零位宽保留；没有数字后缀时沿用原标题。自身标签、显式优先级和触发器继续保留，并写入 ~CREATED~ 。规划只写入下一次 ~SCHEDULED~ ，不复制正文、子任务、ID 或其他规划。每次执行都会创建新的后继；重新打开原任务再完成时，也会再次创建，不维护原任务与后继之间的关联。

例如 ~游泳 @ 2026-11 @ 2~ 的计划为 ~<2026-11-18 Wed 13:00>~ ，使用 ~self loki-spawn-next!(source mon wed fri)~ 完成后，会生成：

#+begin_src org
*** TODO 游泳 @ 2026-11 @ 3
SCHEDULED: <2026-11-20 Fri 13:00>
#+end_src

新节点继承相同触发器，继续完成会生成 ~游泳 @ 2026-11 @ 4~ ，计划为 ~<2026-11-23 Mon 13:00>~ 。原节点标题和已有关闭日志保持不变。重新打开第 2 项再完成，会再次从第 2 项生成一个新的第 3 项；已有第 3、4 项保持原样，编号不扫描兄弟任务的最大值。

*** 完成后间隔 6 个月

Emacs 的 ~loki-spawn-next!~ 还支持 ~BASE "+Nm"~ ，其中 ~N~ 为正整数。要以实际完成当天为基准，使用 ~today~ ：

#+begin_src org
** TODO 高尿酸血症检查
SCHEDULED: <2027-05-06 Thu>
:PROPERTIES:
:TRIGGER: self loki-spawn-next!(today "+6m")
:END:
#+end_src

标记为 ~DONE~ 时立即创建新的同级待办，把 ~SCHEDULED~ 设为完成当天往后 6 个自然月。例如在 ~2027-05-08~ 完成，新任务安排在 ~2027-11-08~ 。新任务继承同一触发器，下一次仍从实际完成日计算；原任务保留完成记录。

月末不存在同号日期时取目标月最后一天，例如 ~2026-08-31~ 加 6 个月得到 ~2027-02-28~ ，~2023-08-31~ 加 6 个月得到 ~2024-02-29~ 。原计划有时刻或同日时刻范围时继续保留；没有 ~SCHEDULED~ 也可使用 ~today~ 。

若要从原计划日期推算，可改成 ~self loki-spawn-next!(source "+6m")~ ；~target~ 使用目标任务的原计划日期。月数间隔只用于 ~loki-spawn-next!~ ，不能与星期集合混用；此新增语法尚未同步到 Org Tasks Core。
