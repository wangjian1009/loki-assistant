#+TITLE: Slack services 接口
#+SETUPFILE: .setup.org

* Team 配置

~slack/teams~ 的配置类型为 ~Vec<SlackTeam>~ 。元数据声明 ~notification_endpoint~ 为 ~/slack/config/teams~ ，以 ~team_id~ 作为 ~Key~ 字段。首次新增只填 Team ID。配置模块通过该接入点通知新增和删除，并查询待确认记录的处理结果。 [[file:config-module.org::*配置项通知接入点][配置项通知接入点]] · [[file:slack-development.org::*Team 注册流程图][Team 注册流程图]]

| 字段        | 类型       | 用途                                                               |
|-------------+------------+--------------------------------------------------------------------|
| ~team_id~   | ~Key~      | 从工作区 URL 的 ~/client/~ 路径取得，格式为 ~^T[A-Z0-9]{1,47}$~ 。 |
| ~name~      | ~string~   | 本地显示名称，可选，默认显示 Team ID。                             |
| ~team_name~ | ~string~   | Slack 返回的工作区名称，校验成功后写入，只读。                     |
| ~user_id~   | ~string~   | Slack 返回的用户 ID，校验成功后写入，只读。                        |
| ~token~     | ~Password~ | 网页会话的 ~xoxc-~ 用户令牌。                                      |
| ~d_cookie~  | ~Password~ | 同一网页会话的 ~d~ Cookie。                                        |

每个 Team 的两项已确认凭据共用一个 pass 条目。~Password.path~ 声明为 ~loki-assistant/slack/{key}.gpg~ ，其中 ~{key}~ 展开为这条记录的 ~team_id~ 。
~token~ 省略 ~Password.key~ ，保存于首行。~d_cookie~ 指定同名的 ~Password.key~ ，保存于后续的 ~d_cookie:~ 行。配置和查询结果只包含条目引用。

通过 ~PATCH~ 将 ~token~ 设为 ~null~ 时，配置模块删除整个 pass 条目并清除两个凭据字段。工作区记录保留。

#+begin_example
xoxc-…
d_cookie: …
#+end_example

** 配置模块交互

| 操作 | 接口                                                                                   | 响应                                                                                                                |
|------+----------------------------------------------------------------------------------------+---------------------------------------------------------------------------------------------------------------------|
| 新增 | ~PUT /data/slack/teams/{team_id}~ ，带 ~If-None-Match: *~ ，请求体为 ~{}~              | ~202~ 和 ~status: pending~ 。Slack 模块打开配置页。                                                                 |
| 保存 | ~PATCH /data/slack/teams/{team_id}~ ，以 ~application/merge-patch+json~ 发送更改的字段 | 数据不全或 Slack 暂不可达时返回 ~202~ 。校验成功返回 ~200~ 和 ~status: confirmed~ 。明确失败返回 ~422~ 和错误。     |
| 重试 | ~PUT /data/slack/teams/{team_id}~ ，零字节请求体                                       | 重新通知 Slack 处理同一份待确认数据，按当前结果返回 ~200~、~202~ 或 ~422~ 。                                        |
| 查询 | ~GET /data/slack/teams~                                                                | ~value~ 为生效记录，~pending~ 为可编辑的待确认记录。失败记录的 ~status~ 为 ~invalid~ ，~error~ 包含错误代码和说明。 |
| 删除 | ~DELETE /data/slack/teams/{team_id}~                                                   | 配置模块等待 Slack 结果，确认后移除记录与对应的 pass 条目。                                                         |

配置模块暂存更新后，调用内部 ~POST /slack/config/teams/{team_id}~ 通知 Slack，密码值通过 Rust API 单独读取。待确认凭据缺项时，Slack 模块打开 ~/slack/team-setup/{team_id}~ 并返回 ~202~ 。用户按页面提示在目标 Slack 工作区获取凭据，回到配置页填写并保存。

用户令牌和 Cookie d 齐全后，Slack 通过 ~auth.test~ 核对身份。校验成功后，配置模块将 ~team_name~ 和 ~user_id~ 与候选记录一起保存，设置界面可查看这两个只读字段。旧工作区会在下次成功校验凭据时补齐。明确失败时配置模块保留错误提示，清除候选记录中的 ~token~ 和 ~d_cookie~ ，并删除暂存条目。下一次校验需要重新填写这两项。已有的生效记录继续服务。 [[file:config-module.org::*配置项通知接入点][配置项通知协议]]

工作区配置生效后，services 使用同一凭据启动实时连接。连接结果通过 ~socket_state~ 和 ~issue_code~ 查询。

* 通用约定

Slack 业务接口和工作区配置只接受本机调用，客户端可直接发起请求。按会话或工作区操作时，services 使用当前会话。客户端也可用 ~X-Loki-Slack-Session~ 携带响应中的 ~session_id~ ，以便会话变更时收到冲突错误。

会话路径中的 ~id~ 格式为 ~team_id.聊天ID~ 。消息时间戳和线程根时间戳使用 Slack 返回的字符串。

分页接口接受可选的 ~limit~ 和 ~cursor~ 。每页默认 50 条，可指定 1 到 100 条。将响应的 ~next_cursor~ 传给下次请求，并沿用原有筛选条件。~next_cursor~ 为 ~null~ 时已到末页。

* 工作区状态与会话

| 方法与路径 | 请求与结果 |
|------------+------------|
| ~GET /status/slack/connections~ | 通过通用状态中心查询各工作区的 ~authorization_state~ 、 ~socket_state~ 、 ~session_id~ 和 ~issue_code~ 。 |
| ~GET /slack/team-setup/{team_id}~ | 返回填写工作区凭据的 HTML 配置页。 |
| ~DELETE /slack/session~ | 必填查询参数 ~team_id~ 。断开当前进程中的工作区会话，成功返回 HTTP 204。 |

* 用户目录

~GET /slack/users~ 一次返回已授权工作区的完整用户目录，优先使用 services 已缓存的资料。响应包含 ~api_version~ 、 ~items~ 和 ~issues~ 。每条用户记录含 ~id~ 、 ~team_id~ 、 ~team_name~ 、 ~session_id~ 、 ~name~ 、 ~display_name~ 、 ~username~ 和 ~is_bot~ 。 ~id~ 格式为 ~team_id.用户ID~ 。部分工作区查询失败时， ~issues~ 记录其 ~team_id~ 和 ~error~ ，其余工作区的用户仍可用。

~GET /slack/users/{id}~ 计划按复合用户标识查询单条用户资料。响应字段待定。

本机用户记录可带 ~cache_path~ 和 ~avatar_path~ ，分别指向资料和 PNG 头像。services 启动后预热头像，写入成功时通过 ~avatar_path~ 返回本机绝对路径。 ~GET /slack/users/{id}/avatar~ 支持显式获取头像并返回 ~cache_path~ ，其中 ~id~ 为复合用户 ID。

** 批量查询用户

~GET /slack/users~ 支持可重复的查询参数 ~id~ 。一次可传入 1 到 100 个复合用户 ID，格式为 ~team_id.用户ID~ ，同一请求可跨工作区。客户端可直接传入消息作者或私聊参与者的 ID。空值、格式无效、超限或未知查询参数会返回 HTTP 400 ~invalid-request~ 。

#+begin_example
GET /slack/users?id=T123.U123&id=T456.U456
#+end_example

查询返回 HTTP 200 和 ~Cache-Control: no-store~ 。 ~items~ 包含查到的用户，按各 ID 在请求中首次出现的顺序排列，重复 ID 只返回一次。 ~issues~ 按同样的顺序记录每个失败的 ~id~ 、 ~team_id~ 和 ~error~ 。

#+begin_src json
{
  "api_version": "1",
  "items": [
    {
      "id": "T123.U123",
      "team_id": "T123",
      "team_name": "项目协作",
      "session_id": "039f972c-2956-40b8-9281-9fca566a50eb",
      "name": "林舟",
      "display_name": "林舟",
      "username": "linzhou",
      "is_bot": false,
      "avatar_path": "/Users/me/.cache/slack/T123/users/U123.png"
    }
  ],
  "issues": [
    {
      "id": "T456.U456",
      "team_id": "T456",
      "error": {
        "source": "business",
        "code": "slack-user-not-found",
        "message": "找不到 Slack 用户。"
      }
    }
  ]
}
#+end_src

services 按工作区当前授权查询，优先使用内存中的用户资料。缺失时只向 Slack 补查对应的用户，同一批次的重复 ID 共用查找结果。只有 Slack 明确返回用户不存在时使用 ~slack-user-not-found~ 。未知工作区、授权失败和 Slack 限流分别使用 ~slack-project-not-found~ 、 ~slack-authorization-required~ 和 ~slack-rate-limited~ 。客户端可仅重试失败项。

* 会话目录

~GET /slack/conversations~ 接受可选的 ~team_id~ 、 ~kind~ 和 ~unread~ 筛选条件，并使用通用分页参数。~kind~ 可为 ~im~ 、 ~mpim~ 、 ~public_channel~ 或 ~private_channel~ 。 ~unread=true~ 筛选有未读消息的会话。

响应包含 ~api_version~ 、 ~items~ 、 ~next_cursor~ 、 ~sync_state~ 和 ~issues~ 。候选包含 ~id~ 、 ~team_id~ 、 ~team_name~ 、 ~session_id~ 、 ~kind~ 、 ~title~ 、 ~participant_ids~ 、 ~last_activity_ts~ 、 ~last_message~ 、 ~unread_count~ 及 ~last_unread_mention_ts~ 等字段。未读状态根据已获取的消息和本机已读位置计算。

* 会话选择

~GET /slack/conversations/picker~ 一次返回全部工作区的会话候选。响应不分页，返回 HTTP 200 和 ~Cache-Control: no-store~ 。

| 字段                   | 内容                                                                                                                                                                                                                          |
|------------------------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ~api_version~          | 协议版本 ~"1"~ 。                                                                                                                                                                                                             |
| ~workspaces~ | 各工作区的 ~team_id~ 、 ~team_name~ 和 ~state~ 。 ~state~ 可为 ~warming_up~ （准备中）、 ~ready~ （已完成）或 ~unavailable~ （数据暂不可用）。准备期间或部分工作区不可用时仍返回已有候选。没有可用候选时， ~items~ 为空数组。 |
| ~items~ | 会话候选。每项包含 ~id~ 、 ~team_id~ 、 ~team_name~ 、 ~session_id~ 、 ~kind~ 、 ~title~ 、 ~unread_count~ 、 ~last_activity_ts~ 、 ~last_unread_mention_ts~ 和 ~history_loaded~ 。Emacs 根据这些字段组织界面、分组和排序。 |
| ~items[].last_message~ | 最后一条消息的 ~author_name~ 、 ~ts~ 和 ~preview~ 。没有可展示的消息时为 ~null~ 。 |
| ~items[].participants~ | 私聊参与者包含 ~id~ 、 ~name~ 和 ~username~ 。已缓存的头像通过 ~avatar_path~ 提供。频道的参与者列表为空数组。 |
| ~items[].search_terms~ | services 准备的搜索词，包含会话名称、用户显示名、Slack 用户名及可用的全拼和拼音首字母。输入变化时在本次响应内筛选。                                                                                                           |

* 按用户打开私聊

~POST /slack/users/{id}/dm~ 按 ~team_id.用户ID~ 打开一对一私聊。请求无需消息正文，可带 ~X-Loki-Slack-Session~ 指定用户候选的授权会话。services 复用已知私聊，首次打开时调用 Slack 的 ~conversations.open~ 。响应返回 ~api_version~ 和 ~conversation~ ，后者包含会话目录中的会话标识、名称和授权会话等字段。Emacs 用该会话标识打开或聚焦聊天窗口。

* 消息读取

| 方法与路径 | 数据范围 |
|------------+----------|
| ~GET /slack/conversations/{id}/messages~ | 分页读取会话顶层消息。 |
| ~GET /slack/conversations/{id}/threads/{thread_ts}/messages~ | 分页读取指定线程的回复， ~thread_ts~ 取根消息的 ~ts~ 。响应还包含根消息 ~root~ 。 |

两个接口均接受 ~limit~ 和 ~cursor~ ，按 ~next_cursor~ 读取更早消息。响应包含 ~api_version~ 、 ~conversation_id~ 、 ~team_id~ 、 ~items~ 、 ~next_cursor~ 、 ~read_through_ts~ 、 ~first_unread_ts~ 、 ~covered_range~ 和 ~sync_state~ 。 ~sync_state~ 为 ~live~ 或 ~cached~ 。

消息中可包含 ~attachments~ 和 ~tables~ 。附件包含 ~title~ 、 ~mimetype~ 、 ~size~ 、 ~url~ 、 ~text~ 和 ~image~ ，其中 ~url~ 是供用户打开的链接， ~image~ 表示可读取图片预览。 ~tables~ 以表格、行、单元格的数组返回 Slack 原生表格的文本。

服务启动时预热用户与已知机器人的头像，历史分页及订阅投递可在 ~author.avatar_path~ 提供本地头像。services 获取消息后先尝试缓存支持的图片预览，缓存成功时在 ~attachments[].preview_path~ 提供本地绝对路径。下载失败或超时后继续提供消息与附件信息。Emacs 只显示由这些路径指向的本地图片。

带独立图标的 Slack 消息可提供 ~icon_path~ 或 ~icon_emoji~ 。前者指向 services 缓存的 PNG，后者是 Slack emoji 短代码。Emacs 在对应消息正文开头显示图标，同一机器人发出的消息可以带不同图标。

~GET /slack/conversations/{id}/messages/{ts}/attachments/{index}/preview~ 读取当前会话消息中的单张图片。 ~index~ 是 ~attachments~ 中从零起算的位置。成功响应为 PNG、JPEG、GIF 或 WebP，最大 5 MiB。附件或预览不可用时返回 ~slack-attachment-not-found~ 。

会话和消息记录可带 ~cache_path~ ，附件可带 ~original_path~ 、 ~preview_path~ 和 ~original_available~ 。预览接口传入 ~local_path=true~ 时按需缓存图片并返回 ~cache_path~ 。路径均为本机绝对路径，文件格式和清理规则见 [[file:slack.org::*缓存设计][缓存设计]]。

** 获取附件原件路径

~GET /slack/conversations/{id}/messages/{ts}/attachments/{index}/original~ 获取附件原件的本机绝对路径。请求体为空，可携带 ~X-Loki-Slack-Session~ 。 ~id~ 为 ~{team_id}.{conversation_id}~ ， ~ts~ 取附件所属消息自身的时间戳，线程回复使用回复的时间戳。 ~index~ 是附件在 ~attachments~ 中从零起算的位置。

services 复用已缓存的原件，缓存缺失时从 Slack 下载并在写入完成后返回 HTTP 200，响应为 ~{"cache_path":"<本机绝对路径>"}~ 。原件的打开和显示由 Emacs 负责。用户点击附件时，Emacs 直接显示 ~original_path~ 指向的可读文件，缓存缺失时启动异步下载。

找不到可读取的附件时返回 HTTP 404 ~slack-attachment-not-found~ ，下载或写入暂时失败时返回 HTTP 503 ~slack-data-unavailable~ 。会话校验沿用 Slack 接口的通用约定。

** 附件原件下载与进度查询

| 方法与路径 | 请求与响应 |
|------------+------------|
| ~POST /slack/conversations/{id}/messages/{ts}/attachments/{index}/original~ | 提交原件下载。路径参数与原件查询接口相同，请求体为空。任务排队或下载中时返回 HTTP 202，命中原件缓存时返回 HTTP 200，响应体均为 ~{"download_id":"<UUID>"}~ 。 |
| ~GET /slack/downloads/{download_id}~ | 查询任务。返回 HTTP 200 和当前进度，任务自身失败时通过响应中的 ~state~ 和 ~error~ 表示。 |

两个接口仅供本机调用，可带 ~X-Loki-Slack-Session~ 。任务归属提交时的工作区授权会话。该会话中重复提交同一附件且任务仍在进行时，返回已有任务 ID。缓存命中时，可用任务 ID 立即查询到完成结果。失败后可重新提交，取得新的任务 ID。

services 将下载任务记录和 ID 仅保存在当前进程的内存中，运行期间保留所有记录，包括已完成和失败的任务。services 重启后从空任务表开始。查询未知 ID 或重启前的 ID 返回 HTTP 404 ~slack-download-not-found~ 。查询已知任务时，所属授权会话已失效则返回 HTTP 409 ~slack-session-changed~ 。

| 状态查询字段 | 含义 |
|--------------+------|
| ~download_id~ | 下载任务 UUID。 |
| ~state~ | ~pending~ 表示排队， ~downloading~ 表示下载中， ~completed~ 表示原件已写入缓存， ~failed~ 表示下载失败。 |
| ~downloaded_bytes~ | 已写入的字节数。命中缓存时为原件大小。 |
| ~total_bytes~ | 已知的总字节数。下载期间未知时为 ~null~ ，完成后为原件大小。 |
| ~cache_path~ | 仅在 ~completed~ 时提供，值为原件的本机绝对路径。 |
| ~error~ | 仅在 ~failed~ 时提供，结构沿用通用错误的 ~error~ 对象。 |

services 在后台流式写入临时文件，连接或传输停滞时可超时，持续传输的大文件可超过普通 Slack HTTP 请求的超时时间。写入完成并提交缓存后，任务才进入 ~completed~ 。Emacs 按任务 ID 轮询，按字节数显示进度，总量未知时显示已下载大小。任务完成时，Emacs 打开 ~cache_path~ 指向的文件，失败时显示 ~error.message~ 。

*** 下载中断与断点续传

- 连接中断、超时或响应提前结束时，当前任务进入 ~failed~ 。services 将可续传的半成品保留为工作区缓存内的 ~.part~ 文件，并记录来源标识、强 ~ETag~ 和已知的总大小。半成品按工作区、当前授权用户和附件原件缓存键查找，同一半成品只由一个任务写入。闲置半成品按 ~cache_retention_days~ 清理。
- 用户重试时通过同一 ~POST~ 创建新任务。services 校验当前授权与下载来源后，从半成品的实际长度发起 ~Range: bytes=<offset>-~ 请求，并用 ~If-Range~ 携带保存的强 ~ETag~ 。services 重启后，新任务也可使用仍可校验的半成品。
- Slack 返回 ~206 Partial Content~ 时，services 确认资源版本与字节编码一致，并校验 ~Content-Range~ 的起止位置及总长度后再追加。下载进度计入已确认复用的字节。Slack 返回 ~200 OK~ 时，使用该完整响应从头写入。收到 ~416 Range Not Satisfiable~ 、范围校验不通过或缺少可用的强 ~ETag~ 时，清理旧半成品并重新完整下载。
- HTTP 响应正常结束后，services 校验已知的响应字节数和文件总大小，再将临时文件原子重命名为正式缓存文件。只有提交成功的原件才会通过 ~cache_path~ 交给 Emacs。

** Block Kit 消息正文

消息对象可包含 ~blocks~ 数组，按 Slack 消息中的顺序传递可渲染的正文区块。应用可以把「未处理的告警」放在顶层 ~text~ ，把告警分组、持续时间和明细放在 ~section~ 中。顶层 ~text~ 用于预览和正文回退，每个区块用 ~type~ 标记结构。

| ~type~ | 字段 | 约定 |
|--------+------+------|
| ~section~ | 可选的 ~text~ 和 ~fields~ | ~text~ 是文本对象， ~fields~ 是有序的文本对象数组。只传递至少含一项有效文本的区块。 |
| ~table~ | ~rows~ | 二维字符串数组，外层是行，内层是该行的单元格。 |
| ~rich_text_preformatted~ | ~text~ 和可选的 ~language~ | 将 ~rich_text~ 中的代码块按原顺序展开到 ~blocks~ 。 ~text~ 包含按顺序拼接的代码正文，保留缩进和换行。 ~language~ 沿用 Slack 提供的语言名。 |
| ~markdown~ | ~text~ | 保留 Slack 提供的 Markdown 正文，其中的代码围栏可以携带语言标签。 |

文本对象包含 ~type~ 和 ~text~ 两个字段。 ~type~ 为 ~mrkdwn~ 或 ~plain_text~ 。services 保留 Slack 返回的字符串，Emacs 根据文本类型解析。以下示例省略了消息标识等字段。

#+begin_src json
{
  "text": "未处理的告警",
  "blocks": [
    {
      "type": "section",
      "text": {
        "type": "mrkdwn",
        "text": "&gt;值班 <@U123>: *<https://example.com/alerts|IP绑定不通>*\n&gt;已持续0.4小时: `有3个绑定的IP无法连通`"
      }
    },
    {
      "type": "section",
      "text": {
        "type": "mrkdwn",
        "text": "&gt;值班 <@U456>: *节点记录冲突*\n&gt;已持续209.9小时: `同一节点对应多条矿机记录`"
      }
    }
  ]
}
#+end_src

services 按原顺序解析区块，逐项跳过未知类型或无效数据。已有的附件内表格按原顺序追加到正文区块末尾。协议版本维持 ~1~ ，旧客户端可继续读取 ~text~ 、 ~tables~ 与 ~attachments~ 。新客户端优先使用 ~blocks~ 中的表格，缺少可渲染区块时回退到 ~tables~ ，避免重复显示。

Emacs 按下列规则选择和显示正文。

- 有可渲染的 ~section~ 时，以区块作为正文，顶层 ~text~ 留作预览。只有表格区块时，先显示顶层 ~text~ ，再显示表格。附件接在正文之后。
- 按数组顺序显示区块以及 ~section~ 内的 ~text~ 和 ~fields~ 。 ~mrkdwn~ 支持引用、行内代码、强调、链接和 Slack 用户提及。识别行首的 Slack 引用标记 ~&gt;~ 。提及按工作区查找用户资料，缺少显示名时回退到用户 ID。 ~plain_text~ 按字面显示，Slack 字符实体在显示时解码一次。

历史分页、线程消息、订阅快照和实时更新使用同一消息定义。services 将新增区块随消息写入磁盘缓存。旧缓存缺少 ~blocks~ 时仍可显示已有的正文和表格。按现有刷新或翻页流程从 Slack 重新取得消息后，以新解析的数据更新同一条缓存记录。Emacs 从响应或订阅收到的区块以该次投递为准。

* 会话消息订阅

每个 Slack 聊天 buffer 创建时生成一个 UUID，并在登记本地 buffer 映射后创建订阅。订阅随 buffer 存活，窗口隐藏或切换时继续接收消息。关闭 buffer 时先移除本地映射，再取消订阅。同一会话重新打开时生成新 UUID。

** 本机 HTTP 接口

| 方法与路径 | 约定 |
|------------+------|
| ~PUT /slack/conversations/{id}/subscriptions/{subscription_id}~ | 空请求体，必填 ~X-Loki-Slack-Session~ 。新建返回 HTTP 201，使用相同会话、会话代次和 UUID 重试返回 HTTP 200。两者均返回 ~api_version~ 、 ~subscription_id~ 、 ~conversation_id~ 、 ~session_id~ 。 |
| ~DELETE /slack/conversations/{id}/subscriptions/{subscription_id}~ | 空请求体，按复合会话 ID 与 UUID 取消。重复取消或订阅已失效时均返回 HTTP 204。即使工作区断开也可清理。 |

接口沿用 Slack 模块的本机访问范围、响应版本与通用 JSON 错误。创建时校验 UUID、会话和当前授权。缺失或无效的请求参数返回 ~400 invalid-request~ ，未知工作区或会话返回对应的 ~404~ ，过期的 ~session_id~ 返回 ~409 slack-session-changed~ 。同一订阅的重试沿用已有投递进度。

** Emacs 消息分发

services 通过现有 Emacs gateway 调用 ~loki-assistant-dispatch~ 的固定入口 ~(loki-assistant-dispatch-slack-messages payload-file)~ ，由 Emacs 按订阅定位目标 buffer。参数是 services 创建的本机临时文件路径，文件内容为 UTF-8 JSON。文件仅对当前用户可读写，调用结束后清理。后台投递仅连接现有 Emacs server。HTTP 调用方只提供会话和订阅标识，函数及目标 server 由 services 决定。

每次投递包含 ~api_version~ 、 ~subscription_id~ 、 ~conversation_id~ 、 ~session_id~ 、 ~sequence~ 和 ~kind~ 。每个订阅的 ~sequence~ 从 1 开始递增，同一批次重试沿用原序号和数据。

- ~kind=snapshot~ 时， ~snapshot~ 携带会话顶层消息的第一页，字段及格式沿用 ~GET /slack/conversations/{id}/messages~ 响应。 ~thread_items~ 携带 services 已缓存的线程回复，每条回复带根消息的 ~thread_ts~ 。services 在快照送达后补拉首屏线程，缓存的新增、编辑和删除继续通过同一订阅投递。
- ~kind=changes~ 时， ~items~ 和 ~deleted_ts~ 分别携带顶层消息的新增或更新、删除时间戳。 ~thread_items~ 携带新增或更新的完整线程回复， ~deleted_thread_messages~ 携带删除记录，每条包含 ~thread_ts~ 和 ~ts~ 。四个字段均为数组，任一数组可以为空。同一回复编辑后沿用原有 ~ts~ ，无需等待根消息的回复数变化。
- ~kind=probe~ 用于确认 buffer 仍存活。它使用下一条消息的 ~sequence~ ，只核对订阅，收到回执后消息序号保持原值。

#+begin_src json
{
  "api_version": "1",
  "subscription_id": "715348a3-2d42-4a03-95c8-cd127edce5e5",
  "conversation_id": "T123.C456",
  "session_id": "2c4df94e-af61-4bcf-87b5-e2143f8937a3",
  "sequence": 2,
  "kind": "changes",
  "items": [],
  "deleted_ts": [],
  "thread_items": [],
  "deleted_thread_messages": [
    {"thread_ts": "1795073990.000001", "ts": "1795074000.000001"}
  ]
}
#+end_src

Emacs 按订阅 UUID 查找仍存活的主聊天 buffer，并核对会话和会话代次。分发函数一次合并每批回复，再更新主聊天及打开的独立线程 buffer，保留当前草稿。打开线程直接显示共享数据。分发函数应用消息或确认探测后返回 Lisp 符号 ~applied~ ，已应用的同序号重试也返回 ~applied~ 。找不到匹配的 buffer 时返回 ~buffer-closed~ ，services 据此删除对应订阅。

** 投递时序与恢复

- 登记订阅时开始跟踪该会话的缓存变更。生成第一页时取得一致的缓存快照和变更位置，先投递快照，再投递该位置之后的变更。首次回调可能先于 ~PUT~ 响应到达。
- Slack 实时事件、重连补拉与本机发送结果都通过缓存更新进入投递队列。仅投递实际提交到缓存的变化。同一订阅按顺序投递，每次等待上一批回执后再投递下一批。等待 Emacs 时释放消息缓存锁。
- 待投递的变更按消息时间戳合并。同一消息只保留最终状态。积压超限时重新取得快照，待当前批次确认后发送新快照。buffer 收到后以新快照重建时间线并重置翻页游标。
- 主动取消立即停止后续投递。关闭时若创建请求仍在进行，Emacs 在创建成功后补发取消请求。取消请求未能送达时，已发出或后续的消息回调通过 ~buffer-closed~ 清理旧订阅。
- services 在订阅空闲 60 秒后探测；Emacs 异常退出时，下一次投递或探测无法连接原 server，services 删除该订阅。所有后台调用禁用 Emacs 自动启动。回调函数缺失视同 ~buffer-closed~ 。求值超时、Lisp 错误和未知回执按退避重试。
- 订阅保存在 services 内存中，services 重启或工作区会话失效时清理。Slack 实时连接在同一会话下重连时，订阅继续接收补拉结果。日常收取消息由 services 推送驱动。

** 聊天 buffer 刷新

在已有聊天 buffer 中执行 ~C-c C-r~ 时，Emacs 刷新最近一页并重新登记消息订阅。services 重启且工作区授权恢复后，一次刷新即可在原 buffer 中恢复推送。

1. Emacs 调用 ~GET /status/slack/connections~ ，按当前聊天的 ~team_id~ 取得最新的 ~session_id~ 和 ~user_id~ 。
2. Emacs 为本次刷新生成新的订阅 UUID，先登记本地映射，再携带当前 ~session_id~ 调用订阅 ~PUT~ 。若返回 ~slack-session-changed~ ，刷新流程重新读取状态并重试一次。刷新进行期间重复按键合并为同一次操作。
3. services 按消息读取规则准备最近一页，优先从 Slack 获取，暂时无法获取时使用可读缓存。Emacs 收到新订阅的首次快照后，重建时间线和翻页游标，保留草稿，并更新 buffer 的 ~session_id~ 、 ~user_id~ 和订阅 UUID。随后移除旧订阅的本地映射并发送 ~DELETE~ 。迟到的旧投递收到 ~buffer-closed~ ，刷新前发出的分页请求也不能覆盖新时间线。

刷新失败时，Emacs 保留当前时间线与草稿，提示失败原因并清理本次新建的订阅。等待快照期间关闭 buffer 时，按关闭流程取消关联的全部订阅。

* 主题聊天关注队列
:PROPERTIES:
:CUSTOM_ID: conversation-watches
:END:

services 在本机持久化一份全局关注队列。配置项 ~slack/watches~ 是只读的 ~SlackWatch~ 数组，每条记录包含复合会话 ID ~id~ 和显示名称 ~display_name~ ，由 Slack 模块通过关注接口更新。主题聊天对应 Slack 的公开或私有频道（ ~public_channel~ 、 ~private_channel~ ）。关注范围包含主题聊天的顶层消息和该聊天中所有线索的回复。关闭聊天窗口、退出 Emacs 或重启 services 后仍保留关注。 [[file:slack-emacs.org::#conversation-watches][Emacs 主题聊天关注操作]]

** 本机 HTTP 接口

| 方法与路径 | 请求与响应 |
|------------+------------|
| ~GET /slack/watches~ | 无查询参数。HTTP 200 返回 ~api_version~ 和 ~items~ ，按 ~conversation_id~ 排序，每项包含一个已关注的 ~conversation_id~ 。空队列返回 ~items: []~ 。 |
| ~GET /slack/conversations/{id}/watch~ | HTTP 200 返回 ~api_version~ 、 ~conversation_id~ 和布尔字段 ~watching~ 。 |
| ~PUT /slack/conversations/{id}/watch~ | 以 ~{"watching":true}~ 开启关注，以 ~{"watching":false}~ 关闭。落盘后返回 HTTP 200 和与单条查询相同的结构。重复提交同一状态返回当前状态。 |

#+begin_src json
{
  "api_version": "1",
  "conversation_id": "T123.C456",
  "watching": true
}
#+end_src

接口仅限本机，响应设置 ~Cache-Control: no-store~ 。开启前根据会话目录核对会话类型，私聊和群组私聊返回 ~422 slack-watch-unsupported-conversation~ ，找不到会话返回 ~404 slack-conversation-not-found~ 。查询及关闭直接读取或修改本机队列，工作区断开或配置移除时仍可操作。参数格式错误返回 ~400 invalid-request~ ，关注存储失败返回 ~503 slack-watch-storage-error~ 。错误使用通用 JSON 响应。

** 消息识别和通知

- 当前的「提及和私信」规则继续适用。主题聊天开启关注后，services 将该主题下普通的未读新消息也纳入现有通知流程，沿用本人消息过滤。线索中的新回复按所属会话匹配关注，无论根消息何时发送、线索是否展开或进入过缓存。
- Slack 实时消息归一化后，以复合会话 ID 匹配关注。~thread_ts~ 存在时用作线索根标识。编辑、删除和反应不触发关注通知。首次开启从落盘时开始生效，历史翻页和 buffer 快照只更新缓存。
- 同一条新消息同时命中关注和直接提及时，只进入一次系统通知队列。按复合会话 ID 和消息 ~ts~ 去重，线索广播使用原回复的消息标识。关闭关注后，尚未转交的消息只按原有通知规则判断。
- 通知使用共享 ~NotificationService~ 。回调复用 ~POST /slack/conversations/{id}/open~ ，以 ~message_ts~ 定位消息，线索回复同时携带 ~thread_ts~ 。回复不可用时定位到根消息，根消息不可用时打开对应会话。 [[*正文摘要][通知正文]] · [[*通知点击跳转][通知点击协议]] · [[file:control-center-services.org::*系统通知模块][系统通知模块]]

** 验收场景

- 开启关注后，普通顶层消息和从未打开过的线索中的普通回复都能发出通知。关闭 Emacs 后仍可发送通知。
- 同一条线索回复既广播到主聊天又直接提及本人时，只显示一次通知。点击后定位到原线索回复。
- 关闭关注后，普通消息恢复为静默，直接提及仍会通知。重启 services 后标题可恢复已保存的关注状态。

* 消息发送与发送记录

~POST /slack/conversations/{id}/messages~ 发送顶层消息。 ~POST /slack/conversations/{id}/threads/{thread_ts}/messages~ 发送线程回复。两个接口均要求 UUID 格式的 ~Idempotency-Key~ ，JSON 请求体包含 ~text~ 。

请求排队时返回 HTTP 202，已有最终结果时返回 HTTP 200。 ~Location~ 指向 ~GET /slack/send-requests/{request_id}?team_id={team_id}~ 。同一会话内重复提交同一标识和内容时返回已有记录，提交不同内容时返回 HTTP 409。

~GET /slack/send-requests/{request_id}~ 要求查询参数 ~team_id~ 。 ~state~ 为 ~pending~ 、 ~sent~ 、 ~failed~ 或 ~unknown~ 。成功发送时 ~result.ts~ 为 Slack 消息时间戳。

发送线程回复时，services 核对 Slack 回执中的线程根时间戳。回执缺少线程信息时，services 在原线程核对消息。若 Slack 返回的消息属于其他位置，则发送记录返回 ~unknown~ 和 ~slack-delivery-target-mismatch~ 。

* 已读位置

~PUT /slack/conversations/{id}/read-position~ 推进会话顶层已读位置。 ~PUT /slack/conversations/{id}/threads/{thread_ts}/read-position~ 推进线程已读位置。两个接口的 JSON 请求体均包含 ~through_ts~ 。响应包含 ~conversation_id~ 、 ~team_id~ 、 ~thread_ts~ 、 ~read_through_ts~ 和 ~unread_count~ 。

* Slack 新消息通知

** 正文摘要

Slack 模块在消息命中现有通知规则后，使用归一化的 ~Message~ 生成纯文本摘要。通知标题为「Slack 新消息」，有发送人时在正文开头加上「发送人 · 」。发送人和提及优先使用事件或当前工作区缓存中的显示名，缺少资料时回退到 Slack ID。摘要与点击回调一同写入内存通知队列，投递和重试直接把摘要用作 ~NotificationRequest.body~ 。 [[file:control-center-services.org::*系统通知模块][通用通知接口]]

按 ~blocks~ 的顺序生成摘要。只要 ~section~ 或 ~markdown~ 能转换出正文，就使用区块内容。只有表格、代码块，或没有可用区块时，先取非空的顶层 ~text~ ，再追加已转换的区块。相邻区块用换行分隔。

| 区块 | 通知正文中的表示 |
|------+------------------|
| ~section~ | 先取 ~text~ ，再按顺序展开 ~fields~ ，每项占一行。 ~plain_text~ 按字面显示， ~mrkdwn~ 按下文规则转换。 |
| ~markdown~ | 保留标题、列表和段落中的文本。链接取可见标签，代码围栏内保留内容，省略围栏和语言标签。 |
| ~rich_text_preformatted~ | 展示首个非空代码行，省略后续非空行时加上「…」。 |
| ~table~ | 展示前两条非空行，每行最多取前三个单元格，以「 · 」分隔单元格。省略列或行时加上「…」。缺少可显示的表格区块时，同样处理旧字段 ~tables~ 。 |

顶层 ~text~ 和 ~mrkdwn~ 文本将 Slack 链接转成标签，无标签的网页链接显示域名。用户提及显示为「@显示名」，频道引用使用 Slack 提供的标签或频道 ID。省略成对的强调标记、行内代码定界符和行首引用标记，代码按字面显示。Slack 字符实体在输出文本中解码一次。未知或空区块逐项略过。

正文和区块都无可显示内容时，取首个附件的标题。旧消息可回退到 ~attachment~ ，再回退到「点击查看消息」。去掉首尾空白，合并多余空行，整条正文最多 240 个 Unicode 码点（含发送人前缀和省略号）。在完整字符簇边界截断，末尾加「…」。横幅能显示的行数由 macOS 决定，点击后在 Emacs 查看完整正文、表格和附件。

上文 Block Kit 示例中的第一段正文可转换成以下文本，其中 ~U123~ 已有显示名「小林」。

#+begin_example
值班 @小林: IP绑定不通
已持续0.4小时: 有3个绑定的IP无法连通
#+end_example

验收覆盖顶层 ~text~ 与区块正文重复、只有 ~blocks~ 、只有表格或代码块、旧 ~tables~ 、只有附件、提及资料缺失、带 emoji 的长消息，以及线程回复点击定位。另检查同一条消息的重试沿用入队时生成的正文。

** 通知点击跳转

~POST /slack/conversations/{id}/open~ 打开或聚焦通知对应的 Emacs Slack 会话，请求体为空。可选查询参数 ~thread_ts~ 展开指定线程， ~message_ts~ 定位目标消息。两者同时提供时，目标消息是指定线程中的回复。

Emacs gateway 使用 ~loki-assistant-dispatch-slack-notification~ 转发通知目标。菜单栏「Slack 聊天」调用本机接口 ~POST /emacs/slack/activate~ ，请求体为空，由 ~loki-assistant-dispatch-activate-slack~ 激活最近使用的聊天或打开选择器。成功响应为 ~{"api_version":"1","app":"slack","opened":true}~ 。

成功返回 HTTP 200，包含 ~api_version~ 、 ~conversation_id~ 和 ~target~ 。 ~target~ 为 ~conversation~ 、 ~thread~ 或 ~message~ ，表示实际定位到的层级。消息不可用时回退到线程或会话，失败沿用通用 JSON 错误。 [[file:control-center-services.org::*平台转交与点击跳转][通用通知回调]]

* 数据准备

services 启动并恢复工作区授权后，在后台预热用户目录、会话目录和最近一页消息。参照 emacs-slack，缺失的私聊用户资料按需补查，用户变更与加入事件更新内存中的用户目录。查看更早消息和线程时按需分页。

重启后，services 用 ~pass~ 中的配置凭据重新授权并建立会话。会话列表同时返回所属工作区、私聊参与者、最后一条消息摘要和最近未读提及时间。未读状态根据 Loki 已获取的消息与本机已读位置计算。Emacs 选择界面的需求见 [[file:slack-emacs.org][Emacs 中的 Slack 操作界面]]。
