#+TITLE: 控制中心服务层

* 作用与状态

本目录是控制中心的 Rust 服务层。它计划作为开机常驻的本机服务，为菜单栏应用和未来的其他客户端提供统一的 loopback HTTP 接口。

当前已完成核心服务器骨架、服务发现模块、配置模块、系统通知模块、Emacs 模块和 macOS LaunchAgent 管理器：服务默认监听 ~127.0.0.1:47321~，提供健康检查、模块发现和配置模型/数据接口，支持配置地址和 Ctrl-C 优雅退出。用户配置保存于 ~~/.assistant/config.yml~，业务模块通过 ~ConfigService~ 读取生效值及来源并订阅变化。Emacs 模块支持 Lisp 求值、buffer 列表、主动状态上报和通知分发。LaunchAgent 管理器支持生成 plist、安装、卸载、启动、停止、重启和状态查询；菜单栏应用提供 services 状态监控和启动入口，托盘登录启动由 Emacs 配置界面管理。

服务成功启动后会写入 ~~/.assistant/service~ JSON pfile，包含 ~host~、~port~、~pid~ 和 ~version~ 。服务正常退出时删除自身文件；客户端应先读取该文件，再请求对应端口的健康接口。

服务运行期间持有 ~~/.assistant/service.lock~ 独占文件锁，防止多个实例覆盖服务发现信息。锁文件保留，进程退出后锁由操作系统释放；判断存活应检查持锁状态，再读取 pfile 并请求健康接口。

模块边界、目录职责和跨模块协议见 [[file:../docs/control-center-services.org][控制中心 services 模块规划]]。

业务模块各自维护交互协议和 HTTP 路由：在 ~src/modules/<module>/~ 内放置 ~protocol.rs~、~routes.rs~ 及需要的 ~service.rs~，handler 使用 ~#[loki_api(...)]~ 声明接口信息，并用 ~linkme~ 静态切片提交模块描述。~http~ 只提供 loopback server 和公共 HTTP 能力，不设集中式 ~protocol~ 目录。~Services::build~ 只组合路由，不负责运行时注册元数据。新增模块应尽量只新增一个目录，跨模块只共享稳定的基础设施。

* 开发

需要 Rust stable 与 Cargo：

#+begin_src sh
cargo fmt --manifest-path services/Cargo.toml
cargo test --workspace --manifest-path services/Cargo.toml
cargo run --manifest-path services/Cargo.toml
make install-service
make uninstall-service
#+end_src

可使用环境变量覆盖监听地址，例如：

#+begin_src sh
LOKI_ASSISTANT_HTTP_ADDR=127.0.0.1:47322 cargo run --manifest-path services/Cargo.toml
#+end_src

服务启动后可检查：

#+begin_src sh
curl http://127.0.0.1:47321/healthz
curl http://127.0.0.1:47321/discover
curl http://127.0.0.1:47321/discover/modules
curl http://127.0.0.1:47321/discover/modules/discover
curl http://127.0.0.1:47321/meta
curl http://127.0.0.1:47321/meta/config
curl http://127.0.0.1:47321/data/config
#+end_src

服务只监听 loopback，不提供跨设备访问。新增业务接口前，先在规划文档中确认模块职责和协议归属。

* 配置存储

services 启动时加载 ~~/.assistant/config.yml~ ，首次成功保存时按需创建文件。文件只保存用户设置，按模块和配置项组织，例如：

#+begin_src yaml
emacs:
  emacsclient_path: /opt/homebrew/bin/emacsclient
control-center:
  center_auto_start: false
#+end_src

通过配置接口保存后，services 原子替换 YAML 文件，成功后更新内存并发出变化通知；写入失败不会更新生效值。文件权限为 ~0600~ 。直接手工修改文件后需重启 services。配置文件无法读取、YAML 无效或已知配置值校验失败时，服务启动会报错。

读取接口返回 ~{value, source}~，其中 ~source~ 为 ~user~ 或 ~default~ 。没有用户设置时使用静态默认值或按元数据搜索得到的程序路径；这些默认值不写入文件。完整协议见 [[file:../docs/control-center-services.org::*配置中心][配置中心协议]]。

~POST /config/validate~ 可提前校验配置而不保存。保存接口也执行相同检查；~Executable~ 必须指向存在、可执行的普通文件，输入程序名时按 ~PATH~ 和元数据建议目录解析并保存为绝对路径。无效输入返回错误，原有值及 YAML 文件不变。

* Emacs

Emacs 的 Rust 配置入口为 ~modules/emacs/config.rs~ 中的 ~EmacsConfig~ ，构造时注入 ~Arc<ConfigService>~ 。每个配置项有独立读取方法；~emacsclient_path()~ 和 ~socket_name()~ 在每次使用时读取生效值及来源，不缓存连接配置。配置元数据通过静态方法和 ~#[loki_config]~ 注册，与 API 元数据使用相同的编译期发现方式。

~emacsclient_path~ 的类型为 ~Executable~，默认程序名为 ~emacsclient~。配置模块先按 services 进程的 ~PATH~ 搜索，再检查模块声明的 Homebrew 和 Emacs App 目录；找到的绝对路径作为默认值返回。也可在 Emacs 配置界面中使用“选择文件…”按钮，或通过接口指定路径：

#+begin_src sh
curl -X PUT http://127.0.0.1:47321/data/emacs/emacsclient_path \
  -H 'Content-Type: application/json' \
  -d '"/opt/homebrew/bin/emacsclient"'

curl -X POST http://127.0.0.1:47321/emacs/eval \
  -H 'Content-Type: application/json' \
  -d '{"script":"(+ 1 2)"}'

curl http://127.0.0.1:47321/emacs/buffers

curl -X POST 'http://127.0.0.1:47321/emacs/apps/open?app=config'

curl -X POST http://127.0.0.1:47321/emacs/receiver/notification \
  -H 'Content-Type: application/json' \
  -d '{"title":"任务完成","app":"emacs","buffer":"*scratch*"}'
#+end_src

配置修改从下次调用开始生效，并保存到 ~~/.assistant/config.yml~ 。不展开路径中的 ~ 和环境变量。~socket_name~ 默认为 ~server~ ，可在 Emacs 配置界面中改为目标 Emacs 的 socket 名称或绝对路径。gateway 显式传入该 socket，不依赖 ~EMACS_SOCKET_NAME~ 或 ~EMACS_SERVER_FILE~ ，也不在连接失败后回退到 TCP server 或其他实例。

Lisp 求值和 buffer 列表查询在 server 不可用时，仍通过 ~emacsclient --alternate-editor=~ 自动启动目标 Emacs daemon；已运行但未启用 server 的 Emacs 不会自动接管连接。启动 Emacs 所需的程序和用户配置须在 services 运行环境中可用。services 以用户级 LaunchAgent 的用户身份运行。

控制中心“设置”调用 ~POST /emacs/apps/open?app=config~ ，由 Emacs 模块负责应用加载和窗口聚焦，客户端无需传入 Lisp。未知应用或目标 Emacs 未安装对应应用时返回 HTTP 404 ~app-not-found~ 和中文 ~message~ ，控制中心在界面显示该说明。完整约定见 [[file:../docs/control-center-services.org::*打开 Emacs 应用][打开 Emacs 应用]]。

通知上报接口为 ~POST /emacs/receiver/notification~ 。Emacs 模块调用创建时注入的系统通知模块，转交菜单栏应用展示 macOS 通知。~buffer~ 可省略，点击时由 services 显示 Emacs；提供时定位对应的存活 buffer。~app~ 省略或为 ~null~ 时由 Emacs 模块补为 ~emacs~ ，center 按应用标识读取随程序打包的图标，不接受自定义图标。传入 ~module_id~ 可将上报交给已注册的 Rust 模块处理器；默认值为 ~emacs~ 。

使用前先执行 ~make restart-center~ 加载新版菜单栏应用并注册通知 URL scheme。首次上报时，macOS 会请求 Loki Assistant 的通知权限；未授权时需在系统设置中允许通知。HTTP 返回 ~status: "forwarded"~ 只表示已交给菜单栏应用，不表示系统已经展示。

默认系统通知响应的 ~result.notification_id~ 可用于 ~GET /notification/{id}~ 查询处理结果。菜单栏应用通过 ~POST /notification/{id}/receipt~ 回报 ~submitted~ 或带 ~code~、~message~ 的 ~failed~ 。~submitted~ 表示已成功提交给系统通知中心，不代表用户已看到通知。30 秒内没有回执为 ~unconfirmed~ ，过期前仍接受迟到回执；记录保留 15 分钟，services 重启后失效。重复回执幂等，应用仅重试回执，不重发通知。自定义模块处理器的返回值保持原有约定。

使用回执能力需同时加载新版 services 和菜单栏应用；操作入口见下方服务管理以及 [[file:../apps/center/README.org][菜单栏应用说明]]。

完整请求、响应、错误码和 Rust 处理器接入方式见 [[file:../docs/control-center-services.org::*Emacs 模块][Emacs 模块协议]]。

* 系统通知代码接口

~services.notification~ 直接持有 ~Arc<NotificationService>~ ，通过 ~services.notification.send(NotificationRequest)~ 发送标题、正文、应用标识与本机服务回调路径。业务模块保存创建时注入的共享引用并调用其实例方法。通知模块负责 URL scheme 转交、App 内跳转封装和提交回执；具体跳转操作由 services 中的业务模块执行。Emacs 模块的创建方式为 ~emacs::Module::new(config.service(), Arc::clone(&notification))~ 。通用接口、应用图标命名规则及跳转协议见 [[file:../docs/control-center-services.org::*系统通知模块][系统通知模块协议]]。

原 Emacs 状态和回执 URL 保留为兼容入口，与通用接口共享同一份记录。~POST /emacs/activate~ 可显示 Emacs，或通过 ~buffer~ 查询参数按名称激活第一个匹配的 buffer。指定 buffer 时仅连接目标 socket 的已有 server，优先聚焦已经显示该 buffer 的 GUI 窗口，并恢复最小化或隐藏的窗口；没有 GUI frame 时创建窗口。中文、引号、反斜杠和换行保持完整。目标已关闭时返回 ~buffer-not-found~ ，不创建同名空 buffer；连接失败返回 ~emacs-unavailable~ ，点击旧通知也不会启动新 daemon。点击失败时菜单栏应用显示具体原因。

* macOS 服务管理

LaunchAgent label 为 ~cc.loki-assistant.services~ ；修改 label 后需要先取消旧服务注册，再重新执行 ~make install-service~ 。

~make install-service~ 会使用当前 Debug 可执行文件注册用户级 LaunchAgent，并将日志写入 ~~/Library/Logs/LokiAssistant/~ ；~make uninstall-service~ 可取消注册。安装和卸载会调用系统的 ~launchctl~ ，需要用户显式执行。

已注册服务可以使用 ~make start-service~、~make stop-service~、~make restart-service~ 和 ~make service-status~ 管理。停止操作会卸载当前用户 domain 中的 LaunchAgent，但保留 plist，之后可以再次启动。

修改 services 源码后，执行以下命令刷新正在运行的服务：

#+begin_src sh
make restart-service
make service-status
#+end_src

~make restart-service~ 会先由 Cargo 编译当前 Debug binary，再让 launchd 重启同一路径的可执行文件。修改服务 label、可执行文件路径或 LaunchAgent 配置时，需要重新执行 ~make install-service~ 。
