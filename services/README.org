#+TITLE: 控制中心服务层

* 作用与状态

本目录是控制中心的 Rust 服务层。它计划作为开机常驻的本机服务，为菜单栏应用和未来的其他客户端提供统一的 loopback HTTP 接口。

当前已完成核心服务器骨架、服务发现模块、配置模块、控制中心模块、状态中心、系统通知模块、Emacs 模块和 macOS LaunchAgent 管理器：服务默认监听 ~127.0.0.1:47321~，提供健康检查、模块发现和配置模型/数据接口，支持配置地址和 Ctrl-C 优雅退出。用户配置保存于 ~~/.assistant/config.yml~，业务模块通过 ~ConfigService~ 读取生效值及来源并订阅变化。Emacs 模块支持 Lisp 求值、buffer 列表、主动状态上报和通知分发。services 自身由 Homebrew services 管理，菜单栏应用只展示服务状态，提供设置、日志与业务入口；托盘登录启动仍由 services 的控制中心模块在配置提交时管理用户级 LaunchAgent。

服务成功启动后会写入 ~~/.assistant/service~ JSON pfile，包含 ~host~、~port~、~pid~ 和 ~version~ 。服务正常退出时删除自身文件；客户端应先读取该文件，再请求对应端口的健康接口。

服务运行期间持有 ~~/.assistant/service.lock~ 独占文件锁，防止多个实例覆盖服务发现信息。锁文件保留，进程退出后锁由操作系统释放；判断存活应检查持锁状态，再读取 pfile 并请求健康接口。

模块边界、目录职责和跨模块协议见 [[file:../docs/control-center-services.org][控制中心 services 模块规划]]。

业务模块各自维护交互协议和 HTTP 路由：在 ~src/modules/<module>/~ 内放置 ~protocol.rs~、~routes.rs~ 及需要的 ~service.rs~，handler 使用 ~#[loki_api(...)]~ 声明接口信息，并用 ~linkme~ 静态切片提交模块描述。~http~ 只提供 loopback server 和公共 HTTP 能力，不设集中式 ~protocol~ 目录。~Services::build~ 组装模块、注入配置处理器并组合路由，元数据仍在编译期注册。新增模块应尽量只新增一个目录，跨模块只共享稳定的基础设施。

* 开发

需要 Rust stable 与 Cargo：

#+begin_src sh
cargo fmt --manifest-path services/Cargo.toml
cargo test --workspace --manifest-path services/Cargo.toml
cargo run --manifest-path services/Cargo.toml
make install-service
make uninstall-service
#+end_src

可使用环境变量覆盖监听地址，例如：

#+begin_src sh
LOKI_ASSISTANT_HTTP_ADDR=127.0.0.1:47322 cargo run --manifest-path services/Cargo.toml
#+end_src

服务启动后可检查：

#+begin_src sh
curl http://127.0.0.1:47321/healthz
curl http://127.0.0.1:47321/discover
curl http://127.0.0.1:47321/discover/modules
curl http://127.0.0.1:47321/discover/modules/discover
curl http://127.0.0.1:47321/meta
curl http://127.0.0.1:47321/meta/config
curl http://127.0.0.1:47321/data/config
#+end_src

服务只监听 loopback，不提供跨设备访问。新增业务接口前，先在规划文档中确认模块职责和协议归属。

* 云端中继安装与管理

~services/relay/~ 维护独立中继的镜像与安装脚本。根目录 ~make relay-image~ 校验 iroh-relay 1.4.1 上游 Linux AMD64 musl 发布包的固定 SHA256，构建 ~loki/iroh-relay:1.4.1~ 。运行包使用上游发布的可执行文件，不在小内存 ECS 上编译 Rust；上游源码见 [[https://github.com/n0-computer/iroh/tree/v1.4.1/iroh-relay][iroh-relay 1.4.1]]。

服务器安装目录需要镜像压缩包 ~iroh-relay-image.tar.gz~、仅管理员可读的 ~relay.env~、~install.sh~ 和 ~enable-ip-https.sh~。镜像通过 ~docker image save~ 导出并 gzip 压缩；环境文件包含随机生成的 ~IROH_RELAY_ACCESS_TOKEN~ 。在该目录安装容器与 IP HTTPS：

#+begin_src sh
sudo sh install.sh
sudo sh enable-ip-https.sh 8.153.207.23 8443
#+end_src

安装复用已有 Docker 和 Caddy。中继容器为 ~loki-iroh-relay~ ，后端只映射 ~127.0.0.1:3340~ ；公网入口为 ~https://8.153.207.23:8443~。Certbot 在独立 venv 中申请并续期公网 IP 证书，无需 DNS；HTTP-01 验证要求公网 TCP 80 可达，中继要求安全组放行 TCP 8443。最终设计及维护位置见 [[file:../docs/relay-deployment.org][中继部署设计]]。

Docker 服务开机启动，容器使用 ~unless-stopped~ 。证书由云端 systemd 定时器每日检查两次，临近到期时自动续签，并更新证书、校验配置和平滑重载 Caddy。常用管理命令：

#+begin_src sh
sudo docker ps --filter name=loki-iroh-relay
sudo docker logs --tail 50 loki-iroh-relay
sudo docker restart loki-iroh-relay
sudo docker stop loki-iroh-relay
sudo docker start loki-iroh-relay
sudo systemctl status loki-relay-cert-renew.timer
sudo systemctl list-timers loki-relay-cert-renew.timer
sudo journalctl -u loki-relay-cert-renew.service
#+end_src

客户端在“网络”配置中设置 ~relay_url~ 和 ~relay_token~ ，地址和令牌均通过自己的配置中心保存；不需要额外的服务环境文件。令牌使用中转服务器已有的共享令牌，两项均非空时才注册。TLS 证书验证始终启用。

* 配置存储

services 启动时加载 ~~/.assistant/config.yml~ ，首次成功保存时按需创建文件。文件只保存用户设置，按模块和配置项组织，例如：

#+begin_src yaml
emacs:
  emacsclient_path: /opt/homebrew/bin/emacsclient
control-center:
  center_auto_start: false
#+end_src

通过配置接口保存时，services 先等待所属模块的配置变化处理器成功，再原子替换 YAML 文件，成功后更新内存并发出变化通知；处理或写入失败不会更新生效值。处理器失败返回 ~config-change-rejected~ 和具体原因；处理成功但落盘失败时调用处理器撤销外部操作。文件权限为 ~0600~ 。直接手工修改文件后需重启 services。配置文件无法读取、YAML 无效或已知配置值校验失败时，服务启动会报错。

读取接口返回 ~{value, source}~，其中 ~source~ 为 ~user~ 或 ~default~ 。没有用户设置时使用静态默认值或按元数据搜索得到的程序路径；这些默认值不写入文件。完整协议见 [[file:../docs/control-center-services.org::*配置中心][配置中心协议]]。

~POST /config/validate~ 可提前校验配置而不保存。保存接口也执行相同检查；~Executable~ 必须指向存在、可执行的普通文件，输入程序名时按 ~PATH~ 和元数据建议目录解析并保存为绝对路径。无效输入返回错误，原有值及 YAML 文件不变。

* 控制中心配置

“控制中心”的 ~center_auto_start~ 保持默认 ~false~ 。在 Emacs 配置界面开启“登录时自动启动”，或通过 ~PUT /data/control-center/center_auto_start~ 提交 JSON ~true~ 时，控制中心模块先同步 ~cc.loki-assistant.center~ 用户级 LaunchAgent；系统操作成功后才保存配置。关闭时卸载任务并删除 plist；失败返回系统错误，界面保留输入，可修复后重新保存。模块构造和服务启动不会自动修改 LaunchAgent。

默认使用仓库的 Debug 菜单栏可执行文件；使用其他构建位置时，在 services 启动环境设置 ~LOKI_ASSISTANT_CENTER_EXECUTABLE~ 为绝对路径。详细操作和处理器接口见 [[file:../docs/control-center-services.org::*控制中心模块][控制中心模块]] 与 [[file:../docs/control-center-services.org::*提交前变化处理][提交前变化处理]]。

* 网络身份与中转注册

“网络”分组提供“中转地址” ~relay_url~ 和“中转令牌” ~relay_token~ ，均默认为空，通过 Emacs 设置程序或通用配置接口保存到 ~~/.assistant/config.yml~ 。地址和令牌都非空时才注册；只设置一项视为未配置，可以任意顺序先后保存。填写令牌时使用服务器已有的共享访问令牌。

服务启动或提交上述配置时，缺少 ~~/.assistant/identity.json~ 则自动生成随机身份，以 ~0600~ 权限保存并通知。身份与中转令牌相互独立，重启或更改配置会复用本地身份，损坏的身份不会自动覆盖。

完整配置变化时先注册新连接，成功且落盘后才替换旧连接并通知成功；注册失败或超时会通知并拒绝保存，保留原配置和连接。清空任意一项成功后关闭连接；首次只保存一项不连接、不发出注册失败通知。启动时配置完整才注册，失败不影响本机 HTTP 服务；可修复后重新提交。每次注册最多等待 10 秒。

本机网络状态读取 ~GET /status/network/my~ ，其 ~value.status~ 为 ~disconnected~ 、 ~connecting~ 、 ~connected~ 或 ~failed~ 。查询不会等待注册过程；连接断开、恢复时由网络模块继续发布更新。状态与通知不包含令牌或私钥。当前只完成本地身份和中转连接，不自动连接固定设备或接收业务消息。

* 状态发布与查询

~status~ 模块提供统一的内存状态存取。~Services~ 持有共享 ~Arc<StatusService>~ ，业务模块在构造时接收并保存到 ~status~ 字段，通过 ~self.status.publish(module_id, key, value)~ 或 ~self.status.publish_many(values)~ 设置数据。状态 HTTP 路由仅提供 GET 查询，不提供通用写入接口。Emacs 程序通过所属模块的 ~POST /emacs/receiver/status~ 上报，再由 ~EmacsService~ 调用共享 ~publish_many_validated~ Rust 接口，按 ~GET /stats/meta~ 声明严格校验后发布。类型、必填、可空、枚举或嵌套元素不符，以及未声明的状态项或对象字段，均返回 HTTP 400 与字段路径；整批失败时不更新原值和时间戳。状态中心不读取业务配置、不自行抓取值。

~GET /stats/meta~ 获取完整状态结构目录：包含模块和状态项名称、说明、嵌套 object 字段、array 元素类型、必填和可空标记，以及网络状态的枚举值。结构由各业务模块的 ~status.rs~ 使用 ~#[loki_status]~ 在编译期注册，当前包括 ~emacs/buffers~ 、 ~emacs/runtime~ 和 ~network/my~ ；尚未发布数据也可查看结构。元数据只描述结构，运行时值仍通过数据查询接口读取。

~GET /status~ 读取全部状态，~GET /status/emacs/buffers~ 读取 Emacs 发布的关注 buffer，~GET /status/network/my~ 读取网络模块发布的本机连接状态。单项响应包含 ~api_version~ 、 ~module_id~ 、 ~key~ 、 ~value~ 和 ~updated_at~ 。数据只保存在内存，重启后由发布方重新上报。完整协议见 [[file:../docs/control-center-services.org::*状态中心][状态中心]]。

* Emacs

Emacs 的 Rust 配置入口为 ~modules/emacs/config.rs~ 中的 ~EmacsConfig~ ，构造时注入 ~Arc<ConfigService>~ 。每个配置项有独立读取方法；~emacsclient_path()~ 和 ~socket_name()~ 在每次使用时读取生效值及来源，不缓存连接配置。配置元数据通过静态方法和 ~#[loki_config]~ 注册，与 API 元数据使用相同的编译期发现方式。

~emacsclient_path~ 的类型为 ~Executable~，默认程序名为 ~emacsclient~。配置模块先按 services 进程的 ~PATH~ 搜索，再检查模块声明的 Homebrew 和 Emacs App 目录；找到的绝对路径作为默认值返回。也可在 Emacs 配置界面中使用“选择文件…”按钮，或通过接口指定路径：

#+begin_src sh
curl -X PUT http://127.0.0.1:47321/data/emacs/emacsclient_path \
  -H 'Content-Type: application/json' \
  -d '"/opt/homebrew/bin/emacsclient"'

curl -X POST http://127.0.0.1:47321/emacs/eval \
  -H 'Content-Type: application/json' \
  -d '{"script":"(+ 1 2)"}'

curl http://127.0.0.1:47321/emacs/buffers

curl -X POST 'http://127.0.0.1:47321/emacs/apps/open?app=config'

curl -X POST http://127.0.0.1:47321/emacs/receiver/notification \
  -H 'Content-Type: application/json' \
  -d '{"title":"任务完成","app":"emacs","buffer":"*scratch*"}'
#+end_src

配置修改从下次调用开始生效，并保存到 ~~/.assistant/config.yml~ 。不展开路径中的 ~ 和环境变量。~socket_name~ 默认为 ~server~ ，可在 Emacs 配置界面中改为目标 Emacs 的 socket 名称或绝对路径。gateway 显式传入该 socket，不依赖 ~EMACS_SOCKET_NAME~ 或 ~EMACS_SERVER_FILE~ ，也不在连接失败后回退到 TCP server 或其他实例。

Lisp 求值和 buffer 列表查询在 server 不可用时，仍通过 ~emacsclient --alternate-editor=~ 自动启动目标 Emacs daemon；已运行但未启用 server 的 Emacs 不会自动接管连接。启动 Emacs 所需的程序和用户配置须在 services 运行环境中可用。services 以用户级 LaunchAgent 的用户身份运行。

控制中心“设置”调用 ~POST /emacs/apps/open?app=config~ ，由 Emacs 模块负责应用加载和窗口聚焦，客户端无需传入 Lisp。未知应用或目标 Emacs 未安装对应应用时返回 HTTP 404 ~app-not-found~ 和中文 ~message~ ，控制中心在界面显示该说明。完整约定见 [[file:../docs/control-center-services.org::*打开 Emacs 应用][打开 Emacs 应用]]。

通知上报接口为 ~POST /emacs/receiver/notification~ 。Emacs 模块调用创建时注入的系统通知模块，转交菜单栏应用展示 macOS 通知。~buffer~ 可省略，点击时由 services 显示 Emacs；提供时定位对应的存活 buffer。~app~ 省略或为 ~null~ 时由 Emacs 模块补为 ~emacs~ ，center 按应用标识读取随程序打包的图标，不接受自定义图标。传入 ~module_id~ 可将上报交给已注册的 Rust 模块处理器；默认值为 ~emacs~ 。

使用前先执行 ~make restart-center~ 加载新版菜单栏应用并注册通知 URL scheme。首次上报时，macOS 会请求 Loki Assistant 的通知权限；未授权时需在系统设置中允许通知。HTTP 返回 ~status: "forwarded"~ 只表示已交给菜单栏应用，不表示系统已经展示。

默认系统通知响应的 ~result.notification_id~ 可用于 ~GET /notification/{id}~ 查询处理结果。菜单栏应用通过 ~POST /notification/{id}/receipt~ 回报 ~submitted~ 或带 ~code~、~message~ 的 ~failed~ 。~submitted~ 表示已成功提交给系统通知中心，不代表用户已看到通知。30 秒内没有回执为 ~unconfirmed~ ，过期前仍接受迟到回执；记录保留 15 分钟，services 重启后失效。重复回执幂等，应用仅重试回执，不重发通知。自定义模块处理器的返回值保持原有约定。

使用回执能力需同时加载新版 services 和菜单栏应用；操作入口见下方服务管理以及 [[file:../apps/center/README.org][菜单栏应用说明]]。

完整请求、响应、错误码和 Rust 处理器接入方式见 [[file:../docs/control-center-services.org::*Emacs 模块][Emacs 模块协议]]。

* 系统通知代码接口

~services.notification~ 直接持有 ~Arc<NotificationService>~ ，通过 ~services.notification.send(NotificationRequest)~ 发送标题、正文、应用标识与本机服务回调路径。业务模块保存创建时注入的共享引用并调用其实例方法。通知模块负责 URL scheme 转交、App 内跳转封装和提交回执；具体跳转操作由 services 中的业务模块执行。Emacs 模块的创建方式为 ~emacs::Module::new(config.service(), Arc::clone(&notification), Arc::clone(&status))~ 。通用接口、应用图标命名规则及跳转协议见 [[file:../docs/control-center-services.org::*系统通知模块][系统通知模块协议]]。

原 Emacs 状态和回执 URL 保留为兼容入口，与通用接口共享同一份记录。~POST /emacs/activate~ 可显示 Emacs，或通过 ~buffer~ 查询参数按名称激活第一个匹配的 buffer。指定 buffer 时仅连接目标 socket 的已有 server，优先聚焦已经显示该 buffer 的 GUI 窗口，并恢复最小化或隐藏的窗口；没有 GUI frame 时创建窗口。中文、引号、反斜杠和换行保持完整。目标已关闭时返回 ~buffer-not-found~ ，不创建同名空 buffer；连接失败返回 ~emacs-unavailable~ ，点击旧通知也不会启动新 daemon。点击失败时菜单栏应用显示具体原因。

* macOS 服务管理

services 使用本地 formula ~loki-assistant/local/loki-assistant-services~ ，统一由 ~brew services~ 管理；服务以当前用户运行，不使用 sudo。托盘的 ~cc.loki-assistant.center~ LaunchAgent 仍归 services 控制中心模块管理，与 services 自身的启停相互独立。托盘只显示服务状态，不提供启动或停止 services 的操作。

根目录 ~make install-service~ 编译当前 Debug binary，生成带 SHA256 校验的本机安装包与本地 tap formula，安装到 Homebrew Cellar，然后启动并注册 services。首次迁移会在新 formula 安装成功后卸载旧 ~cc.loki-assistant.services~ 任务并删除旧 plist，避免两个服务争用端口和锁；托盘任务、用户配置和身份均保留。重复执行安装可更新本机构建。

~make uninstall-service~ 停止并注销 Homebrew 服务、卸载 formula，保留 ~~/.assistant/~ 、托盘启动设置和日志。~make start-service~ 、 ~make stop-service~ 与 ~make service-status~ 分别调用 Homebrew 的启动、停止与状态查询。修改代码后使用 ~make restart-service~ ，它会重新编译和更新已安装的 binary，再通过 Homebrew 重启；直接 ~brew services restart~ 只重启已安装的版本。

可直接使用以下命令查看和管理已安装的服务：

#+begin_src sh
brew services list
brew services info loki-assistant-services
brew services restart loki-assistant-services
brew services stop loki-assistant-services
brew services start loki-assistant-services
#+end_src

服务 stdout 和 stderr 继续保存在 ~~/Library/Logs/LokiAssistant/services.log~ 与 ~services.error.log~ 。服务运行环境由本地 formula 的 ~service~ 块定义；安装入口不创建 Homebrew 服务环境文件，中转地址与令牌使用“网络”配置。

Rust binary 只提供服务运行入口和 ~--help~ ，不再包含自管 services LaunchAgent 的安装与启停命令。Homebrew 停止服务时的 SIGTERM 与 Ctrl-C 均走相同的关闭流程，释放中转连接和服务发现信息。
